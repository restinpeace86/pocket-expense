# PocketExpense 의사결정 기록

## 문서 목적
주요 의사결정과 그 이유를 기록한다. 새 기능·구조를 제안하거나 구현을 시작할 때 기존 결정과 충돌하는지 확인하는 기준으로 쓴다.
- **확정(Decided)**: 구현 기준이다.
- **미결(Open)**: "보류 대상 작업" 열에 적힌 작업만 구현 보류한다. 나머지 작업은 진행할 수 있다.

---

## 확정 결정 (Decided)

| ID | 결정 | 이유 | 일자 |
|---|---|---|---|
| D-001 | 데이터 구조는 `spec/data/schema.md`, 상태·결재 규칙은 `spec/data/expense-lifecycle.md`가 단일 출처다. 기존 `PRD.md`, 구 CLAUDE.md 마스터 스펙, `ui-layout.md`는 흡수 후 삭제했다. | 같은 내용이 여러 문서에 달리 적혀 충돌이 발생했음 | 2026-10-13 |
| D-002 | 로그인은 Kakao/Google OAuth만 쓴다. 휴대폰 번호 인증은 폐기한다. 휴대폰 번호는 온보딩에서 입력하는 직원 정보(알림톡 수신 번호)로만 쓴다. | 사용자 결정. SMS 인증 비용·연동 부담 제거 | 2026-10-13 |
| D-003 | 직원의 회사 매핑은 **초대 코드**로 한다. 초대 링크/QR에 코드가 포함되어 자동 입력되고, 화면에는 회사명을 보여 주어 직원이 확인한다. 회사명 직접 입력으로 매칭하지 않는다. | 회사명은 중복·오타가 생겨 매칭 키로 쓸 수 없음 (Claude 제안) | 2026-10-13 |
| D-004 | 하나의 로그인 계정은 하나의 회사에만 소속된다. | 5~30인 타겟에서 다중 소속 수요가 낮고 라우팅·권한이 단순해짐 (Claude 제안) | 2026-10-13 |
| D-005 | 직원/관리자 테이블 이름은 `members`다 (`users` 사용 금지). | Supabase `auth.users`와 혼동 방지 | 2026-10-13 |
| D-006 | Vision LLM은 Google Gemini로 통일한다 (영수증 파싱 + 사내 양식 분석). | 문서 간 모델 불일치 해소, 기술 스택 단일화 | 2026-10-13 |
| D-007 | 카카오 알림톡 결재 알림은 현재 구현 범위에 포함한다. 단계 연기하지 않는다. 발송은 어댑터 뒤에 두고, 발송대행사가 정해지기 전에는 개발용 로그 드라이버로 동작한다. | 사용자 결정. 핵심 USP | 2026-10-13 |
| D-008 | 경비 카테고리는 식대(`meal`), 출장비(`trip`), 외부 미팅비(`meeting`) 3개다. 출장비는 세부 유형(`trip_type`)을 가진다. | 사용자 결정 | 2026-10-13 |
| D-009 | 식대 한도는 **1인 한도 × 인원수**로, 영수증(청구 건) 단위로 적용한다. 인원수는 직원이 직접 입력한다. 식대 외 카테고리는 전액 회사 지원이다. | 영수증에 식사 인원이 나오지 않음. 사용자 결정 | 2026-10-13 |
| D-010 | 결제수단(`payment_method`)으로 개인카드/법인카드를 구분한다. 개인카드는 회사가 직원에게 회사지원금을 지급하고, 법인카드는 직원이 회사에 개인부담금을 납부한다. | 정산 방향이 반대이기 때문. 사용자 결정 | 2026-10-13 |
| D-011 | 결재라인은 **관리자가 설정**한다. 직원은 결재자를 고르지 않는다. 부서별 결재라인이 있으면 그것을, 없으면 회사 기본 결재라인을 쓴다. 결재는 순차 진행이다. | 5~30인 조직에서 직원이 결재자를 찾는 수고 제거, 결재 누락 방지 (Claude 제안) | 2026-10-13 |
| D-012 | 상신 시점에 결재라인을 경비별로 스냅샷한다. 이후 결재라인을 바꿔도 진행 중인 결재에는 영향이 없다. | 진행 중 결재의 일관성 | 2026-10-13 |
| D-013 | 알림톡 결재 링크는 로그인한 해당 결재자만 처리할 수 있다. 토큰만으로 승인되는 무로그인 링크는 쓰지 않는다. 카카오 로그인 세션이 유지되면 바로 결재 화면이 열린다. | URL 유출 시 제3자 승인 위험 | 2026-10-13 |
| D-014 | 반려되면 경비는 `rejected`가 되고, 직원이 수정해 재상신하면 결재가 새 회차(`round`)로 처음부터 다시 진행된다. 이전 회차 이력은 보존한다. | 반려 후 흐름 미정의 해소 | 2026-10-13 |
| D-015 | `paid`(정산완료)는 관리자가 `approved` 건에 대해 처리한다(일괄 가능). | `paid` 전환 주체 미정의 해소 | 2026-10-13 |
| D-016 | 월말 출력의 기준월은 **결제일자(`expense_date`)** 다. 대상은 `approved`, `paid` 상태. 형식은 `.xlsx` 1개 + 영수증 원본 + 지출결의서 PDF를 담은 ZIP이다. 엑셀에는 영수증 링크 대신 ZIP 안의 **영수증 파일명**을 적는다. | 세무 처리는 거래일 기준. 비공개 Storage의 signed URL은 만료되고 공개 버킷은 영수증 노출 위험 | 2026-10-13 |
| D-017 | 공급가액(`supply_amount`)과 부가세(`vat_amount`)를 저장하고, 영수증 파싱 대상에 포함한다. | 세무 처리에 필요. 사용자 결정 | 2026-10-13 |
| D-018 | 계산 기준값(1인 식대 한도, km당 유류비 단가)은 경비 행에 스냅샷 저장한다. | 회사 규칙 변경이 과거 청구 금액을 바꾸지 않게 함 | 2026-10-13 |
| D-019 | 사내 양식 정의는 `companies.custom_schema`가 아니라 버전을 가진 `form_templates` 테이블로 관리하고, 경비는 작성 당시 양식 버전을 참조한다. | 양식 수정이 과거 경비의 입력값 해석을 깨뜨리지 않게 함 | 2026-10-13 |
| D-020 | 경비 1건 = 영수증 1장 = 결재 1건이다. 여러 영수증을 묶은 결의서는 현재 범위가 아니다. | 기존 Spec 구조 유지, 단순성 | 2026-10-13 |
| D-021 | 부서는 `departments` 테이블로 관리한다(관리자 등록, 직원은 목록에서 선택). | 부서별 결재라인 매칭에 자유 텍스트를 쓸 수 없음 | 2026-10-13 |
| D-022 | 상태 배지에 `rejected`(빨강)를 포함한 5단계 색상을 쓴다. | 문서 간 배지 불일치 해소 | 2026-10-13 |
| D-023 | 타겟 규모는 5~30인으로 통일한다. | CLAUDE.md(5~20)와 PRD(5~30) 불일치 해소 | 2026-10-13 |
| D-024 | 테스트 프레임워크는 Vitest를 쓴다. | `npm run test` 검증 단계 정의 필요 | 2026-10-13 |
| D-025 | 직원 정보: 필수 = 이름, 휴대폰 번호, 부서, 개인정보 수집·이용 동의 / 선택 = 직급, 사번, 정산 계좌(은행·계좌번호·예금주), 차량번호. 이메일은 OAuth 계정에서 가져온다. | 사용자 지시(이름·회사·휴대폰) + Claude 제안(부서는 결재라인, 계좌는 개인카드 정산 지급, 차량번호는 자차 출장비 증빙에 필요) | 2026-10-13 |

## 미결 사항 (Open)

| ID | 미결 내용 | 보류 대상 작업 | 그 외 작업 처리 |
|---|---|---|---|
| O-01 | 알림톡 발송대행사 선정, 카카오 비즈니스 채널 개설, 알림톡 템플릿 심사 | 실제 발송대행사 API 연동 (todo T8-3) | 어댑터·로그 드라이버·발송 이력은 진행 가능 |
| O-02 | 세무사무소 업로드 템플릿(더존/세무사랑 등) 미확보 | 엑셀 컬럼의 최종 회계 프로그램 호환 매핑 (todo T10-4) | 내부 표준 컬럼(`spec/features/tax-export.md`)으로 출력 기능은 진행 가능 |
| O-03 | 상신자가 결재라인에 결재자로 포함된 경우(예: 대표 본인 경비) 처리 방식 | 없음 — 잠정 규칙 적용: 본인 단계는 `skipped` 처리, 남은 결재자가 없으면 상신을 막고 "관리자에게 결재라인 설정을 요청하세요" 안내 | 확정 시 `expense-lifecycle.md` 수정 |
| O-04 | 자차 출장비 편도/왕복 기준 | 왕복 토글 UI와 왕복 시 거리 2배 계산 (todo T7-4) | `is_round_trip` 컬럼은 생성. 잠정: `distance_km`에 실제 총 주행거리를 넣고 그대로 계산 |
| O-05 | 구독 요금제 결제·인원 제한 기능 | 결제·요금제 관련 일체 | Spec 작성 전까지 구현하지 않음 |
