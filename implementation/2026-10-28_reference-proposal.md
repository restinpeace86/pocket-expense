## 1. reference.md가 말하는 것 (한 줄 요약)
지금 제품은 "회사 내부 통제(작성·결재·정산)가 제대로 작동하는가"를 해결했다. 다음 단계는 **"그 자료가 외부 세무 검증(세무사·세무조사)에서도 설명 가능한가"** 이다.
모든 세무 기능을 만들지 말고, **지출결의서에 빠지기 쉬운 업무 근거·외부 증빙을 연결하고, 확정된 자료를 세무사 프로그램에 바로 넣을 수 있게 넘기는 것**이 경쟁력이라는 흐름이다.

주제는 7가지로 묶인다.

| # | 주제 | reference.md 핵심 |
|---|---|---|
| A | 소명 자료·업무 근거 | 금액 불일치 사유, 계약서·견적서·이체 내역을 같은 지출에 연결, 소명 파일 묶음 |
| B | 계정별 리스크 | 접대비는 거래처·참석자·목적 강제, 여비교통비는 목적·구간, 개인카드는 사업 관련성 |
| C | 공제·가산세 점검 | 적격증빙 수집 상태, 3만 원 이하 증빙불비 가산세 면제, "최종 판단은 세무사" 표시 |
| D | 결제 인프라 연계 | 홈택스·카드사·현금영수증·전자세금계산서·통장 → **파일 업로드 대조 먼저, API 연동은 나중** |

| F | 지출·지급 운영 | 반복 지출, 지급 예정일, 송금 확인증, 계정과목 일괄 변경, 부서 예산(경고 수준), 이상 거래 표시 |

## 3. 우리가 취해야 할 원칙 (방향)
1. **세무 판단은 하지 않고 근거를 모은다** — 가산세·공제 계산은 "가능성 점검 + 적용 기준·기준일 표시 + 최종 판단은 세무사". D-071(신뢰성 안에서 공수 줄이기)과 같다.
2. **외부로 나가는 자료는 승인·마감된 확정 자료만** — 세무사가 보는 화면·파일도 이 원칙(이미 세무 마감에 적용).
3. **연동보다 파일 업로드 대조** — 카드사 API·오픈뱅킹·펌뱅킹은 계약·비용이 커서 나중. 이미 카드 내역 대조(D-111)가 이 방식이다.
4. **양식은 하나로 시작, 프로그램별 양식은 파일을 받은 뒤** — O-02 보류(T10-4)와 같다.
5. **급여·퇴직금·손익계산서는 범위 밖** — reference.md도 미룸. 제품 정체성(경비 정산) 유지.
6. **매출 쪽 기능은 우리 데이터가 아니다** — "신용카드 매출세액 공제", "매출액·현금영수증 발행 비율 변동"은 판매자(매출) 기준이라 경비 앱에는 해당 데이터가 없다. 적용 대상 아님.

## 5. 개선사항 2(세무사 워크스페이스) — 스킵 이유와 재설계안
**스킵 이유**
1. **D-004 "하나의 로그인 계정은 하나의 회사에만 소속된다"와 상충** — 요청은 한 세무사 계정이 여러 회사에 자동으로 붙는 구조(N:1).
2. **O-02 보류** — "세무사무실 회계 프로그램 포맷에 맞춘 엑셀"은 양식 파일 입수 전 보류(T10-4).
3. **스펙에 없는 보안 결정이 필요** — 이메일만 맞으면 승인 없이 즉시 연결되면, 사장님이 이메일을 잘못 치면 모르는 사람에게 회사 전체 경비 자료가 열린다(회사 간 격리 원칙). 세무사가 고객사 계정과목을 고치는 권한, 세무사를 바꿀 때 이전 세무사 접근 해제도 정해야 한다.

**재설계안 (권장 A안)**
- 세무사는 회사 **소속(멤버)이 아니라 "외부 열람자"** — 새 관계표 `tax_agent_links`(회사, 세무사 이메일, 상태, 연결한 관리자, 연결·해제 시각). 한 세무사 계정은 여러 회사와 연결될 수 있지만 **어느 회사의 멤버도 될 수 없다**(D-004는 "멤버 소속"에 대한 규칙으로 유지, D-xxx로 보완).
- 연결: 관리자가 [설정 › 담당 세무사]에 사무소명·담당자·이메일·연락처 입력 → 그 이메일로 로그인하면 **"OO회사가 세무 자료 열람을 요청했어요 [수락]" 한 번** → 연결(이메일 오타로 엉뚱한 사람에게 자료가 가는 것 방지). 이미 수락한 세무사에게 새 고객사가 같은 이메일을 넣으면 목록에 "새 요청"으로 쌓임(자동 누적은 수락 1번 뒤).
- 볼 수 있는 것: **승인·마감된 자료만** — 월별 세무 엑셀·ZIP(기존 세무 마감 그대로 재사용), 계정과목별·결의서별 요약, 증빙 사진(서명 링크). 작성 중·결재 중 자료는 안 보임.
- 할 수 있는 것: 내려받기(기록 남김 — 4-1 ①), 계정코드 **수정 제안** 또는 계정코드만 수정(회사 관리자에게 기록 표시) — 결정 필요.
- 해제: 관리자가 언제든 [연결 끊기], 이메일을 바꾸면 이전 연결은 바로 해제.
- 초대 메일은 발송 수단이 없어(메일 발송 서비스 미도입) 처음에는 **"로그인하면 자동으로 요청이 보임" + 관리자에게 공유 링크 복사**로 시작.
- 회사 격리: 세무사 조회는 전용 DB 함수에서 `tax_agent_links`(수락·활성) 확인 후에만, 격리 테스트를 출시 차단 조건으로(기존 원칙 그대로).

**결정해 주셔야 할 것**
1. D-004 보완: "세무사는 멤버가 아닌 외부 열람자로 여러 회사와 연결 가능"으로 할지
2. 연결 방식: 즉시 연결(요청 원문) vs 세무사 수락 1번(권장)
3. 세무사 권한: 읽기·내려받기만 / 계정코드 수정까지
4. 회계 프로그램 양식: 지금은 기존 세무 엑셀 그대로, 양식 파일 받으면 추가(O-02)

## 6. 제안 우선순위 (한 번에 고르기 쉽게)
