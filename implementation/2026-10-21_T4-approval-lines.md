- 기준: `spec/features/approval-workflow.md` §2~§4, `spec/screens/admin-dashboard.md` ⑥, `spec/screens/approver.md` ①②, D-012·D-026·D-039

## 변경 사항
- DB `034_approval_lines.sql`: `save_approval_line(부서 또는 기본, 검토자 목록)` — 관리자 이상만, 검토자는 같은 회사 활성 멤버·최대 4명·중복 불가, 단계를 통째로 바꿈(원자적), 부서별 라인을 0명으로 저장하면 지워 기본 결재라인을 따름
- 테스트 `018_approval_lines.sql`: 저장 권한·검사(다른 회사 검토자·부서, 중복, 5명), 다른 회사 열람 불가, 영업팀 직원 상신 → 박팀장 검토 차례(관리자·다른 직원 처리 불가, 다른 직원은 열람도 불가) → 검토 승인 → 관리자 승인, 부서 라인 없는 직원은 직통, 검토자 본인 소명서는 본인 단계 건너뜀, 비활성 검토자면 상신 차단
- 관리자 [설정 › 사전 검토 결재라인] `/admin/approval-lines`: 결재라인 목록(기본 + 부서별, 결재선·적용 인원), [부서별 결재라인 추가], 편집(검토자 고르기·위/아래 순서·빼기, 마지막 "관리자 최종 승인" 고정), 미리보기, 저장, 부서 라인 지우기
- 검토자: 하단 메뉴 [결재함](대기 건수 배지 — 결재라인에 들어 있거나 검토 차례가 있을 때만, 관리자 이상은 관리자 승인 차례 건수), `/approvals` 결재함(대기/처리완료), `/approvals/[claimId]` 결재 화면(영수증·원본 패널·이력, [반려]/[검토 승인], 상태별 안내: 앞 단계 대기·이미 처리됨·관리자 차례). 관리자는 지출 승인 관리로, 청구자 본인은 내 소명서로 보냄
- 직원 상신 확인 창의 결재선을 실제 결재라인으로 표시("박영업 검토 → 관리자 승인", 본인 단계까지는 건너뜀)
- 검토 승인 시 다음 결재자에게 알림(이미 연결된 dispatch가 처리)

## 특이 사항
