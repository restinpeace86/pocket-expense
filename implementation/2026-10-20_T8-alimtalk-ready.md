# T8-1·T8-2·T9-6 알림톡 — 보내기 직전까지

- 구현 일시: 2026-10-20
- 기준: `spec/features/kakao-alimtalk.md`, `spec/screens/notification-rule.md`(문구 단일 기준), D-013·D-034·D-039·D-047, 실제 발송대행사는 ⛔ O-01

## 변경 사항
- `src/lib/notify/templates.ts`: 템플릿 6종 문구·버튼 링크(결재 요청·승인 완료·반려·지급 완료·초대·독촉), 결제수단 요약, 휴대폰 번호 검사·가리기 (단위 테스트)
- `src/lib/notify/sender.ts`: `NotificationSender` 어댑터. `ALIMTALK_DRIVER=log`(기본)는 서버 로그에만 남김. 없는 드라이버 이름이면 "연결되지 않음"으로 실패 기록. **대행사가 정해지면 이 파일에 드라이버 하나만 추가하면 바로 발송된다**
- `src/lib/notify/dispatch.ts`: 결재 처리가 끝난 뒤 수신자를 정해 `notification_logs`에 기록하고 보낸다(service role, 같은 회사로 한정). 번호가 없거나 틀리면 실패 기록, 일시적 실패는 30초 뒤 1회 재시도
  - 상신 → 현재 단계 대상자: 관리자 승인 단계면 청구자를 뺀 관리자 이상 전원, 사전 검토 단계면 지정 검토자
  - 사전 검토 승인 → 다음 단계 대상자 / 최종 승인 → 청구자(사비 지급 대기 또는 정상 마감 문구) / 반려 → 청구자(사유, 편집 화면 링크) / 지급 완료 → 지급액이 있는 소명서의 청구자
  - 최고 관리자 본인 결재 생략 건은 보내지 않음
- 서버 액션(상신·승인·반려·지급 완료)에서 응답을 보낸 뒤(`after`) 알림 처리 — 화면 체감 시간에 영향 없음, 실패해도 결재는 그대로
- 버튼 도착지: `/workspace/[id]/approvals/[claimId]`(관리자 → 지출 승인 관리 상세, 본인 → 내 소명서, 그 밖 → 권한 안내; 로그인 안 했으면 proxy가 로그인 후 돌아오게 함), `/workspace/[id]/employee/settlements`(정산 타임라인 T6-10 전까지 내 소명서 "완료" 목록으로)
- 관리자 [알림 이력] `/admin/notifications` 열림: 전체/실패, 받는 사람(번호 가림), 소명서, 보낸 내용·버튼 링크, 실패 사유, 개발 모드 배너

## 특이 사항
- 실데이터 점검(임시 회사, 끝나고 삭제): 상신 → 대표·관리자(청구자 제외) 2건, 승인·반려·지급 완료 → 직원 각 1건이 기록되고 버튼 링크가 배포 도메인 기준으로 만들어짐
- 남은 것: 실제 발송대행사 드라이버(O-01), [재발송](T11-4), 사전 검토자 화면(T4·T9-4)
