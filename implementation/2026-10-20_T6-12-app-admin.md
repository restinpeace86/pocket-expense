- DB `031_app_admin_overview.sql`: 회사 목록 집계 함수(service role만 실행)
- 테스트 `016_receipt_records.sql`: 기록 1건(같은 항목 재차감해도 1건), 인식 결과 복사, 직원·대표·운영자 계정이라도 고객 역할로는 기록·운영자 목록·보관함·집계 함수 접근 불가, 항목 삭제·소명서 통째 삭제 후에도 기록과 스냅샷 유지
- 접근: `src/proxy.ts`에서 `/app-admin` 경로는 운영자 계정이 아니면 화면을 그리기 전에 404, 화면(`requireAppAdmin`)·조회 함수에서 한 번 더 확인
- 화면(PC 기준, 읽기 전용): 회사 목록(요약 4개 + 표), 회사 상세(영수증 표·멤버·크레딧 지급), 영수증 상세(사진·기록·AI가 읽은 전체 내용·품목 표·직원이 확정한 값·원본 JSON), CSV(BOM·수식 주입 방지)
- 삭제 흐름: 직원이 크레딧 쓴 영수증(항목·소명서)을 지우면 사진을 보관함으로 먼저 옮기고(실패하면 지우지 않음) 3개월 뒤 삭제 예정일 기록
- 정리 작업: `/api/cron/purge-receipt-archive`(매일 03:00 KST, `vercel.json`), `CRON_SECRET` 없거나 틀리면 404
- 운영자 계정 등록: 사용자 카카오 계정 1개를 SQL로 등록(코드·마이그레이션에는 넣지 않음)

## 특이 사항
- 처음에는 화면 안에서만 막아 비로그인 요청에 200 + 페이지 제목("운영자")이 나갔다(데이터는 안 나감). 요청 입구에서 막도록 바꿔 모든 `/app-admin` 경로가 404·본문에 흔적 없음을 확인
- 실데이터 점검(임시 회사, 끝나고 삭제): 사진 2장이 보관함으로 옮겨짐, 삭제 예정일 3개월 뒤, 정리 작업 인증 없으면 404, 기간 지난 사진 정리 후 보관함 비어 있음. 지운 직후 다운로드는 저장소 캐시 때문에 잠시 받아질 수 있음(목록에서는 사라짐)
- 운영자 계정으로 실제 로그인해 화면을 여는 확인은 카카오 로그인이 필요해 하지 못함 → 사용자 확인 필요
- 남은 것: Vercel `CRON_SECRET` 등록(사용자), 개인정보 처리방침 반영(O-07)
