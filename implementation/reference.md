특히 경비관리와 지출결의는 단순 조회뿐 아니라 사용자의 현재 처리 상태를 파악해 알려주는 기능으로 발전시킬 수 있어.
3. 단순한 질문을 넘어 실제 기능 실행까지
여기서 중요한 건 AI가 답변만 하는 게 아니라, 사용자의 요청을 이해하고 WORKON의 실제 기능과 연결된다는 점이야.

나는 세 단계로 구분하는 걸 추천해.
단계	AI 역할	예시
1단계: 조회	데이터를 찾아 답변	오늘 회의실 예약 현황 알려줘
2단계: 이동	해당 기능이나 화면 열기	회의실 예약 화면 열어줘
3단계: 실행	사용자의 요청을 실제 처리	내일 오후 2시 회의실 예약해 줘

3단계는 예약이나 지출결의처럼 실제 데이터가 변경되는 작업이므로, 실행 전에 조건을 보여주고 사용자 확인을 받는 게 안전해.

예를 들어:
- 사용자: @WORKON 내일 오후 2시에 1회의실 예약해 줘
- AI: 내일 오후 2시부터 3시까지 예약할까요?
- 사용자: 응
- AI: 예약 완료 안내
이런 흐름이야.
4. 어떤 AI 기능부터 시작해야 할까?
처음부터 모든 기능을 자동화할 필요는 없어.
WORKON AI 단계별 도입안
1차 추천
업무 정보 조회 및 화면 이동
- 오늘 일정 확인
- 회의실 예약 현황 확인
- 미처리 경비 확인
- 승인 대기 내역 확인
- 관련 메뉴 바로 열기
  
  기존 데이터를 활용할 수 있어 초기 구현 부담이 상대적으로 낮음.


2차 확장
업무 처리 및 실행
- 회의실 예약 및 취소
- 경비 내역 등록
- 지출결의 요청
- 일정 등록 및 변경
  
  실행 권한, 확인 절차, 중복 처리 방지 필요.


3차 확장
능동적인 업무 보조
- 경비 미처리 항목 알림
- 승인 지연 항목 안내
- 오늘의 주요 일정 요약
- 회의실 예약 충돌 안내
  
  사용자가 묻기 전에 필요한 정보를 알려주는 단계.


5. 반드시 고려해야 할 부분
이 기능은 일반적인 AI 챗봇과 달리 실제 회사 데이터에 접근하기 때문에 몇 가지 원칙이 필요해.
- 사용자 권한: 사용자가 볼 수 있는 정보만 AI도 조회할 수 있어야 해.
- 개인정보 보호: 단체 채팅방에서 개인 경비 내역을 질문하면 다른 사람에게 노출되지 않도록 개인 응답으로 처리해야 해.
- 실행 전 확인: 예약, 취소, 승인 등 데이터 변경 작업은 확인 절차를 거쳐야 해.
- 정확한 데이터: 회의실 예약 가능 시간이나 미처리 경비는 AI가 추측하지 않고 WORKON의 실제 데이터로 확인해야 해.
- 지원 범위 제한: WORKON이 제공하는 기능 안에서만 실행하고, 지원하지 않는 요청은 불가능하다고 안내해야 해.
6. 이 기능이 WORKON의 브랜드에 주는 가치
내가 특히 긍정적으로 보는 건 이 부분이야.

기존 그룹웨어는 사용자가 메뉴를 찾아가서 직접 업무를 처리하는 방식이야.

그런데 WORKON은 앞으로 다음과 같은 사용 경험을 제공할 수 있어.
- 기존 방식: 메뉴를 찾아서 회의실 예약 현황 확인
- WORKON AI: 채팅창에서 물어보고 바로 확인
- 기존 방식: 경비관리 메뉴에 들어가 미처리 내역 확인
- WORKON AI: @WORKON 내 미처리 경비 있어?라고 질문
즉, 기능을 제공하는 것을 넘어 기능을 사용하는 과정까지 편리하게 만드는 것이지.

그리고 이건 WORKON이 단순히 경비관리와 그룹웨어 기능을 묶은 제품이 아니라는 인상을 줄 수 있어.

다만 지금 당장 AI를 브랜드의 핵심 기능으로 광고하기보다는, 실제 구현 후에 차별화 요소로 강조하는 게 좋겠어.

내 제안은 WORKON의 사내 채팅을 AI 기능의 중심 인터페이스로 설계하는 거야. 별도의 AI 앱을 만드는 것보다 기존 채팅에서 @WORKON으로 호출하는 방식이 제품의 통합성을 더 잘 보여준다고 생각해.

다음으로는 이 기능을 기존 채팅에 단순히 추가할지, 아니면 WORKON 전체 기능을 연결하는 별도의 WORKON AI 서비스 구조로 설계할지 정하는 것이 좋겠어.
