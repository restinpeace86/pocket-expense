[개선사항] # 역할 및 맥락
너는 Next.js (App Router), TypeScript, TailwindCSS에 정통한 시니어 프론트엔드/풀스택 엔지니어다.
우리는 5~20인 미만 소기업·중소기업을 타깃으로 하는 올인원 실무 웹앱(PWA) 을 개발하고 있다.
무겁고 복잡한 대기업용 그룹웨어 기능은 배제하고, 대화 엉킴을 방지하는 실무형 서브 대화 시스템과 PC에서는 무소음 시각 알림 UX에 집중한다.

# [기능 1] 하이브리드 서브 대화(스레드/이슈 카드) UI 아키텍처 (상세 설계)

PC와 모바일의 환경 차이를 완벽히 반영한  대화 구조를 구현하라.

1. 모바일 화면 - 단일뷰 (Single View) 아키텍처:
   - 카카오톡처럼 친숙한 일직선 메인 대화 타임라인을 기본 제공 중
   - 사용자가 특정 메시지를 터치하여 [서브 대화/이슈 카드 만들기]를 실행하면, 화면 전체가 바뀌는 복잡한 라우팅 대신 스마트폰 하단에서 위로 스윽 올라오는 **'하단 시트(Bottom Sheet)'** 또는 가벼운 **'풀스크린 모달'**로 서브 대화창이 열리게 한다. (slack의 개념 본땀)
   - 서브 대화 안에서 토론을 마친 뒤 상단의 '< (뒤로 가기)' 버튼을 누르면 메인 타임라인으로 부드럽게 복귀한다.
   - 서브 대화가 종료 되면 [이 서브대화 종결하기] 와 같은걸 누르면 대화내용 그대로 추후에 볼수 있는 형태로 따로 저장되며, 더이상의 그 채팅방에서의 대화는 불가능하다. 그냥 채팅창 형태의 기록으로 남아있는것일뿐이며, 메인대화에서는 서브대화의 제목? 주제요약? 등 간단한형태의 카드로써가지고 있게 된다.
   - 모바일 화면에선 멀티뷰 인터랙션으로 구현안하며, 모바일에서의 사이드바 패널은 [해당 채팅방의 서브대화보기?]와 같은 버튼 하나만들고 누르면 바텀시트형태로 서브대화 목록 리스트가 뜨고 그걸 선택시 그 서브대화 내역이 열리며 보는형태로... 닫으면 다시 서브대화 목록 리스트 떠있는 상태로 가고..
     
2. PC / 와이드 화면  - 멀티뷰 (Multi-View) 아키텍처:
   - [서브 대화/이슈 카드 만들기] 실행시, 좌우 2단 분할 레이아웃(Grid 또는 Flex)으로 메인대화가 좌측 서브대화는 우측으로 적용한다.
   - **왼쪽 영역:** 메인 대화 타임라인 (실시간 메시지 흐름).
   - 메인대화채팅방과 오른쪽 서브 대화 채팅방에 대하여 둘다 실시간 메시지 흐름을 타며 서브대화가 종료된후는 서브 대화 채팅방은 더이상 채팅방이 아니고 채팅을 했던 기록이 남아있는 형태임
   - **오른쪽 영역:** 전용 서브 대화 사이드바 패널 (오른쪽 서랍장 형태).
   - PC에서는 메인 대화창에서 특정 이슈 카드나 서브 대화 항목을 클릭하는 즉시, 페이지 이동 없이 **오우거/우측 패널에 해당 서브 대화 내용이 실시간으로 로드**되어 좌우를 동시에 보며 토론할 수 있는 멀티뷰 인터랙션을 구현한다.

3. 데이터 구조 및 상태 관리 요구사항:
   - 메인 대화 메시지와 서브 대화(스레드) 데이터는 외래키(Thread ID / Parent Message ID)로 매핑되는 구조를 전제로 한다.
   - 메인 타임라인에는 정신없는 텍스트 대신 **[시간 + AI가 자동 생성한 타이틀 + 참여자 요약 카드]** 형태로 압축되어 렌더링되도록 컴포넌트 상태를 설계할 것.

# [기능 2] 무소음 하이브리드 시각 알림 (토스트 팝업 + 무드등 펄스)

사무실 환경에서 소리나 눈이 부신 전체 화면 깜빡임 없이, 직원의 집중을 깨지 않으면서 직관적으로 인지할 수 있는 알림 UX를 구현하라.
일반적으로 사무실에서 작업하는공간에서 소리를 꺼놓는 채 업무하는 곳들이 대부분이며 일반적이다. 이에 맞춰서 PC 환경에서 볼 경우 알림에 대하여 좀더 직관적이고 빠르게 알수있도록 시각적인 포인트를 가미하는게 필요하다.

1. 우측 하단 토스트 팝업 (Text & Context):
   - 앱이 활성화된 상태에서 새 메시지나 멘션이 오면, 화면 **우측 하단에 3초 동안 부드럽게 떴다가 조용히 사라지는 컴팩트한 토스트 팝업 카드**를 띄운다. (예: `[김 대리] 영수증 정산 건에 새 메시지`)
   - 토스트를 클릭하면 즉시 해당 채팅방/서브 대화로 이동.
2. 가장자리 무드등 펄스 (Peripheral Vision):
   - 토스트 팝업과 동시에, 게임 UI에서 영감을 받아 앱 창의 **가장자리 테두리(Vignette)에서 안쪽으로 은은한 투명 파란빛이 0.5초 동안 서서히 나타났다 사라지는 페이드 인-아웃 애니메이션**을 2회 반복하여 주변 시야를 자극.

너는 Next.js (App Router), TypeScript, TailwindCSS에 정통한 시니어 프론트엔드/풀스택 엔지니어다.
우리는 5~20인 미만 소기업·중소기업을 타깃으로 하는 올인원 실무 웹앱(PWA) **'모아온(Moa-on)'**을 개발하고 있다.

# [기능 3] 실무형 피드백 및 소통 창구 (버그 신고 vs 기능 추가 요청 이원화)

앱 최상단 헤더(Header)나 사이드바에 상시 노출되는 진입점부터, 모달 폼, 그리고 선택지에 따른 이원화된 안내 메시지(응답 팝업)까지 완벽하게 구현하라.

1. 프론트엔드 UI/UX 요구사항:
   - **진입점:** 앱 헤더 우측이나 사이드바에 직관적인 아이콘 버튼 (`💬 피드백 / 소통 창구` 또는 🐛/💡 아이콘) 배치.
   - **피드백 작성 모달 (Modal):**
     * **구분 선택 (Radio / Tab):** `[🐛 버그 신고]` vs `[💡 기능 추가 요청]` 중 하나를 반드시 선택하게 함.
     * **내용 입력 영역:** 텍스트렌더러/텍스트박스 (`textarea`, placeholder: "불편하신 점이나 제안할 아이디어를 편하게 남겨주세요.")
     * **자동 로그 수집 (치트키):** 사용자가 인지하지 못하는 사이, 백그라운드에서 **현재 접속 중인 페이지 URL, 브라우저 정보, 그리고 접수 시간(Timestamp)**이 데이터에 함께 묶여서 전송되도록 설계.

2. 이원화된 제출 완료 안내 팝업 (Toast 또는 Alert / Modal):
   - **[버그 신고]를 선택하고 제출했을 때의 응답 텍스트:**
     > "소중한 제보 감사합니다! 제보해주신 버그는 확인 후 **가장 빠른 시일 내(24시간 이내)**로 신속하게 수정 및 개선하겠습니다."
   - **[기능 추가 요청]을 선택하고 제출했을 때의 응답 텍스트:**
     > "소중한 아이디어 감사드립니다! 💡\n\n보내주신 기능은 추후 업데이트에 **적극적으로 반영**하도록 하겠습니다.\n\n다만, 해당 기능이 저희 서비스의 전체 뼈대와 실무 프로세스에 부합하는지 면밀히 검토하는 과정이 필요하여, 검토를 거쳐 우리 서비스에 가장 적합한 형태로 다듬어 선보이는 데 다소 시간이 소요될 수 있는 점 너른 양해 부탁드립니다.\n\n앞서 직원 여러분의 업무를 더 편안하게 만들어 드릴 수 있도록 꾸준히 발전하는 모아온이 되겠습니다. 고맙습니다!"

3. 데이터 흐름 및 관리자(사장님) 연동 고려사항:
   - 제출된 데이터가 Supabase DB(`feedback_logs` 테이블 등)에 `category (bug | feature)`, `content`, `page_url`, `user_info`, `status (pending | reviewing | resolved)` 필드로 안전하게 적재되는 구조 제시.

# 출력 결과물 요구사항
1. 해당 피드백 시스템을 구현하기 위한 컴포넌트 코드 제공 (예: `FeedbackButton.tsx`, `FeedbackModal.tsx`, 관련 API 또는 서버 액션 스켈레톤).
2. 버그 신고와 기능 추가 요청에 따라 제출 완료 후 서로 다른 안내 문구(Alert/Toast)가 동적으로 분기되는 상태 관리 로직 작성.
3. 구현 코드 작성 후, 프론트엔드 관점에서 필수 로그(URL, 기기 정보)를 깔끔하게 수집하기 위한 팁이나 엣지 케이스 검토 내용 포함.
