[개선사항 1] 사용자 워크플로우 시나리오 초안 작성 프롬프트
지금부터 우리 프로젝트(PocketExpense, 5~15인 소기업 지출 정산 SaaS)의 전체 사용자 워크플로우를 완벽하게 검증하기 위해, 상세한 E2E 시나리오 명세서를 spec/e2e-workflow.md 파일로 작성해 줘.

실제 소기업 현장에서 벌어지는 예외 상황과 권한 분리까지 모두 포함하여, 다음 총 8가지 핵심 시나리오를 상세히 마크다운으로 정리해 줘:

영수증 등록 단계 (직원): 직원이 모바일/웹에서 영수증(사진/내역)을 등록하고 지출결의를 올린다.

카톡 알림 및 승인 단계 (현재 Mocking 처리 가정): 시스템이 관리자(사장님)에게 카카오톡 알림을 보내고, 사장이 링크를 눌러 '승인'을 처리한다.

반려 및 재요청 단계 (예외 처리): 사장이 카톡에서 '반려'를 눌렀을 때, 직원에게 사유가 전달되고 직원이 내용을 수정해서 다시 결재를 올린다.

관리자 및 권한 분리 단계: 일반 직원은 자기 것만, 경리·총무는 회사 전체 목록을, 사장은 결재 대기 목록만 보는 권한별 화면 흐름.

엑셀 출력 단계 (경리): 승인된 내역을 경리 담당자가 세무사무실 제출용 엑셀 파일로 한 번에 다운로드한다.

요금제 및 장수 제한 체크: 29,000원 기본 플랜(150장) 소진 시 추가 팩 또는 상위 플랜 유도 팝업이 뜨는 분기 흐름.

시크릿 쿠폰 입력 단계: 구글 폼 후기 작성 후 발급받은 쿠폰 번호를 입력했을 때 영수증 장수가 실시간으로 +100장 리필되는 결제 흐름.

월말 마감 및 데이터 아카이빙 단계: 매달 말일/월초 사용량 리셋 또는 이월, 지난달 데이터가 세무사무실용으로 아카이빙되는 주기적 흐름.

위 8가지 시나리오가 실제 유저의 행동 순서에 맞춰 끊김 없이 이어지도록 명세서를 작성해 줘.

   - 서브 타이틀은 메인 타이틀 바로 아래에 자연스럽게 이어지도록 약간 톤 다운된 색상(또는 세컨더리 텍스트 스타일)으로 배치해 주세요.
   - 현재 랜딩 페이지를 전면 수정하는 것이 아닙니다. 현재 랜딩 페이지 기준으로 검토해주세요.

현재 코드를 분석하고, 이 문구가 가장 매력적으로 돋보일 수 있도록 코드를 수정 또는 제안해 주세요.

[개선사항 3] PocketExpense 프로젝트에 관리자 전용 1:1 카카오톡 피드백 버튼 기능을 추가하려고 합니다. 디바이스 환경 및 유저 권한에 따라 노출 방식을 다르게 구현해 주세요.

### [구현 요구사항]

1. **권한 공통 조건**:
   - 오직 **관리자(Admin) 권한을 가진 로그인 유저**에게만 노출되어야 합니다. (일반 팀원/직원 계정에는 절대 보이지 않아야 함)

2. **디바이스별 노출 위치 분기 (Responsive UI)**:
   - **PC 화면 (Desktop)**: 화면 우측 하단(`fixed bottom-6 right-6 z-50`)에 눈에 띄는 플로팅 버튼 형태로 상시 노출해 주세요. (예: 아이콘 + "관리자 피드백" 텍스트)
   - **모바일 화면 (Mobile)**: 화면을 가리지 않도록 우측 하단 플로팅 형태는 숨기고(`hidden sm:flex` 또는 유사한 반응형 처리), 모바일 하단/사이드 네비게이션 바 내부의 **[설정] 메뉴 안쪽**에 「관리자 1:1 문의」 항목으로 배치해 주세요.

3. **동작 및 설정**:
   - 클릭 시 새 창(`target="_blank"`)으로 지정된 카카오톡 채널 링크(`https://pf.kakao.com/_xxxxxx/chat` - 상수로 분기하거나 환경 변수 처리)로 이동하도록 구현해 주세요.

현재 프로젝트의 레이아웃, 네비게이션, 그리고 권한 관리 구조를 먼저 파악한 뒤 필요한 컴포넌트를 수정/추가해 주세요.

[개선사항 4] PocketExpense 프로젝트에 카카오톡 알림톡 Mocking(시뮬레이션) 기능을 구현하려고 합니다. 
추후 사업자등록 및 정식 카카오톡 비즈니스 채널 API 연동 시, API 키와 템플릿 코드만 쉽게 교체(Swappable)할 수 있도록 구조화해 주세요.

### [구현 요구사항]

1. **서비스/인터페이스 설계 (Swappable Architecture)**:
   - 알림톡 전송 책임을 갖는 서비스 레이어(예: `KakaoAlimTalkService` 등)를 인터페이스 또는 추상화된 함수 형태로 만들어 주세요.
   - 현재 단계에서는 **Mock 모드**로 동작하여, 알림톡 발송 요청이 들어오면 실제 외부 API를 찌르는 대신 **서버 콘솔(Console.log)에 템플릿 종류별로 이쁘게 포맷팅된 알림톡 내용**을 찍어주고, 성공 응답(Mock Response)을 반환하게 해주세요.

2. **핵심 알림톡 3가지 시나리오 및 페이로드(Payload) 구조**:
   - 아래 3가지 상황별로 필요한 데이터가 콘솔에 명확히 찍히도록 함수나 메서드를 분기해 주세요.
   - **① 지출 상신 알림 (직원 ➡️ 관리자)**
     - 트리거: 직원이 영수증 등록 및 지출결의 작성 후 상신할 때
     - 포함 데이터: 현장명/프로젝트명, 직원명, 결제 금액, 사용처(상호명), 결재 요청 링크 등
   - **② 결재 승인 완료 알림 (관리자 ➡️ 직원)**
     - 트리거: 관리자가 해당 지출을 승인(결재 완료)할 때
     - 포함 데이터: 상신한 직원명, 결제 금액, 사용처, "결재가 정상 완료되었습니다" 메시지 등
   - **③ 결재 반려 알림 (관리자 ➡️ 직원 + 반려 사유)**
     - 트리거: 관리자가 해당 지출을 반려할 때
     - 포함 데이터: 상신한 직원명, 결제 금액, 사용처, **반려 사유(필수 포함)** 등

3. **확장성 확보**:
   - 추후 정식 API 연동 시 환경 변수(`KAKAO_API_KEY`, 각 템플릿 ID 등)만 변경하거나 전략 패턴을 통해 실제 발송 모듈로 쉽게 갈아끼울 수 있도록 주석과 구조를 명확히 잡아주세요.

현재 프로젝트 구조를 확인하고, 알림톡 발송 관련 모듈 및 Mock 로직을 생성/수정해 주세요.
