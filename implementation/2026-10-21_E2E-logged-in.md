# 로그인 상태 E2E 점검 (①결재라인 ②필터·계정과목 ③정산·내 정보)

- 점검 일시: 2026-10-21
- 방식: 이메일 로그인을 켜지 않고, 관리자 키로 테스트 계정의 일회용 로그인 링크 → 세션 → 브라우저 쿠키(@supabase/ssr 형식)로 실제 앱(로컬 개발 서버 + 실제 DB)에 로그인. 임시 회사(smoke-e2e) 1곳·계정 4개(대표·관리자·팀장·직원), 끝나면 사진·회사·계정 삭제. 스크립트는 커밋하지 않음(.responsive/live)

## 시나리오 (모두 통과)
1. ① 대표: 영업팀 결재라인에 박팀장 검토자 저장
2. 직원(휴대폰 390): 새 소명서 → 영수증 업로드 → AI 인식(김밥천국 강남역점) → 항목을 사비로 → 소명 내용
3. ① 상신 확인 창에 "결재선: 박팀장 검토 → 관리자 승인" → 상신
4. ① 박팀장: 하단 [결재함] → 검토 승인
5. ② 관리자(PC 1440): 필터(출장비 → 없음, 식대 → 1건) → 계정과목 기업업무추진비로 조정("계정 조정됨") → 반려(사유 + 영수증 지목)
6. ② 직원: 반려 사유 확인 → 고쳐서 재상신 → 박팀장 2회차 검토 승인 → 관리자: 조정 유지 확인 → 일괄 승인
7. ③ 관리자: 정산 지급 관리(계좌 미등록 표시) → 지급 완료 처리 → 직원 정산 내역 "지급 완료" → 내 정보 계좌 등록(선택 동의)
8. 알림 기록 9건(결재 요청 6 = 팀장 2회 + 관리자 2명 × 2회, 반려 1, 승인 1, 지급 1), 알림 이력 화면, 운영자 영수증 기록 1건(인식 성공)

## 체감 시간 (누른 순간 → 화면에 결과, 로컬 개발 서버 — 배포 환경보다 느림)

## 점검 중 발견해 고친 것
- **회사 삭제가 막히던 버그**(migration 037): 크레딧을 쓴 영수증 기록이 있는 회사를 지우면, 연쇄 삭제 중 030의 삭제 트리거가 이미 지워지는 회사의 기록을 고치려다 외래키 위반으로 회사 삭제 전체가 실패. 회사가 지워지는 중이면 기록을 고치지 않게 수정. 016 테스트에 "회사 삭제 시 기록도 함께 삭제" 추가(수정 전 실패 → 수정 후 통과 확인). 이 버그 때문에 점검 중 남은 임시 회사 5곳은 수정 후 모두 지움
- **로그인한 화면의 개발 서버 오류**: 세션 확인이 현재 시각을 읽어 Next 미리 렌더링 단계에서 "unstable value Date.now()" 오류(개발 화면 "Issues")가 났다. 로그인 확인(`getCurrentUserId`·`getMembership`)을 요청 때 실행하도록(`connection()`) 바꿔 0건 확인. 미리보기는 로그아웃 상태라 그동안 드러나지 않았음
