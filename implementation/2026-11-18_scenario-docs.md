# 사용자 시나리오 점검 — 회사 양식 확장 1~4단계 + 저장 공간 (D-290)

- 일시: 2026-11-18 · 시나리오 E2E `.responsive/live/e2e-scenario-docs.mjs`(DB에 미리 넣는 것 없이 화면만 — 결재라인도 화면에서)

## 흐름
A 관리자 PC: 구매요청서 사진(HTML로 만든 PNG) → [양식 추가 › 일반 결재 문서] → AI 읽기(표를 못 찾으면 사용자처럼 다시 읽기) → 종류 자동 구매요청서 · 품목 표 자동(4열·3줄) → 정할 칸 정하기 → 등록 → 막대 1/3개 → [사전 검토 결재라인] 박팀장
B 직원 휴대폰: 홈 [결재 문서] → 쓰기(칸마다 입력 방식대로·표 3줄·첨부) → 미리보기(품목·결재 전) → 올리기 창 결재선
C 박팀장: 홈 결재함 배지 → 반려 / D 직원: 반려 배지 → 사유 → 고쳐 2회차 / E 박팀장 확인 / F 관리자 메뉴 배지 → 최종 승인
G [알림]방: 확인 요청·승인 요청·반려·승인 / H PDF·엑셀(품목·결재란 3명) / I 관리자 전체 목록 종류·상태·달·제목 / J 요금제 저장 공간 결재·증빙
UI: 직원 결재 문서 목록·보기, 박팀장 결재함(처리완료), 관리자 결재 문서(대기·전체·상세), 회사 양식, 요금제 — 390·768·1280 넘침 0, 스크린샷 확인

## 찾은 것 · 고친 것
1. AI 읽기가 가끔 '표를 찾지 못했어요. 다시 찍어 주세요'(5번 중 2번) — 서버 기록을 남겨 보니 Google AI 503(몰림)이 두 모델 모두. `src/lib/ai/gemini-retry.ts`(새): 바쁨(429·5xx·시간 초과)이면 1.5초 쉬고 같은 모델 한 번 더 → 대체 모델, 응답이 깨지면 바로 다음 모델. 회사 양식·서류 변환은 끝내 바쁘면 'AI가 몰려 있어요, 1~2분 뒤 다시'(회사 양식 다시 읽기 횟수·서류 변환 횟수·크레딧 그대로). 영수증·지출결의서 양식 읽기도 같은 다시 부르기. 실패 이유는 서버 기록(모델·초·상태 코드만). 테스트 `gemini-retry.test.ts`
2. AI가 제목을 '구 매 요 청 서'로 주면 양식 이름·문서 제목에 띄움이 그대로 → 제목 검색 안 됨. `tidyTitle`: 낱글자로만 띄운 제목은 붙임(단어 띄어쓰기는 그대로)
3. 결재 문서 쓰기: 첨부를 붙이거나 빼면 화면을 새로 읽는데, 자동 저장(1.2초) 전 입력이 있으면 먼저 저장(`saveFirst`)
4. 회사 양식 목록: 결재 문서 줄에 '2단계 준비 중'(옛 표시) → '직원이 쓰는 중'
5. 휴대폰(390) 결재 문서 보기: 품목 표 금액 열이 잘림 → 표 최소 폭 없앰·숫자 줄바꿈 안 함, [양식 보기·PDF·엑셀] 버튼 글자 꺾임 → 줄바꿈 안 함·작은 글씨
6. 운영 도움말 '요금제와 저장 용량' 둘째 단계를 새 기준(모든 파일 합계·꽉 차면 올리기 멈춤)으로 — 운영 DB help_steps 한 줄(사용자 지시)
7. 테스트 쪽(앱 문제 아님): e2e-leave 옛 기대값(D-251 설정 탭·설명 접힘·변경 이력 탭), 시나리오의 화면 그려지기 전 입력·목록 로딩 대기
