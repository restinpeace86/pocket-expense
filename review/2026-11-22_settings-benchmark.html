다모온 설정 벤치마킹

네이버웍스, 다우오피스, flex, 시프티, 비즈플레이, Google Workspace, Slack이 관리자 설정을 어떻게 두는지 공개 도움말로 확인하고 다모온과 비교했어요. 제품 화면을 직접 써 본 것은 아니라서 문서에 없는 것은 "확인 못 함"으로 적었어요.

한 줄 결론

메뉴 구조와 저장 방식은 이미 비슷하거나 앞서 있어요. 제품 안에 진행률이 있는 설정 마법사와 저장 안 함 경고는 공개 문서로는 다른 제품에서 확인되지 않았어요. 다른 제품이 더 잘하는 것은 세 가지예요. ① 설정 변경 이력이 모든 설정에 남는다 ② 바꾸면 어떻게 되는지 미리 보여 준다 ③ 엑셀로 직원·입사일·기존 연차를 한 번에 올린다.

우리 쪽에 적용하면 좋을 것 (추천 순서)

기능 동결 중이라 제안만 드려요. 고르신 것만 만들어요. B-1~B-3이 이번 설정 UX 흐름과 바로 이어져요.

B-1추천 1순위 · 작음최초 1회 설정 마지막에 [직원 초대] 단계 추가

flex와 시프티의 시작 가이드는 모두 회사·조직 → 근무 → 휴가 → 결재·권한 → 구성원 초대 순서예요. 정책을 다 정한 뒤 직원을 부르는 게 마지막 단계예요. 우리 마법사는 파일 보관에서 끝나서 가장 중요한 "직원 부르기"가 빠져 있어요. 마지막 단계로 초대 링크 복사 화면을 붙이면 돼요(약 1분). DB 변경은 없어요.

근거: flex 초기 설정 가이드, 시프티 시작하기(관리자)

B-2추천 2순위 · 중간설정 변경 이력을 모든 설정으로 넓히기

지금은 근태 설정만 "누가·언제·이전→이후"가 남아요. 네이버웍스는 관리자가 한 모든 작업을 180일 남기고, Google은 설정 이름·이전 값·새 값까지 남겨요. 식대 한도·유류비 단가·결재라인·마감 일정이 언제 누구 때문에 바뀌었는지는 세무사에게 설명할 때 필요해요. 설정 › [변경 이력] 한 곳에서 전체를 보게 해요. DB 표가 하나 필요해요.

근거: 네이버웍스 Admin 로그, Google 관리자 로그

B-3추천 3순위 · 중간"바꾸면 이렇게 돼요" 미리보기 (U-3과 합침)

flex는 연차 정책 화면에서 테스트 입사일을 넣어 보면 앞으로 연차가 어떻게 생기는지 미리 보여 주고, 정책을 바꾸면 "과거 연차까지 다시 계산돼요"라고 미리 경고해요. 우리 식대·유류비 화면의 예시("2명이 29,000원 먹으면 회사 24,000원")가 같은 방향이라, 이 모양을 다른 화면에도 넓혀요.

  • 직원별 연차: 입사일을 넣어 보면 올해·내년 연차 일수를 미리 보기
  • 마감 일정: "이렇게 바꾸면 이번 달 마감일은 12월 2일" 미리 보기
  • 연차 기준·5인 미만 바꾸기 전: 이미 확정한 연차에 어떤 영향이 있는지 경고
  • 모든 선택지에 [기본·추천] 표시(U-3)

근거: flex 연차 정책(자동 부여 미리보기·재계산 안내)

B-4중간 · 중간엑셀로 직원 입사일·기존 연차 한 번에 올리기 (U-15와 합침)

네이버웍스·flex·시프티 모두 엑셀 서식을 받아 채워 올리고, 틀린 줄은 이유를 보여 주고 고쳐 다시 올리는 방식이에요. 네이버웍스는 올해 쓴·남은 연차도 올릴 수 있어서 연말이 아닌 때에 옮겨 오는 회사도 바로 맞출 수 있어요. 우리는 직원별 연차에서 입사일을 한 명씩 넣어야 해요. 직원 초대는 지금처럼 링크로 두고, 입사일과 기존 연차만 엑셀로 받으면 돼요.

근거: 네이버웍스 부재 관리(데이터 불러오기), flex 여러 명 추가하기, 시프티 이관 가이드

B-5중간 · 작음설명에 "언제 켜야 하나요" 예시 붙이기

비즈플레이는 선택 항목마다 "이런 회사면 켜세요"를 예시로 설명하고, 네이버웍스는 근무 방식을 부서 예시(생산 = 교대, 영업 = 선택근무)로 보여 줘요. 우리 기능 사용·결재라인·회사 양식 화면에 "이런 회사는 켜세요 / 건너뛰세요" 한 줄을 붙여요. 최초 1회 설정의 단계별 이유 문구와 같은 말투로 맞춰요.

B-6확인 · 작음법정 휴가는 끌 수 없게 표시

flex는 법정 휴가를 기본으로 두고 지울 수 없게 해요(설정만 바꿈). 우리 휴가 종류 화면에서 법정 휴가(출산전후·배우자 출산 등)를 끌 수 있는지 확인하고, 끌 수 있으면 "법정 휴가라 끌 수 없어요"로 막을지 정해야 해요. 다만 우리 원칙이 "막지 말고 알려 주기"라서 경고만 할 수도 있어요.

B-7나중 · 큼메뉴별 관리자 권한

네이버웍스(유료)·다우오피스·flex 모두 "근태만 보는 관리자", "결재 양식만 고치는 관리자"처럼 메뉴 단위로 권한을 나눠요. 우리는 최고 관리자 / 관리자 두 가지예요. 50명 이하 회사에서는 아직 필요가 적어서 문의가 생기면 하는 게 맞아요.

B-8나중 · 큼기본 정책 + 예외 그룹

다른 제품은 "모두 기본 정책, 예외만 다른 그룹"(개인 → 하위 부서 → 상위 부서 순서로 적용)이에요. 우리는 결재라인만 부서별이 있고, 식대 한도·근무 기준은 회사 하나예요. 영업팀만 식대 한도가 다른 회사가 생기면 그때 검토해요.

이미 앞서 있는 것 (그대로 지키기)

  • 제품 안 최초 1회 설정: 다른 제품은 도움말 문서로 순서를 알려 줘요. 우리는 화면 안에서 단계·%·남은 시간을 보여 줘요.
  • 저장 안 함 경고: 공개 문서로는 다른 제품에서 확인되지 않았어요.
  • 설명 방식: 식대 예시·법 근거·기본값을 보여 주는 방식은 flex·네이버웍스 문서 수준과 같아요. 이 모양을 모든 화면으로 넓히는 게 B-3이에요.
  • 메뉴 수: 50명 이하 회사에 맞게 적게 유지하고 있어요. 보안·감사·아카이빙 같은 대기업용 메뉴는 따라 만들 필요가 없어요.
