# [Spec] 공통 UI 및 반응형 레이아웃 규칙

## 1. 화면 구조 (D-049, `workspace-architecture.md`)
- **직원 워크스페이스**: 모바일 퍼스트(`< 768px` 기준 설계). PC에서 열면 가운데 정렬된 모바일 폭(`max-w-md`)으로 보인다.
- **관리자 워크스페이스**(`/workspace/[id]/admin/**`): PC와 모바일 모두 지원하는 반응형. PC(`>= 768px`)는 좌측 사이드바 + 우측 메인 Split View, 모바일은 사이드바를 햄버거 메뉴로 접고 테이블은 카드 리스트, 승인은 카드형 슬라이드 뷰로 보여 준다. 기능은 줄이지 않는다.
- **워크스페이스 스위처**: 관리자 이상에게는 양쪽 헤더 우측 상단에 [ ⇄ 관리자 모드로 전환 ] / [ ⇄ 직원 모드로 전환 ] 버튼을 상시 노출한다. 일반 직원에게는 숨긴다.
- 카메라 촬영처럼 PC에서 쓸 수 없는 기능은 "카메라 촬영은 모바일에서 사용 가능합니다" 안내로 대체한다.

## 2. 모바일 규칙
- 하단 고정 CTA 또는 하단 내비게이션 바를 쓴다.
- 버튼·터치 영역은 `min-height: 44px` 이상.
- 숫자 입력은 `inputmode="numeric"`, 금액은 천 단위 콤마로 표시한다.
- 영수증 업로드는 `accept="image/*,application/pdf"`와 카메라 촬영(`capture`)을 함께 지원한다.

## 3. 디자인 시스템
- TailwindCSS 기본, 일관된 색상 팔레트, `rounded-xl`, `shadow-sm`의 깔끔한 SaaS 톤.
- 아이콘: `lucide-react` (카테고리: 일반 식대 `Utensils`, 출장비 `Briefcase`, 미팅비 `Users` / 출장 세부 유형: 출장 식비 `UtensilsCrossed`, 대중교통 `TrainFront`, 택시 `CarTaxiFront`, 통행료·주차 `ParkingSquare`, 숙박 `BedDouble`, 자차 `Car`, 기타 `Receipt`).

## 4. 상태 배지 표준 (D-022) — 지출소명서 상태
| 상태 | 표시명 | 클래스 |
|---|---|---|
| `draft` | 📝 임시저장 | `bg-gray-100 text-gray-700` |
| `submitted` | 🟡 검토 대기 | `bg-yellow-100 text-yellow-800` |
| `approved` | ✅ 승인 완료 (정산 대기) | `bg-green-100 text-green-700` |
| `rejected` | 🔴 반려됨 | `bg-red-100 text-red-700` |
| `paid` | 💰 정산 지급 완료 / 정산 없는 건은 "✅ 승인 완료 (정산 없음)" | `bg-purple-100 text-purple-700` |
- 직원 정산 화면(E-03)과 관리자 정산 지급 관리(A-02)에서는 `approved`를 "🟡 정산 대기"로 표시한다.

- `submitted` 배지 옆에 사전 검토가 있으면 진행 문구(예: "팀장 검토 중")를 함께 표시한다.

## 5. 로딩 · 에러
- 영수증 파싱, 양식 분석, 거리 계산, 엑셀/ZIP 생성 등 비동기 처리 중에는 스켈레톤 또는 스피너를 반드시 표시한다.
- 에러는 토스트 또는 인라인 안내 문구로 사용자 친화적으로 알리고, 가능한 경우 대체 경로(수동 입력, 재시도)를 함께 제시한다.
- 성공한 저장·상신·승인·반려는 토스트로 확인시킨다.
- 금액·결재 처리 같은 되돌릴 수 없는 액션(상신, 승인, 반려, 정산완료, 삭제)은 확인 다이얼로그를 거친다.

## 6. 화면 설명(도움말) 표시 규칙 (D-065)
관리자·직원이 화면마다 "이 설정이 무엇이고 왜 필요한지" 이해할 수 있어야 한다. 다만 설명이 화면을 덮지 않도록 3단계로 나눈다.
| 단계 | 표시 | 내용 |
|---|---|---|
| ① 한 줄 요약 | 제목 아래 **항상** | 이 화면·항목이 무엇을 하는지 한 문장 |
| ② 자세히 | **[ⓘ 왜 필요한가요?]**(또는 [ⓘ 이렇게 해요] 등)를 눌러 **그 자리에서 펼침** | 왜 필요한지, 선택지별 차이, 지나거나 바꾸면 어떻게 되는지 |
| ③ 예시 | **선택한 선택지에만** | 실제 숫자로 된 예시(오늘 날짜·실제 금액 기준) |

- 팝업·별도 가이드 페이지로 띄우지 않는다(설명을 읽으며 선택지를 비교할 수 없고 모바일에서 불편).
- 처음 보는 사람을 위해 각 ②는 **그 브라우저에서 처음 볼 때 한 번 펼친 상태**로 보여 주고, 이후에는 접힌 상태로 보여 준다(브라우저 저장, 실패하면 접힌 상태).
- 공용 컴포넌트: `src/components/ui/help.tsx`(`SectionHeading`, `HelpDetails`). 새 화면도 이 컴포넌트로 만든다.
