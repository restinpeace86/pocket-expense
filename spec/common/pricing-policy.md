# [Spec] 비즈니스 모델 및 과금/결제 정책 (Pricing & Billing Policy)

## 1. 과금 철학 및 원칙
- **영구 무료 플랜 없음**: 서버비, Vision LLM API 비용, 카카오톡 알림톡 원가 방어를 위해 상시 무료 플랜은 운영하지 않는다.
- **월 구독 모델 (Monthly Subscription)**: 정식 런칭 후에는 매월 1일에 사용량이 자동 리셋되며, 미사용 잔여 장수는 이월되지 않는다 (`Use-it-or-lose-it`).

## 2. 요금제 구조
- **무료 체험 (Free Trial)**: 
  - 가입 즉시 **누적 100장 영수증 무료 처리 크레딧** 제공 (기간 제한 없음).
  - 100장을 모두 소모하는 시점에 추가 업로드가 일시 중지되며 유플랜 선택을 요구함.
- **정식 월 구독 플랜**:
  - **베이직 (Basic)**: 월 40,000 원 / 월 300장 제공 (5~10인 소기업)
  - **스탠다드 (Standard)**: 월 70,000 원 / 월 600장 제공 (10~20인 기업)
  - **프로 (Pro)**: 월 100,000 원 / 월 1,000장 제공 (20~30인 기업)

## 3. 한시적 운영 및 결제 예외 처리 (MVP 페이즈 수동 크레딧 정책)
- **배경**: 사업자등록증 발급 및 PG사(토스페이먼츠 등) 결제 시스템 연동 전까지의 초기 검증 기간 동안 적용하는 예외 운영 룰.
- **수동 크레딧 연장 (Manual Grant)**:
  - 기업 고객이 무료 체험(누적 100장)을 모두 소모한 이후, 유료 결제 시스템이 아직 연동되지 않은 상태이므로 **플랫폼 운영자(관리자)가 백엔드 DB 또는 운영자 툴에서 수동으로 추가 크레딧(예: 추가 100장 부여 또는 체험 기간 연장)을 직접 지급**할 수 있다.
- **동작 방식**:
  - 고객사별 잔여 크레딧이 0이 되었을 때, 운영자에게 요청 또는 사전 협의된 경우 운영자가 백엔드에서 해당 기업의 `remaining_credits`를 수동으로 갱신하여 서비스 중단 없이 계속 테스트 및 실무 활용이 가능하도록 조치한다.

## 4. MVP 단계 '가상 결제(Mock Payment)' UI 처리 전략
- **동작 방식**:
  - 결제/구독 신청 화면과 카드 등록 UI는 정석대로 구현하되, 현재는 **'사전 체험 프로모션 기간'**으로 처리.
  - 결제 버튼 클릭 시 실제 과금 없이 **"사전 프로모션 적용으로 이번 달 결제 금액 0원으로 즉시 활성화되었습니다"**라는 안내 팝업과 함께 구독 상태가 `ACTIVE`로 전환되도록 Mock(가상) 처리.
  - 향후 사업자등록 및 PG 연동 시 UI 수정 없이 백엔드 API만 연동하도록 설계.
