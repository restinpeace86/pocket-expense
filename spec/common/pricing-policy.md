# [Spec] 비즈니스 모델 및 과금/결제 정책 (Pricing & Billing Policy)

관련: D-046 (D-027 대체), D-054, D-077 → D-081 → **D-133(현재 가격)** → **D-198(이름·직원 수·혜택 표시)** / 화면: `spec/screens/admin-billing.md` / 데이터: `billing_plans`, `companies.receipt_credits_*`, `credit_ledger`

## 1. 과금 철학 및 원칙
- **영구 무료 플랜 없음**: 서버비, Vision LLM API 비용, 카카오 알림톡 원가 방어를 위해 상시 무료 플랜은 운영하지 않는다.
- **월 구독 모델 (Monthly Subscription)**: 정식 결제 도입 후에는 매월 1일에 사용량이 리셋되며 미사용 잔여 장수는 이월되지 않는다(Use-it-or-lose-it). 정식 결제 도입 전에는 구현하지 않는다.
- **과금 단위는 영수증 1장**: 영수증 사진·파일 업로드 1건 = 1장.

## 2. 요금제 구조
- **설계 원칙 (D-133, D-081 가격 대체)**: B2B SaaS 표준대로 **공급가액 기준 + VAT 별도(세금계산서 발행)**. 선택이 쉬운 **3단 라인업**(스타터/스탠다드/프로). **월간 결제로 먼저 선보인다** — 연간 선결제는 나중에 다시 정한다(사용자 결정 2026-10-27, `billing_plans.annual_price`는 비워 두고 화면에 표시하지 않음).
- **정식 구독 플랜 (D-133)**:
  | 플랜 (내부 코드) | 직원 수 (D-198) | AI 영수증 읽기 | 월간 자동결제 (공급가액, VAT 별도) | 대상 |
  |---|---|---|---|---|
  | 스타터 (`starter`) | 최대 10명 (1인당 약 2,900원) | 월 150장 | 월 29,000원 | 1인 사업자·소규모 현장 팀 |
  | **프로 (`standard`, 추천·주력)** | 최대 20명 (1인당 약 2,450원) | 월 400장 | 월 49,000원 | 본격적으로 현장을 뛰는 소기업 |
  | 비즈니스 (`pro`) | 제한 없음 | 월 800장 | 월 89,000원 | 현장 여러 곳을 함께 운영하는 팀 |
  - **D-198 (사용자 결정 2026-11-03)**: 이름을 스타터/프로/비즈니스로(옛 스탠다드 → 프로, 옛 프로 → 비즈니스, 내부 코드는 그대로). 가격은 그대로. **모든 기능은 모든 플랜에 같고, 차등은 직원 수와 AI 영수증 읽기 장수**. 요금 카드는 장수만이 아니라 "이 가격에 포함"(직원 수·1인당 가격 / AI 영수증 읽기·장당 가격 / 모든 기능 포함) + 카드 아래 "모든 플랜에 똑같이 포함" 기능 목록(지금 있는 기능만, `src/lib/billing/plan-benefits.ts`).
  - **직원 수 세는 법·적용(D-199, D-198 대체)**: 계정 수가 아니라 **그 달에 영수증을 1장 이상 올린 사람**(크레딧 사용 기록의 올린 사람 기준). 대표·경리도 영수증을 올린 달만 세고 결재·정산·마감만 하면 세지 않음. 세무사무소 계정은 세지 않음. **한도를 넘어도 영수증 올리기는 막지 않고**, 직원 초대 단계에서 플랜 올리기를 안내(결제 연동 때 적용, 지금은 표시만).
  - **요금 기준 6줄(D-199)** — 요금제 화면·랜딩 요금 카드 아래와 FAQ에 같은 문장(`src/lib/billing/plan-benefits.ts` `PRICING_RULES`): ① 직원 수 = 그 달 영수증을 올린 사람(대표·경리 포함 규칙) ② 세무사무소 계정 제외 ③ 플랜 인원을 넘어도 업로드는 막지 않고 초대 때 안내 ④ AI 영수증 읽기 장수는 매월 1일 새로, 이월 없음 ⑤ 홈택스 자료 올리기·카드 내역 대조는 장수에서 빠지지 않음 ⑥ 장수 소진·유료 구독 해지 뒤에도 지난 자료 조회·내려받기 가능(서비스 탈퇴=이용 계약 해지는 30일 뒤 파기 — 약관 제9·17조).
  - **가격 표기(D-199)**: 1인당 가격은 최대 인원을 채웠을 때의 계산이라 "최대 인원 기준"을 붙여 보조로만. 앞에 내세우는 말은 "그 안에서는 인원이 늘어도 같은 가격".
  - 가격은 공급가액이며 결제 시 VAT 10%가 별도로 붙고 세금계산서를 발행한다. 예: 프로 49,000원 + VAT 4,900원 = 53,900원. 화면·랜딩에서는 가격 옆에 "(VAT 별도)"(D-078).
  - **요금 카드 아래 안내(랜딩·요금제 화면)**: "※ 매월 제공되는 기본 크레딧 중 사용하지 않은 잔여 장수는 다음 달로 이월되지 않습니다."
  - **추가 크레딧(애드온)**: 50장당 8,000원(VAT 별도, `billing_addons`). 요금제 고르는 곳의 상품이 아니라 **남은 장수가 0일 때만** 요금제 화면에 [추가 크레딧 충전]으로 나타난다. 결제 연동 전이라 버튼은 비활성("결제 준비 중").
  - **후기 쿠폰 = 첫 결제 50% 할인 (D-201, D-134 대체)**: 모든 회사의 첫 결제 50% 할인은 없앤다. 후기(설문)를 남긴 회사(`companies.review_coupon_at`)가 아직 결제한 적 없으면(`first_purchase_at` 없음) 첫 달 월간 요금 50% 할인(스타터 14,500 / 프로 24,500 / 비즈니스 44,500원 + VAT). 쿠폰이 없으면 요금 카드에 "후기를 남기면 첫 결제 50% 할인 쿠폰을 드려요". 실제 결제는 PG 연동 때.
  - **월간 연속 결제 보너스 (⛔ 미결 O-09)**: 확정 전까지 화면에 표시하지 않고 구현하지 않는다. (2026-10-28 사용자: 보류 유지, 추후 다른 할인 정책으로 검토 — 지금 할인은 첫 결제 50%만, D-145)
- 800장을 넘게 쓰는 회사(옛 엔터프라이즈 대상)·장수 초과 시 처리는 결제 연동 때 정한다.
- **무료 이용 = 첫 월말 마감까지 (D-201, 사용자 결정 2026-11-03 — 이전: 누적 100장)**: 가입한 달 + 다음 달 세무 마감일(5일, 쉬는 날이면 앞 영업일)까지 무료(`companies.trial_ends_on`, `private.trial_end_for`). 25일 이후 가입은 한 달 더(어느 날 가입해도 마감·세무사무소 전달까지 한 번은 해 보게). 장수는 안전 상한만(가입 지급 800장 = 비즈니스 플랜 수준, `app_settings.trial_receipt_cap`). 결제 연동 전(B-4)이라 종료일이 지나도 막지 않고 "결제 준비 중이라 계속 무료" 안내. 이미 있던 회사는 가입일 기준으로 종료일을 채움. **예외 회사(D-202)**: `trial_ends_on`이 비어 있으면 종료일 없이 "무료 이용 중", 후기 요청 배너도 띄우지 않음 — 운영사 회사(페이퍼컴퍼니)만 해당.
- **후기 요청 (D-201, D-130 보상 변경)**: 조건은 그대로(한 줄 후기 공백 빼고 10자 이상 + 홈페이지 소개 동의, D-137), 보상은 +100장 대신 첫 결제 50% 할인 쿠폰. 요청 시점: 첫 세무 마감을 마친 뒤 또는 무료 기간 3일 전(관리자 홈 배너 + 요금제 화면 버튼 강조), 아직 후기를 안 남긴 회사만. 랜딩 후기에 "후기를 남긴 회사에 첫 결제 50% 할인 쿠폰을 드려요" 표시(추천·보증 표시).
- **이벤트 추가 지급 (현재)**: 이벤트 기간에는 100장을 모두 쓰면 **추가 100장을 자동으로 무료 지급**한다(§5, D-054).

## 3. 현재 운영 방식 (결제 시스템 연동 전)
- 결제 화면(`admin-billing.md`)은 정식 형태로 보이되 **결제를 진행할 수 없도록 막아 둔다**(플랜 선택·약관 체크·결제 버튼 모두 비활성, "무료 제공 기간" 안내).
- 실제 결제, 가상 결제 활성화, 운영자 수동 크레딧 지급은 **하지 않는다**.
- 100장을 모두 쓰면 이벤트 추가 지급(§5)으로 계속 쓸 수 있다. 이벤트가 꺼져 있을 때만 업로드가 중지된다(§4).
- 향후 사업자등록·PG(토스페이먼츠 등) 연동 시 결제 화면 수정 없이 백엔드 결제 API와 월 리셋만 추가하도록 설계한다.

## 4. 크레딧 차감 규칙
| 상황 | 처리 |
|---|---|
| 영수증 파일 업로드 성공 | 1장 차감 (`credit_ledger`에 `receipt_upload` 기록) |
| 같은 항목에서 [다시 올리기](교체) | 추가 차감 없음 |
| 항목·결의서 삭제 | 환급 없음 |
| 영수증 없는 항목(자차 유류비 등) | 차감 없음 |
| AI 파싱 실패 | 업로드는 성공했으므로 차감 유지 |
| 남은 크레딧보다 많은 장수 선택 | 이벤트 기간: 중간에 0이 되면 추가 지급 후 전부 업로드(§5). 이벤트 꺼짐: 남은 장수만큼만 업로드, 나머지는 "무료 사용량을 초과했습니다" 안내 |
- 차감은 서버에서 원자적으로 처리한다(동시에 여러 직원이 올려도 0 미만이 되지 않음).
- **남은 20장 이하**: 관리자 대시보드·요금제 화면에 "무료 사용량이 n장 남았습니다" 안내(이벤트 기간이면 "소진 시 이벤트로 100장이 추가 지급됩니다" 덧붙임).
- **0장**: 이벤트 기간이면 §5에 따라 즉시 추가 지급. 이벤트가 꺼져 있으면 직원 화면의 영수증 추가 버튼이 막히고 "회사 무료 사용량을 모두 사용했습니다. 관리자에게 문의하세요" 안내. 이미 올린 영수증으로 작성·상신·결재·정산·세무 마감은 계속 가능하다.

## 5. 이벤트 추가 지급 (D-054)
- **조건**: 이벤트가 켜져 있고(`CREDIT_EVENT_BONUS_ENABLED=true`, 기본 켜짐), 회사의 남은 크레딧이 0이 되는 순간.
- **지급**: 서버가 같은 트랜잭션에서 `CREDIT_EVENT_BONUS_AMOUNT`(기본 100)장을 자동 지급한다(`receipt_credits_granted += 100`, `credit_ledger` +100 `event_bonus`). 이벤트 기간에는 소진할 때마다 반복 지급된다.
  - 여러 장을 한 번에 올리다 중간에 0이 되면 그 자리에서 지급하고 나머지 업로드를 계속한다(직원 업로드가 끊기지 않음).
- **안내**:
  - 업로드한 직원: 토스트 "회사 무료 영수증 100장을 모두 사용했습니다. 현재 이벤트 기간이라 추가 100장을 무료로 더 드립니다."
  - 관리자 이상: 다음 접속 시 대시보드 상단 배너 + 요금제 화면에 같은 문구와 "이벤트 추가 지급 n회 (총 지급 n장)". 배너는 [확인]으로 닫는다(회사별 `last_event_bonus_at` 이후 확인 여부 저장).
- **이벤트 종료**: 환경변수로 끄면 이후 소진 시 추가 지급 없이 §4의 0장 규칙(업로드 중지)을 따른다. 이미 지급된 크레딧은 유지된다.
- 이벤트 값(사용 여부·지급 장수)은 코드에 하드코딩하지 않고 환경변수로 관리한다.
