# [Spec] 비즈니스 모델 및 과금/결제 정책 (Pricing & Billing Policy)

관련: D-046 (D-027 대체), D-054, D-077 / 화면: `spec/screens/admin-billing.md` / 데이터: `billing_plans`, `companies.receipt_credits_*`, `credit_ledger`

## 1. 과금 철학 및 원칙
- **영구 무료 플랜 없음**: 서버비, Vision LLM API 비용, 카카오 알림톡 원가 방어를 위해 상시 무료 플랜은 운영하지 않는다.
- **월 구독 모델 (Monthly Subscription)**: 정식 결제 도입 후에는 매월 1일에 사용량이 리셋되며 미사용 잔여 장수는 이월되지 않는다(Use-it-or-lose-it). 정식 결제 도입 전에는 구현하지 않는다.
- **과금 단위는 영수증 1장**: 영수증 사진·파일 업로드 1건 = 1장.

## 2. 요금제 구조
- **정식 월 구독 플랜**:
  | 플랜 | 월 요금(부가세 별도) | 월 제공 장수 | 장당 | 권장 규모 |
  |---|---|---|---|---|
  | 스타터 (Starter) | 25,000원 | 150장 | 약 167원 | 5~10인 |
  | **스탠다드 (Standard, 추천·주력)** | 50,000원 | 400장 | 125원 | 10~25인 |
  | 프로 (Pro) | 100,000원 | 1,000장 | 100원 | 25~50인 |
  | 엔터프라이즈 (Enterprise) | 200,000원 | **무제한** (공정 사용 기준 월 3,000장, 넘으면 맞춤 상담) | 67원 이하 | 50인 이상 |
  - 장수가 많을수록 장당 가격이 내려간다(상위 요금제로 올릴 이유). 엔터프라이즈는 공정 사용 기준을 넘으면 맞춤 가격을 상담한다(D-077).
  - 화면·랜딩에는 "부가세 별도"를 함께 표시한다.
- **한시적 무료 제공 (현재)**: 회사를 처음 등록하면 **누적 100장 무료 크레딧**을 지급한다(기간 제한 없음).
- **이벤트 추가 지급 (현재)**: 이벤트 기간에는 100장을 모두 쓰면 **추가 100장을 자동으로 무료 지급**한다(§5, D-054).

## 3. 현재 운영 방식 (결제 시스템 연동 전)
- 결제 화면(`admin-billing.md`)은 정식 형태로 보이되 **결제를 진행할 수 없도록 막아 둔다**(플랜 선택·약관 체크·결제 버튼 모두 비활성, "무료 제공 기간" 안내).
- 실제 결제, 가상 결제 활성화, 운영자 수동 크레딧 지급은 **하지 않는다**.
- 100장을 모두 쓰면 이벤트 추가 지급(§5)으로 계속 쓸 수 있다. 이벤트가 꺼져 있을 때만 업로드가 중지된다(§4).
- 향후 사업자등록·PG(토스페이먼츠 등) 연동 시 결제 화면 수정 없이 백엔드 결제 API와 월 리셋만 추가하도록 설계한다.

## 4. 크레딧 차감 규칙
| 상황 | 처리 |
|---|---|
| 영수증 파일 업로드 성공 | 1장 차감 (`credit_ledger`에 `receipt_upload` 기록) |
| 같은 항목에서 [다시 올리기](교체) | 추가 차감 없음 |
| 항목·소명서 삭제 | 환급 없음 |
| 영수증 없는 항목(자차 유류비 등) | 차감 없음 |
| AI 파싱 실패 | 업로드는 성공했으므로 차감 유지 |
| 남은 크레딧보다 많은 장수 선택 | 이벤트 기간: 중간에 0이 되면 추가 지급 후 전부 업로드(§5). 이벤트 꺼짐: 남은 장수만큼만 업로드, 나머지는 "무료 사용량을 초과했습니다" 안내 |
- 차감은 서버에서 원자적으로 처리한다(동시에 여러 직원이 올려도 0 미만이 되지 않음).
- **남은 20장 이하**: 관리자 대시보드·요금제 화면에 "무료 사용량이 n장 남았습니다" 안내(이벤트 기간이면 "소진 시 이벤트로 100장이 추가 지급됩니다" 덧붙임).
- **0장**: 이벤트 기간이면 §5에 따라 즉시 추가 지급. 이벤트가 꺼져 있으면 직원 화면의 영수증 추가 버튼이 막히고 "회사 무료 사용량을 모두 사용했습니다. 관리자에게 문의하세요" 안내. 이미 올린 영수증으로 작성·상신·결재·정산·세무 마감은 계속 가능하다.

## 5. 이벤트 추가 지급 (D-054)
- **조건**: 이벤트가 켜져 있고(`CREDIT_EVENT_BONUS_ENABLED=true`, 기본 켜짐), 회사의 남은 크레딧이 0이 되는 순간.
- **지급**: 서버가 같은 트랜잭션에서 `CREDIT_EVENT_BONUS_AMOUNT`(기본 100)장을 자동 지급한다(`receipt_credits_granted += 100`, `credit_ledger` +100 `event_bonus`). 이벤트 기간에는 소진할 때마다 반복 지급된다.
  - 여러 장을 한 번에 올리다 중간에 0이 되면 그 자리에서 지급하고 나머지 업로드를 계속한다(직원 업로드가 끊기지 않음).
- **안내**:
  - 업로드한 직원: 토스트 "회사 무료 영수증 100장을 모두 사용했습니다. 현재 이벤트 기간이라 추가 100장을 무료로 더 드립니다."
  - 관리자 이상: 다음 접속 시 대시보드 상단 배너 + 요금제 화면에 같은 문구와 "이벤트 추가 지급 n회 (총 지급 n장)". 배너는 [확인]으로 닫는다(회사별 `last_event_bonus_at` 이후 확인 여부 저장).
- **이벤트 종료**: 환경변수로 끄면 이후 소진 시 추가 지급 없이 §4의 0장 규칙(업로드 중지)을 따른다. 이미 지급된 크레딧은 유지된다.
- 이벤트 값(사용 여부·지급 장수)은 코드에 하드코딩하지 않고 환경변수로 관리한다.
