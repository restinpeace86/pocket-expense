# [Spec] 출장비 (출장 결의서 · 세부 유형 · 자차 거리/유류비)

관련: D-008, D-018, D-034, D-035, D-040, D-068, D-069(→D-089), **D-085**, D-088, **D-089** / 데이터: `expense_claims`의 출장 정보, `expense_items`의 trip 관련 컬럼 / 계산 규칙 원본: `spec/data/expense-lifecycle.md` §5.2, §5.3

## 1. 일반 경비와 출장비의 구분 (D-035)
- (D-097) **출장비는 영수증 카테고리가 아니라 결의서 상단 [출장 경비] 모드**다. 일반 결의서의 영수증 카테고리 선택지에는 출장비가 없고, 출장 결의서의 영수증은 모두 출장비로 처리되며 영수증 편집에서는 세부 유형만 고른다.
- **출장 중에 쓴 비용은 종류와 상관없이 모두 출장비(`trip`)** 로 분류한다. 출장 중 식비, 교통비, 톨게이트비, 주차비, 숙박비, 자차 유류비가 모두 출장비의 세부 유형이다.
- **일반 식대(`meal`)** 는 출장이 아닌 평소 점심·야근 식대다.
- **출장 식비(`trip` / `meal`)** 도 1식 한도 × 인원수를 적용한다(D-040, `smart-meal.md`). 예: 부산국밥 17,000원, 한도 10,000원 → 절사 모드에서 10,000원 지급, 7,000원 개인 부담. 계정과목은 여비교통비.

| 상황 | 카테고리 | 세부 유형 |
|---|---|---|
| 평소 점심 식대 | 식대(`meal`) | — |
| 부산 출장 중 점심 | 출장비(`trip`) | 출장 식비(`meal`) |
| 출장 KTX | 출장비(`trip`) | 대중교통(`public_transport`) |
| 출장 고속도로 톨게이트 | 출장비(`trip`) | 통행료·주차(`toll_parking`) |

## 2. 출장 결의서 (헤더)
- 결의서 편집 화면 헤더의 **[출장 경비] 스위치**를 켜면 출장 결의서가 된다(`expense_claims.is_business_trip`).
- 출장 정보(켜면 필수): 출장지(`trip_destination`), 출장 기간(`trip_start_date` ~ `trip_end_date`), 출장 목적(`trip_purpose`).
- **출장 기간 입력(D-085)**: 날짜 창 두 개 대신 **달력 하나(날짜 범위 선택)** — 시작일을 누르고 종료일을 누른다(같은 날 두 번 = 당일, 시작일보다 앞을 누르면 그날부터 다시). 연월일만, 시간 없음. 요약 표시 "2026.10.14 (수) ~ 10.15 (목) · 1박 2일". 휴대폰에서는 드래그 대신 두 번 누르기(드래그는 화면 스크롤과 겹친다).
- **이동 수단(D-085)**: [🚗 자차] / [🚄 대중교통·KTX] (`expense_claims.trip_transport`, 선택 입력). 대중교통·KTX는 지금처럼 교통편 영수증을 올린다. 자차를 고르면 결의서 안에 **자차 유류비** 칸이 열리고 [경로 입력하고 유류비 계산] → 자차 항목(§4)을 만든다. 여러 구간이면 [자차 이동 하나 더]. 자차 유류비를 쓸 수 없는 경우(§4 회사 설정·자가운전보조금)는 버튼 대신 안내만.
- 출장 결의서에 추가되는 영수증 항목은 **카테고리 기본값이 출장비**가 되고, AI가 세부 유형을 추천한다(`receipt-parser.md` §3). 예: 식당 영수증 → 출장 식비, 하이패스·톨게이트 영수증 → 통행료·주차, KTX 승차권 → 대중교통, 호텔 → 숙박.
- 출장 결의서 안에서도 직원이 항목 카테고리를 바꿀 수 있다(예: 출장과 무관한 영수증이 섞인 경우 일반 식대로 변경).
- 출장 기간 밖의 결제일자를 가진 출장비 항목은 "출장 기간 밖" 노란 경고를 표시한다(상신은 가능).
- 제목 자동 제안(출장 결의서): "{시작일 M/D} {출장지} 출장" (예: "10/15 부산 출장").
- 출장 결의서가 아니어도 출장비 항목을 넣을 수 있다(예: 시내 외근 택시). 이때 출장 정보는 항목의 적요로 남긴다.

## 3. 세부 유형 (`trip_type`, 출장비 항목 필수)
| 값 | 표시명 | 영수증 | 금액 입력 | 추가 입력 |
|---|---|---|---|---|
| `meal` | 출장 식비 | 필수 | 영수증 파싱/직접 입력 | 인원수(필수, 기본 1), 1식 한도 적용 |
| `public_transport` | 대중교통(KTX·버스·항공 등) | 필수 | 영수증 파싱/직접 입력 | |
| `taxi` | 택시 | 필수 | 영수증 파싱/직접 입력 | |
| `toll_parking` | 통행료·주차 | 필수 | 영수증 파싱/직접 입력 | |
| `lodging` | 숙박 | 필수 | 영수증 파싱/직접 입력 | 숙박 기간(체크인~체크아웃) |
| `own_car` | 자차 유류비 | 선택 | 거리 × 단가 자동 계산 | 출발지·도착지·거리(§4) |
| `other` | 기타 | 필수 | 영수증 파싱/직접 입력 | 적요 필수 |

- 항목 공통 입력: 적요(`purpose`, 권장), 결제수단.
- 항목의 `trip_start_date`/`trip_end_date`는 숙박 기간에만 쓴다(숙박이면 필수). 출장 전체 기간은 결의서 헤더에 둔다.
- 자차 항목은 영수증 없이 [영수증 없이 항목 추가]로 만든다.

## 3-1. 회사차량으로 간 출장 (D-106)
- 출장 이동 수단: [자차] [대중교통] [회사차량]. [회사차량]을 고르면 "어느 차로 갔나요"에서 등록된 회사차량을 고른다(등록된 차량이 있으면 필수, `company-vehicles.md`).
- 그 출장의 주유·통행료·주차 영수증은 세부 유형 **회사차량 주유**(`car_fuel`)·**회사차량 통행료·주차**(`car_toll`) → 기본 계정과목 **차량유지비**. 숙박·식사·대중교통·택시는 여비교통비 그대로.
- 톨비(`toll_parking`)는 자동으로 회사차량 통행료·주차가 되고, AI가 주유소로 본 영수증은 회사차량 주유가 된다. 이동 수단을 다른 것으로 바꾸면 되돌린다(주유는 "기타").
- 자차(개인 차) 출장은 지금처럼 km당 유류비 + 톨비·주차 모두 여비교통비.

## 4. 자차 유류비 (`own_car`)
- 회사 설정이 자차 유류비 **사용 안 함**(`fuel_enabled=false`, D-068)이면 세부 유형 선택지에 `own_car`를 보여 주지 않고, 서버도 새 `own_car` 항목을 받지 않는다(이미 있는 항목은 그대로).
- 청구자가 **자가운전보조금 받음**(`members.receives_car_allowance=true`, D-070)이면 같은 방식으로 `own_car`를 막고 "자가운전보조금을 받고 있어 자차 유류비는 청구할 수 없어요. 통행료·주차비는 영수증으로 올려 주세요" 안내.
- 회사 설정 **계기판 사진 받기**(`companies.odometer_photo_required=true`, D-070)면 자차 항목에 출발·도착 계기판 사진 2장이 필수(영수증 첨부와 같은 Storage 규칙). 꺼져 있으면 첨부란을 보이지 않는다.
### 4.1 입력
- (D-097) **화면 이동 없음**: 결의서의 이동 수단에서 [자차]를 고르면 그 자리에서 경로 입력 칸이 펼쳐진다. 항목은 첫 장소를 고를 때 만들어진다(자차만 눌러 두고 떠나도 빈 항목이 남지 않음). 경로 카드는 접고 펼 수 있고, 영수증 목록의 자차 행을 누르면 출장 영역의 그 경로가 펼쳐진다. 사용일·적요는 0.8초 뒤 자동 저장.
- 출발지·도착지: **자동완성 검색**(글자를 치면 0.3초 뒤 `/api/places` → Kakao Local 장소·주소 검색, 로그인한 멤버만, `KAKAO_REST_API_KEY`는 서버에서만)으로 목록에서 고른다 → `start_location`/`end_location`, 좌표 저장(국내 좌표만). 출장 결의서면 도착지 칸에 "출장지 OO(으)로 찾기"를 제안한다.
- 두 곳을 고르면 **자동으로** 서버가 Kakao Mobility 길찾기(자동차 추천 경로)로 편도 거리를 구한다 → `route_one_way_km`(소수 첫째 자리 반올림), `distance_source='api'`. 거리 반영은 서버 전용 함수가 저장된 좌표와 같을 때만 한다(직원이 거리·출처를 직접 쓸 수 없음).
- 결과는 **'출장 경로 및 거리 산정 요약' 디지털 카드**(출발지·도착지·주소, 총 주행 거리, 왕복/편도, 계산식, 정산 금액, 계산 기준·시각)로 영수증 자리에 붙는다 — 내비 화면 캡처를 올리지 않는다. 직원 항목 화면·결의서 화면·관리자/사전 검토자 영수증 패널에 같은 카드.
- **증빙 파일(D-088)**: 상신이 끝나면 서버가 확정된 값(경로·거리·단가 스냅샷·금액)으로 증빙 이미지(PNG, 결의서 제목·청구자·차량번호·사용일·출장 목적·출발/도착 주소·총 거리·계산식·거리 근거·정산 금액·상신 시각)를 만들어 영수증 버킷 `{company}/route-cards/{claim}/{item}.png`에 저장하고 `route_card_path`로 연결한다. 직원은 이 폴더에 올리거나 덮어쓸 수 없다(위조 방지). 결재 화면 영수증 패널은 이 이미지를 보여 주고(없으면 값으로 그린 카드), 세무 마감 ZIP에는 영수증 사진처럼 이 파일을 넣는다(T10). 반려 뒤 경로·거리·금액을 바꾸면 연결이 끊기고 다시 상신할 때 새로 만든다. 항목을 지우면 파일도 지운다.
- 차량번호: 멤버 프로필 `vehicle_number`를 보여 주고, 없으면 "내 정보에서 차량번호를 등록하세요" 안내(상신은 막지 않음).
- `payment_method`는 개인카드로 고정한다(`expense-lifecycle.md` §5.5).
- `expense_date` 기본값은 출장 시작일(출장 결의서가 아니면 오늘). 직원이 바꿀 수 있다.

### 4.2 계산
- 청구 금액 = `편도 거리 × 회사 km당 단가`(원 단위 반올림) × (왕복이면 2). **DB가 계산**(직원이 금액을 넣지 않음, `private.recompute_claim`)하고 상신 때 `applied_fuel_rate_per_km` 스냅샷. 화면은 같은 식으로 미리 보여 주기만(`src/lib/expense/route.ts`).
- 표시: "128.4km × 200원 = 25,680원".
- **편도/왕복 (D-089, D-069 대체)**: 기본은 **편도**. 계산 순서는 **편도 거리 × km당 단가 = 편도 금액(원 단위 반올림)** → 경로 카드 계산식 바로 아래 **[왕복으로 계산 (× 2 = n원)]** 버튼을 직원이 직접 눌러야 **편도 금액 × 2**가 된다(누르면 [편도로 되돌리기]). `is_round_trip=true`면 `distance_km`(총 주행 거리, 표시용) = 편도 × 2. 직접 입력(`manual`)도 같은 버튼을 쓴다(입력값 = 편도 거리). 돌아오는 길이 다르면 [자차 이동 하나 더]로 귀가 구간을 따로 넣는다.
- 표시: 편도 "편도 377km × 200원 = 75,400원", 왕복 "편도 377km × 200원 = 75,400원 × 2(왕복) = 150,800원". 승인 화면·증빙 이미지에도 같은 문구.
- 증빙: 주유 영수증은 받지 않는다. 출발지·도착지·거리·출장 목적이 정산 근거이며 세무 마감 자료에 함께 나간다. 통행료·주차비는 별도 항목(영수증)으로 올린다.

### 4.3 Fallback
- 주소 검색·길찾기 실패 또는 키 미설정 시: "거리를 자동으로 계산하지 못했어요. 주행거리를 직접 입력해 주세요" 안내 + km 직접 입력 필드 → `distance_source='manual'`.
- 자동 계산 후 직원이 km 값을 고치면 `distance_source='manual'`로 바뀐다.
- 결재자·관리자 화면에서 `manual` 건은 "직접 입력 거리" 배지를 표시한다.
