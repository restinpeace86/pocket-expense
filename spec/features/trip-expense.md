# [Spec] 출장비 (출장 소명서 · 세부 유형 · 자차 거리/유류비)

관련: D-008, D-018, D-034, D-035, D-040, O-04 / 데이터: `expense_claims`의 출장 정보, `expense_items`의 trip 관련 컬럼 / 계산 규칙 원본: `spec/data/expense-lifecycle.md` §5.2, §5.3

## 1. 일반 경비와 출장비의 구분 (D-035)
- **출장 중에 쓴 비용은 종류와 상관없이 모두 출장비(`trip`)** 로 분류한다. 출장 중 식비, 교통비, 톨게이트비, 주차비, 숙박비, 자차 유류비가 모두 출장비의 세부 유형이다.
- **일반 식대(`meal`)** 는 출장이 아닌 평소 점심·야근 식대다.
- **출장 식비(`trip` / `meal`)** 도 1식 한도 × 인원수를 적용한다(D-040, `smart-meal.md`). 예: 부산국밥 17,000원, 한도 10,000원 → 절사 모드에서 10,000원 지급, 7,000원 개인 부담. 계정과목은 여비교통비.

| 상황 | 카테고리 | 세부 유형 |
|---|---|---|
| 평소 점심 식대 | 식대(`meal`) | — |
| 부산 출장 중 점심 | 출장비(`trip`) | 출장 식비(`meal`) |
| 출장 KTX | 출장비(`trip`) | 대중교통(`public_transport`) |
| 출장 고속도로 톨게이트 | 출장비(`trip`) | 통행료·주차(`toll_parking`) |

## 2. 출장 소명서 (헤더)
- 소명서 편집 화면 헤더의 **[출장 경비] 스위치**를 켜면 출장 소명서가 된다(`expense_claims.is_business_trip`).
- 출장 정보(켜면 필수): 출장지(`trip_destination`), 출장 기간(`trip_start_date` ~ `trip_end_date`), 출장 목적(`trip_purpose`).
- 출장 소명서에 추가되는 영수증 항목은 **카테고리 기본값이 출장비**가 되고, AI가 세부 유형을 추천한다(`receipt-parser.md` §3). 예: 식당 영수증 → 출장 식비, 하이패스·톨게이트 영수증 → 통행료·주차, KTX 승차권 → 대중교통, 호텔 → 숙박.
- 출장 소명서 안에서도 직원이 항목 카테고리를 바꿀 수 있다(예: 출장과 무관한 영수증이 섞인 경우 일반 식대로 변경).
- 출장 기간 밖의 결제일자를 가진 출장비 항목은 "출장 기간 밖" 노란 경고를 표시한다(상신은 가능).
- 제목 자동 제안(출장 소명서): "{시작일 M/D} {출장지} 출장" (예: "10/15 부산 출장").
- 출장 소명서가 아니어도 출장비 항목을 넣을 수 있다(예: 시내 외근 택시). 이때 출장 정보는 항목의 적요로 남긴다.

## 3. 세부 유형 (`trip_type`, 출장비 항목 필수)
| 값 | 표시명 | 영수증 | 금액 입력 | 추가 입력 |
|---|---|---|---|---|
| `meal` | 출장 식비 | 필수 | 영수증 파싱/직접 입력 | 인원수(필수, 기본 1), 1식 한도 적용 |
| `public_transport` | 대중교통(KTX·버스·항공 등) | 필수 | 영수증 파싱/직접 입력 | |
| `taxi` | 택시 | 필수 | 영수증 파싱/직접 입력 | |
| `toll_parking` | 통행료·주차 | 필수 | 영수증 파싱/직접 입력 | |
| `lodging` | 숙박 | 필수 | 영수증 파싱/직접 입력 | 숙박 기간(체크인~체크아웃) |
| `own_car` | 자차 유류비 | 선택 | 거리 × 단가 자동 계산 | 출발지·도착지·거리(§4) |
| `other` | 기타 | 필수 | 영수증 파싱/직접 입력 | 적요 필수 |

- 항목 공통 입력: 적요(`purpose`, 권장), 결제수단.
- 항목의 `trip_start_date`/`trip_end_date`는 숙박 기간에만 쓴다(숙박이면 필수). 출장 전체 기간은 소명서 헤더에 둔다.
- 자차 항목은 영수증 없이 [영수증 없이 항목 추가]로 만든다.

## 4. 자차 유류비 (`own_car`)
- 회사 설정이 자차 유류비 **사용 안 함**(`fuel_enabled=false`, D-068)이면 세부 유형 선택지에 `own_car`를 보여 주지 않고, 서버도 새 `own_car` 항목을 받지 않는다(이미 있는 항목은 그대로).
### 4.1 입력
- 출발지·도착지: 주소 검색(Kakao Local API, `KAKAO_REST_API_KEY` 서버 호출)으로 선택 → `start_location`/`end_location`, 좌표 저장. 출장 소명서면 도착지 기본값으로 출장지를 제안한다.
- [거리 계산] 버튼 → 서버에서 Kakao Mobility 길찾기 API 호출 → `distance_km`(소수 첫째 자리 반올림), `distance_source='api'`.
- 차량번호: 멤버 프로필 `vehicle_number`를 보여 주고, 없으면 "내 정보에서 차량번호를 등록하세요" 안내(상신은 막지 않음).
- `payment_method`는 개인카드로 고정한다(`expense-lifecycle.md` §5.5).
- `expense_date` 기본값은 출장 시작일(출장 소명서가 아니면 오늘). 직원이 바꿀 수 있다.

### 4.2 계산
- 청구 금액 = `distance_km × 회사 km당 단가`, 원 단위 반올림. 상신 시 `applied_fuel_rate_per_km` 스냅샷.
- 표시: "128.4km × 200원 = 25,680원".
- **편도/왕복 (D-069)**: 거리 계산 옆에 [왕복] 체크(기본값 체크). 체크하면 `is_round_trip=true`, `distance_km` = 길찾기 편도 거리 × 2. 풀면 편도 거리 그대로. 직접 입력(`manual`)일 때도 같은 체크를 쓴다(입력값 = 편도 거리).
- 표시: 왕복이면 "왕복 · 400km × 2 = 800km × 200원 = 160,000원", 승인 화면에도 같은 문구.
- 증빙: 주유 영수증은 받지 않는다. 출발지·도착지·거리·출장 목적이 정산 근거이며 세무 마감 자료에 함께 나간다. 통행료·주차비는 별도 항목(영수증)으로 올린다.

### 4.3 Fallback
- 주소 검색·길찾기 실패 또는 키 미설정 시: "거리를 자동으로 계산하지 못했어요. 주행거리를 직접 입력해 주세요" 안내 + km 직접 입력 필드 → `distance_source='manual'`.
- 자동 계산 후 직원이 km 값을 고치면 `distance_source='manual'`로 바뀐다.
- 결재자·관리자 화면에서 `manual` 건은 "직접 입력 거리" 배지를 표시한다.
