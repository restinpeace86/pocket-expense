# 사내 메신저 (D-203)

> 사용자 결정 2026-11-03: "회사 안 직원끼리", "최대한 카톡하고 비슷하게", 만들어서 확인한 뒤 기능 스위치로 숨긴다.
> 회사 ↔ 세무사무소 대화는 이 범위가 아니다(그쪽은 확인 요청 D-196 — 채팅 아님).

## 1. 범위
- **같은 회사의 승인된 멤버끼리만**. 다른 회사·세무사무소·대기/비활성 멤버와는 대화할 수 없다(DB에서 강제).
- 대화 형태
  - **1:1**: 같은 두 사람은 방 하나(다시 고르면 그 방). 첫 메시지 전에는 상대 목록에 보이지 않음.
  - **그룹**: 나 + 1명 이상, 이름은 선택(없으면 참여자 이름). 누구나 초대·이름 바꾸기·나가기.
  - **소명서 대화**: 소명서(결의서) 화면 [이 건으로 대화] → 소명서마다 방 하나. 처음엔 연 사람 + 작성자, 다른 사람은 초대. 그 소명서를 볼 수 있는 사람(본인·관리자·결재자)만 열 수 있다. 방 위에 소명서 띠(제목·금액·[소명서 보기]).
  - 1:1에서 [대화상대 초대] = 카톡처럼 새 그룹방.
- 1차 기능: 글, 사진(휴대폰 사진 회전 반영·카톡 일반 화질 수준 1280px JPEG + 말풍선용 480px 미리보기, D-204), 파일(20MB까지), 읽음(말풍선 옆 안 읽은 사람 수), 목록 안 읽은 수, 메뉴 배지, 웹푸시, 내 메시지 삭제("삭제된 메시지입니다."), 글 복사, 검색(목록 안 방 이름·참여자).
- 나중에: 입력 중 표시, 접속 중 표시, 메시지 수정, 1:1 목록에서 지우기.

## 2. 화면 (카톡처럼)
- 주소: `/workspace/{회사}/chat` (목록), `/workspace/{회사}/chat/{방}` (대화방). 직원·관리자 공통 화면.
- PC(md 이상): 왼쪽 목록 + 오른쪽 대화방. 휴대폰: 목록 ↔ 대화방 한 화면씩.
- 들어가는 곳: 직원 하단 메뉴 [채팅](배지), 관리자 왼쪽 메뉴 [채팅](홈 아래, 배지), 관리자 휴대폰 위 줄 채팅 아이콘(배지), 소명서 화면 [이 건으로 대화].
- 목록: 프로필(이름 첫 글자), 방 이름(그룹은 인원 수), 마지막 메시지, 시각(오늘 = 시각 / 어제 / 올해 = M월 D일 / 그 전 = YYYY. M. D.), 안 읽은 수. 알림이 꺼져 있으면 안내 줄 + [알림 켜기] — 다른 화면으로 가지 않고 그 자리에서 이 기기 알림을 켠다(아이폰 홈 화면 추가 전·알림 차단이면 방법 안내, [×]로 닫기).
- 직원 하단 메뉴(홈·정산·결재함·채팅·내 정보)는 채팅 목록에서도 그대로 보인다. 휴대폰은 대화방에 들어가면 숨김(입력칸 자리), PC는 계속.
- 대화방: 하늘색 배경, 날짜 구분선, 내 말풍선 오른쪽 노랑·상대 왼쪽 흰색 + 이름·프로필, 같은 사람·같은 분이면 이름은 첫 줄·시각은 마지막 줄, 초대·나가기 안내 줄. 위로 올리면 이전 대화 50개씩. 아래를 안 보고 있을 때 새 메시지 → [새 메시지 N].
- 입력: PC Enter = 보내기, Shift+Enter = 줄바꿈, 한글 조합 중에는 보내지 않음. 휴대폰 Enter = 줄바꿈. 사진·파일 버튼. 4,000자까지.
- 메시지 메뉴: 길게 누르기(휴대폰)·오른쪽 클릭(PC) → 복사(글) / 삭제(내 메시지).
- 보내는 중 표시, 실패하면 [다시 보내기]·[삭제].
- 방 메뉴(☰): 대화상대 목록, 초대, 이름 바꾸기(그룹), 나가기(그룹·소명서 방, 1:1은 나가기 없음).

## 3. 데이터 (migration 106·107)
- `company_features(company_id, feature, enabled)` — 회사별 기능 스위치(`messenger`, 근태 `attendance` 자리). **기본 꺼짐, 화면 버튼 없음** — 운영자만 DB(service role)에서 켠다.
- `chat_rooms(kind direct|group|claim, title, direct_key, claim_id, last_message_at)`, `chat_members(last_read_at, joined_at, left_at)`, `chat_messages(kind text|image|file|system, body, attachment_*, deleted_at, pushed_at)`. 모두 company_id + 복합 FK로 회사 섞임 방지, 회사 삭제 시 연쇄 삭제, 소명서 삭제 시 그 방 삭제.
- 쓰기는 모두 security definer 함수(스위치·회사·참여자 확인): `chat_open_direct`, `chat_create_group`, `chat_open_claim`, `chat_invite`, `chat_leave`, `chat_rename`, `chat_send`(화면이 만든 id로 한 번만 저장), `chat_delete_message`, `chat_mark_read`, `chat_claim_push`. 읽기: `chat_room_list`, `chat_room_detail`, `chat_messages_page`(이전/이후 50개), `chat_unread_total`(꺼짐 = null), `chat_member_directory`, `my_feature_enabled`.
- 표 직접 쓰기 권한 없음. 읽기 RLS = 같은 회사 + 지금 참여 중 + 스위치 켜짐.
- 초대받은 그룹 참여자는 들어온 뒤 메시지만 본다. 1:1·소명서 방은 처음부터.
- 첨부: 비공개 버킷 `chat-files/{회사}/{방}/{메시지 id}.{확장자}`(20MB) — 그 방 참여자만 올리고 읽음(서명 주소 1시간), 지우기는 올린 사람만.

## 4. 실시간·알림
- 메시지 저장 → DB 트리거가 방 참여자 각자의 비공개 주제 `chat:{member_id}`로 보냄(Supabase Realtime Broadcast). 읽음·방 변경도 같은 주제. `realtime.messages` 읽기 정책 = 내 주제 + 스위치 켜짐.
- 브라우저는 Supabase에 직접 연결(Vercel을 거치지 않음). 메뉴 배지·목록·대화방이 연결 하나를 나눠 씀.
- 다시 연결되거나 화면이 다시 보이면 마지막 메시지 이후를 다시 불러와 빈틈을 메운다.
- 웹푸시: 메시지를 보낸 뒤 서버 동작이 받는 사람(보낸 사람·나간 사람 제외)에게 보냄. 같은 메시지는 한 번만(`pushed_at`). 1:1 = 제목 보낸 사람·내용, 그룹·소명서 = 제목 방 이름·"이름: 내용", 사진·파일은 "사진을 보냈어요."/"파일을 보냈어요.". 그 대화방을 보고 있으면 알림을 띄우지 않음(서비스 워커). 아이폰은 홈 화면에 추가한 경우만.
- Realtime 메시지 표는 날짜별로 Supabase가 만든다(실시간 연결이 있으면 자동). 연결이 하나도 없던 날 보낸 실시간 알림은 빠질 수 있으나, 화면은 열 때·다시 연결될 때 다시 불러오므로 메시지는 빠지지 않는다.

## 5. 권한·개인정보
- 관리자도 자기가 참여한 방만 본다(직원 대화 열람 없음).
- 보존: 회사가 쓰는 동안 보관, 회사 계정 해지 시 다른 자료와 같이 30일 뒤 삭제(약관 제17조). 퇴사(비활성) 멤버 메시지는 남기고 이름 뒤 "(퇴사)".
- 정식 공개 전에 약관·개인정보 처리방침에 메신저(대화 내용·첨부 보관) 항목 추가 필요.

## 6. 스위치
- 켜기/끄기: `company_features`에 (회사, 'messenger', true/false). 꺼지면 메뉴·배지 사라짐, 주소는 "찾는 화면이 없어요", DB 함수는 `FEATURE_DISABLED`, 표 읽기·실시간 수신도 막힘(데이터는 남음).
- **D-206(2026-11-04)부터 모든 회사 기본 켜짐** — 줄이 없으면 켜짐, (회사, 'messenger', false) 줄이 있으면 꺼짐(운영자만).

## 7. 첨부 보관·저장 한도·트래픽 (D-204, migration 108)
- **사진 화질**: 원본 긴 변 1280px JPEG(품질 0.8), 미리보기 긴 변 480px WebP(안 되는 브라우저는 JPEG). 영수증 사진(2000px)과는 따로.
- **트래픽 줄이기**: 말풍선은 미리보기만 받고 원본은 [사진 크게 보기]에서만. 서명 주소(1시간)는 50분까지 같은 주소를 다시 써서(이 탭 안, 새로고침 포함) 브라우저 저장본을 쓰게 하고, 파일은 이름이 메시지마다 달라 바뀌지 않으므로 브라우저 저장 1년(cacheControl). 파일(사진 아닌 것)은 누를 때만 받음.
- **보관 기간 90일**(`private.app_settings.chat_attachment_days`): 보낸 지 90일이 지나면 새벽 작업(`/api/cron/nightly`)이 원본·미리보기를 지우고 `attachment_purged_at` 표시 → 말풍선 "보관 기간이 지난 사진이에요."/"…파일이에요."(파일 이름은 남김). 글 메시지는 그대로.
- 같은 새벽 작업이 삭제한 메시지에 남은 파일, 올렸지만 메시지가 되지 않은 파일(하루 지난 것)도 지운다.
- **회사별 저장 한도**(지우지 않았고 90일 안의 원본 + 미리보기 합): 요금제별 `billing_plans.chat_storage_mb` — 스타터 1GB / 프로 3GB / 비즈니스 10GB. 무료 이용 = 스타터. 결제 연동 전이라 회사에 요금제가 없어 지금은 모든 회사 스타터(`private.chat_storage_limit`, 결제 연동 때 회사 요금제를 읽게 바꾼다). 크기는 저장소에 실제로 올라간 크기로 센다.
- 한도를 넘으면 보내기가 막히고(`STORAGE_FULL`, 올린 파일은 지움) 대화방에 "회사 채팅 저장 공간(1GB)이 다 찼어요. 사진·파일은 90일이 지나면 자동으로 지워져 다시 보낼 수 있어요." 글은 계속 보낼 수 있다.
- 읽기: `chat_storage_status()` = 사용량·한도·보관 일수. 정리 함수 `chat_files_due`·`chat_files_mark_purged`는 서버(service role) 전용.

## 8. [알림]방 (D-206, migration 109)
- 사람마다 하나인 시스템 방(`chat_rooms.kind = 'notice'`, `notice_member_id`). 처음 알림이 올 때 생긴다. 지금은 회의 10분 전 안내(`spec/features/calendar.md` §2-3)만.
- 글 종류 `notice`(보낸 사람 없음, `link` = [캘린더에서 보기]) — 안 읽은 수·배지에 들어간다. 알림방에는 notice 글만, 다른 방에는 notice 글 불가(트리거). 보내기·초대·나가기 불가(`NOTICE_ROOM`), 화면은 입력창 대신 안내 한 줄, 방 메뉴·인원 수 없음.
- 웹푸시: pg_net → `/api/cron/reminder-push` → `chat_notice_push_due()`(서버 전용, 한 번만).

## 9. 관리자 화면에서 들어가는 곳 (D-208)
- 관리자 왼쪽 메뉴에는 [채팅]을 두지 않는다 — 채팅은 관리자 틀 밖 전체 화면(← 뒤로)이라 다른 메뉴 항목과 동작이 달라서. **머리글 오른쪽 말풍선 아이콘**(PC·휴대폰 같음, 안 읽은 수 배지)으로 들어간다.
- 직원(·관리자 직원 모드)은 하단 메뉴 [채팅] 그대로. 하단 메뉴는 워크스페이스 공통 레이아웃 하나(D-207).
