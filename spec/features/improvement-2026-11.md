## A. 서브 대화 (스레드 · 이슈 카드)

### A-1. 무엇인가
- 단체방·결의서 방에서 메시지 하나를 골라 **그 건만 따로 이야기하는 작은 대화**를 연다. 메인 대화가 엉키지 않게 한다.
- 메인 대화에는 긴 글 대신 **카드 한 장**만 남는다: 시각 · 제목 · 참여자 요약(얼굴 3개 + 외 n명) · 글 수 · 상태(진행 중 / 종결) · 종결 요약 한 줄.
- **종결은 선택**이다(사용자 2026-11-10, 슬랙처럼 종결 없이 계속 써도 됨). 건이 끝나면 [종결하기] → 한 줄 요약이 붙고 '종결' 탭으로 간다. 종결된 동안은 입력이 잠기고(기록으로 보기), **[다시 열기]** 하면 '진행 중'으로 돌아와 이어서 쓴다(요약은 남겨 두고, 다시 종결할 때 새로 만든다).

### A-2. 어디서 쓰나 (추천안 — 시안에서 확인)
- 대상 방: **대화하는 방 전부 — 1:1방 · 단체방 · 결의서 방**(사용자 2026-11-10). [알림]방·도우미 방은 사람끼리 대화하는 방이 아니라서 없음.
- 서브 대화는 채팅 목록에 따로 나오는 방이 아니라 **메인 대화방에 속한 작은 대화방**이다(생김새는 일반 대화방과 같음).
- 알림 = 그 서브 대화 참여자만, 서브 대화 글은 메인 안 읽은 수에 넣지 않고 카드에 '새 글 n'(사용자 2026-11-10 확정).
- 만들기: 메시지 메뉴(길게 누르기 / 오른쪽 클릭) → **[서브 대화 만들기]**. 메시지 하나에 서브 대화는 하나뿐이다. 이미 있으면 메뉴가 [서브 대화 보기]로 바뀐다.
- 누가 보고 쓰나: 그 방 참여자 모두. 방에 나중에 들어온 사람은 들어온 뒤 만들어진 서브 대화만 본다(메인과 같은 규칙).
- 누가 종결·다시 열기 하나: **만든 사람 + 회사 관리자**.
- 화면에 열리는 서브 대화는 **한 번에 하나**(휴대폰 시트·PC 서랍 모두). 다른 서브 대화를 누르면 보던 것은 닫히고 그것이 열린다. 한 방에 주제별 서브 대화는 여러 개 있을 수 있다(사용자 2026-11-10).
- 첨부: 글·사진·파일 모두 가능(메인과 같은 20MB, 같은 보관 기간·영구 보관).

### A-3. 제목 (AI 제안 → 사람 확정)
- [서브 대화 만들기]를 누르면 시트가 열린다. 원래 메시지와 그 앞 글 몇 개로 Gemini가 **제목 후보 하나**(20자 안쪽)를 채워 둔다.
- 만드는 사람은 그대로 두거나 고칠 수 있다. 제목은 비워 둘 수 없다.
- AI가 실패하거나 느리면(3초 넘음) 원래 메시지 첫 줄을 제목 칸에 넣는다.
- 종결할 때 AI가 서브 대화 전체로 **한 줄 요약**(40자 안쪽)을 만든다. 종결하는 사람이 고칠 수 있고, 비우면 요약 없이 종결한다.
- AI 호출은 만들 때 1번, 종결할 때 1번이다. 결의서 크레딧은 쓰지 않는다(채팅 기능에 포함).

### A-4. 휴대폰 (단일 화면)
- 메인 대화는 지금처럼 한 줄로 흐른다.
- 카드나 [서브 대화 보기]를 누르면 **아래에서 올라오는 전체 화면 시트**가 열린다. 주소는 바뀌지 않는다(뒤로 가기 = 시트 닫기).
  - 위: [<] 뒤로 · 제목 · 상태 · (권한이 있으면) [종결하기]
  - 맨 위: 원래 메시지(회색 상자)
  - 그 아래: 서브 대화 글들, 그리고 입력칸. 종결된 동안에는 입력칸 자리에 "종결된 대화예요" + 요약 + (권한이 있으면) [다시 열기]가 보인다.
- 방 위 메뉴(☰)에 **[서브 대화 목록]** 이 생긴다. 시트로 열리고 진행 중 / 종결 탭이 있다. 하나를 누르면 그 서브 대화가 열리고, 닫으면 목록으로 돌아온다.

### A-5. PC (md 이상 · 멀티 화면)
- 서브 대화를 열면 대화방 오른쪽에 **서랍 패널**(폭 380px)이 열린다. 메인은 왼쪽에 그대로 있고, **양쪽 모두 실시간**이다.
- 메인의 카드나 다른 서브 대화를 누르면 페이지 이동 없이 패널 내용만 바뀐다. [×]를 누르면 패널이 닫힌다.
- 방 머리글에 [서브 대화] 버튼이 있다(진행 중인 개수 배지). 누르면 오른쪽 **서랍**에 이 방의 서브 대화 목록이 뜬다: 검색(제목·요약), 진행 중 / 종결 탭, 줄마다 제목·누구 메시지에서·인원·글 수·시각·새 글·(종결) 요약. 하나를 누르면 서랍 안에서 그 대화가 열리고 [< 목록]으로 돌아온다. **서랍에 열리는 서브 대화는 한 번에 하나**(사용자 2026-11-10). 방에는 주제별로 서브 대화가 여러 개 있을 수 있다(정할 것).
- 화면 폭이 좁아서(채팅 목록 + 메인 + 패널이 다 들어가지 않을 때, 1180px 미만) 패널을 열면 **왼쪽 채팅 목록을 접는다**. 패널을 닫으면 목록이 다시 펴진다.
- PC 새 창(420px)에서는 폭이 좁으므로 휴대폰처럼 시트로 연다.

### A-6. 읽음 · 알림
- 서브 대화 글은 **메인의 안 읽은 수에 넣지 않는다.** 카드에 "새 글 n" 점이 붙는다.
- 웹푸시는 **그 서브 대화 참여자**에게만 보낸다: 만든 사람 + 원래 메시지를 쓴 사람 + 한 번이라도 글을 쓴 사람(보낸 사람 제외). 제목 = "방 이름 › 서브 대화 제목".
- 종결·다시 열기는 참여자에게 푸시를 보내지 않고, 메인 카드만 '종결 + 요약' / '진행 중'으로 바뀐다.

### A-7. 데이터 (안)
- `chat_threads(id, company_id, room_id, root_message_id unique, title, status open|closed, summary, created_by, closed_by, closed_at, last_message_at, message_count)`
- `chat_messages.thread_id`(null = 메인). 같은 방·같은 회사 복합 FK.
- `chat_thread_reads(thread_id, member_id, last_read_at)` — "새 글" 점에 쓴다.
- 함수: `chat_thread_open(p_root, p_title)`, `chat_thread_close(p_thread, p_summary)`, `chat_thread_reopen(p_thread)`(안내 줄 "○○님이 다시 열었어요"), `chat_send`에 `p_thread` 추가(종결된 서브 대화면 `THREAD_CLOSED`), `chat_thread_list(p_room)`, `chat_thread_messages(p_thread, ...)`, `chat_thread_mark_read`.
- 메인 타임라인에서는 원래 메시지 바로 아래에 카드가 보인다(카드는 서브 대화가 아니라 원래 메시지에 붙음 — 새 메시지 줄을 만들지 않음).
- 실시간: 지금 주제 `chat:{member_id}`에 `thread`(만들기·종결·글 수) 이벤트를 추가하고, `message`에 `thread_id`를 싣는다.

### A-8. 엣지 케이스
- **원래 메시지 삭제**: 서브 대화는 남고, 원래 글 자리에 "삭제된 메시지입니다."가 보인다.
- **두 사람이 동시에 만들기**: `root_message_id unique` 때문에 나중 사람은 이미 만들어진 서브 대화로 들어간다.
- **종결 직후 보낸 글**: `THREAD_CLOSED`. 보내는 중이던 글은 "종결된 대화라 보내지 못했어요"로 표시하고, [복사]만 남긴다.
- **방에서 나간 사람**: 서브 대화도 못 본다(메인과 같다).
- **PC ↔ 휴대폰 폭 전환**(창 크기 바꾸기): 열려 있던 서브 대화는 그대로 유지하고, 패널 ↔ 시트로만 바뀐다(상태 하나 `openThreadId`).
- **다시 연결**: 메인처럼 `reconnect`로 빠진 글을 다시 불러온다(열린 서브 대화 포함).
- **스위치 꺼짐**: 메신저가 꺼지면 서브 대화도 같이 막힌다.

## B. 무소음 시각 알림 (PC)

### B-1. 언제 뜨나
- **PC(md 이상)** 에서 앱 화면이 보이고 있을 때 새 채팅 메시지(메인·내가 참여한 서브 대화)가 오면 뜬다.
- 뜨지 않는 경우:
  - 그 대화방을 보고 있을 때(서브 대화는 그 패널이 열려 있을 때)
  - 내가 보낸 메시지
  - 창이 가려져 있거나 최소화돼 있을 때(그때는 웹푸시가 맡는다)
  - [내 정보]에서 끈 경우
- 휴대폰에는 띄우지 않는다(웹푸시가 있음).

### B-2. 오른쪽 아래 토스트
- 작은 카드로 3초 동안 부드럽게 올라왔다가 사라진다. 마우스를 올려 두면 사라지지 않는다.
- 내용: 프로필 · **보낸 사람** · 방 이름(서브 대화면 "방 › 서브 대화 제목") · 내용 한 줄(사진·파일은 "사진을 보냈어요.").
- 누르면 그 대화방(서브 대화면 그 패널)으로 간다. [×]로 바로 닫을 수 있다.
- 여러 개가 오면 최대 3장까지 쌓이고, 같은 방은 한 장으로 합친다("+2").
- 카카오톡 문의 버튼(D-127)이나 결재 고정 버튼 줄이 있으면 그 위에 뜬다.
- 화면 읽기 프로그램에는 `role="status"`(조용히 읽음)로 알린다.

### B-3. 가장자리 빛
- 토스트와 함께 화면 가장자리 안쪽에서 **은은한 파란빛**(투명 파랑, 안쪽으로 번짐)이 짧게 반짝(0.5초: 0.25초 켜짐 + 0.25초 꺼짐)하고, 이걸 **2번** 한다(모두 약 1초, 사용자 2026-11-10 "짧게 2번").
- 화면 위에만 덮이고 클릭은 막지 않는다(`pointer-events: none`).
- 운영체제의 **움직임 줄이기** 설정을 켠 사람에게는 빛을 보여 주지 않는다(토스트만).
- 1.5초 안에 다시 오면 빛은 다시 켜지 않는다(깜빡임 방지).

### B-4. 설정
- [내 정보] › **[PC 화면 알림]**: 켜짐(기본) / 꺼짐. 계정에 저장한다(`members.chat_visual_alert`, 기본 true).
- 관리자는 채팅 목록 위 설정에서 같은 스위치를 쓴다.

## C. 의견 보내기 (버그 신고 · 기능 요청)

### C-1. 들어가는 곳
- 워크스페이스 공통 머리글(직원·관리자 모두) 오른쪽에 **[의견 보내기]** 아이콘(말풍선)을 둔다. 휴대폰도 같은 자리에 둔다.
- 관리자 카카오톡 문의 버튼(D-127)은 그대로 두고 따로 운영한다(카카오톡 채널이 열리면 둘 다 보인다).

### C-2. 작성 창
- 구분(꼭 고름, 처음엔 아무것도 선택 안 됨): **[🐛 버그 신고]** / **[💡 기능 요청]**
- 내용: 여러 줄 입력칸. placeholder "불편하신 점이나 제안할 아이디어를 편하게 남겨주세요." 10자 이상, 2,000자까지.
- 아래 작은 글씨로 "보내면 지금 보고 있는 화면 주소와 브라우저 정보가 함께 전달돼요."를 보여 준다(몰래 모으지 않고 알림).
- 함께 보내는 것(자동): 화면 주소(경로만, 주소 뒤 `?` 이후는 뺌), 브라우저·기기 요약(User-Agent), 화면 크기, 앱 버전(배포 커밋 앞 7자리), 보낸 시각, 회사·멤버(서버가 로그인에서 채움 — 화면에서 보낸 값은 믿지 않음).
- [보내기]. 보내는 중에는 버튼이 막히고, 실패하면 입력한 내용을 그대로 두고 "보내지 못했어요. 다시 눌러 주세요."를 보여 준다.

### C-3. 보낸 뒤 안내 (구분마다 다름)
- **버그 신고**:
  > 소중한 제보 감사합니다!
  > 확인 후 가장 빠르게 수정할게요. 제보해 주신 내용은 **24시간 안에 확인**해요.
- **기능 요청**:
  > 소중한 아이디어 감사드립니다! 💡
  >
  > 보내주신 기능은 추후 업데이트에 **적극적으로 반영**하도록 하겠습니다.
  >
  > 다만, 해당 기능이 저희 서비스의 전체 뼈대와 실무 프로세스에 부합하는지 면밀히 검토하는 과정이 필요하여, 검토를 거쳐 우리 서비스에 가장 적합한 형태로 다듬어 선보이는 데 다소 시간이 소요될 수 있는 점 너른 양해 부탁드립니다.
  >
  > 앞으로도 직원 여러분의 업무를 더 편안하게 만들어 드릴 수 있도록 꾸준히 발전하는 WORKON이 되겠습니다. 고맙습니다!
- 안내는 작성 창 자리에 바로 보여 주고 [확인]으로 닫는다.

### C-4. 데이터 · 운영자
- `feedback_logs(id, company_id, member_id, category bug|feature, content, page_url, user_agent, viewport, app_version, status pending|reviewing|resolved, operator_note, created_at, updated_at)`
- 회사 데이터 섞임 방지: 복합 FK(company_id, member_id), RLS 강제. 회사 사용자는 **쓰기(함수)만**, 읽기는 운영자(service role)만. 회사 관리자는 직원 의견을 보지 않는다.
- 쓰기 함수 `feedback_submit(p_category, p_content, p_page_url, p_user_agent, p_viewport, p_app_version)`: 길이 검사, **한 사람 하루 10건**까지(넘으면 `TOO_MANY`).
- 저장되면 운영자 디스코드(`DISCORD_WEBHOOK_URL`)로 "🐛/💡 [회사명] 첫 줄…" 알림을 보낸다. 알림이 실패해도 저장은 된다.
- 운영자 화면 `/app-admin/feedback`: 목록(구분·상태 필터), 상세(내용·주소·기기), 상태 바꾸기(접수 → 검토 중 → 해결), 메모.
- 개인정보: 내용에 개인정보를 넣지 말라는 안내를 작성 창에 한 줄 둔다. 개인정보처리방침(8-93)에 "의견 보내기: 내용·화면 주소·브라우저 정보, 해결 후 1년 보관" 항목을 추가한다.

### C-5. 엣지 케이스
- 로그인이 풀린 상태에서 보내기 → 로그인 화면으로(작성 내용은 그 화면에 임시 저장해 두고 돌아오면 다시 채움).
- 아주 긴 주소·User-Agent → 서버에서 잘라 저장한다(주소 500자, UA 300자).
- 대기·비활성 멤버는 머리글이 없으므로 보낼 수 없다.
- 미리보기(dev preview)·관리자 '직원 화면 보기'에서도 같은 버튼이 보이고, 보내는 사람은 실제 로그인한 사람이다.
