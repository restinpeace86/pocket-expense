## 0. 공통
- **회사별 기능 스위치** `attendance`(캘린더와 같은 `company_features`). 회사 관리자가 근태 설정에서 직접 켠다. 기본 꺼짐.
  - 꺼져 있으면: 직원 홈의 근태·휴가 칸, 하단 가운데 [QR 출퇴근], 근태 주소 모두 숨김(직접 접근 404). 출근 단말 화면은 "근태가 꺼져 있어요" 안내.
- **시간은 항상 서버 시간(한국 시간)**. 휴대폰·단말 시계는 쓰지 않는다.
- **테넌트 격리**: 모든 테이블 company_id + RLS 강제. 단말·QR 토큰의 회사와 찍은 사람의 소속 회사가 같아야 한다.
- **출퇴근 기록은 서버 라우트에서만**(서비스 키) 남긴다. 직원 권한으로 기록 테이블·적재 함수에 직접 쓰지 못한다.
- 관리자도 [직원 모드]에서 같은 방법으로 출퇴근을 남긴다.
- 하지 않는 것: 지각·조퇴 집계, 연장·심야·휴일 수당 계산, 급여 연동, GPS·IP 확인, **자정 넘은 퇴근**.

- 시간차 허용 여부는 여기 두지 않고 [직원별 연차 일수] 화면에 둔다.
- **사용 안내(사용자 결정 2026-11-08)**: 근태 설정 위에 [근태는 이렇게 동작해요] 접힌 안내(기본 접힘, 펼치면 단계 설명 + **예시 화면 이미지**: 출근 단말 화면 · 직원 QR 찍기 · 출근/퇴근 결과 · 직원 홈). 이미지는 승인된 시안 캔버스에서 만든 그림(서비스 로고·이름 없음, 회사명은 "예시 회사")을 정적 파일로 넣는다. 서비스 이름이 확정돼도 그림을 다시 만들 필요가 없게 로고·서비스 이름을 넣지 않는다.
- 설정을 바꾸면 **그 뒤 기록부터** 적용(이미 남은 기록·자동 퇴근은 바꾸지 않는다).
- **설정 변경 이력(사용자 결정 2026-11-08)**: 저장할 때마다 이력 1행 — 바꾼 사람·바꾼 시각(서버)·바뀐 항목마다 이전 값→새 값. 지우거나 고칠 수 없다(관리자도). 근태 설정 아래 [변경 이력]에서 최신순으로 본다. 근태 켜기/끄기, 출근 단말 등록·이름 변경·해제도 이력에 남긴다. 데이터: `attendance_settings_history`(id, company_id, changed_by_member_id, changed_at, changes jsonb `{항목: [이전, 새]}`) — 쓰기는 서버 함수만, 읽기는 관리자.
- 데이터: `attendance_settings`(company_id PK, work_start, work_end, daily_hours, work_days, missing_alert_minutes, leave_year_basis, under_five, updated_by, updated_at). 관리자만 쓰기, 회사 멤버 읽기.

## 2. 회사 QR (출근 단말)
### 2-1. 단말 등록·관리 (관리자 → 근태 설정 아래 [출근 단말])
- **연결 코드 방식(사용자 결정 2026-11-08)**: 공용 기기에 관리자 로그인을 남기지 않는다. 관리자가 자기 PC·휴대폰에서 [출근 단말 추가] → 이름(예: "1층 입구", 30자) → **6자리 연결 코드**(10분, 한 번만, 새 코드를 받으면 앞 코드 무효)를 받는다 → 회사 기기 브라우저에서 `/attend/terminal`을 열고 코드 입력 → 그 기기 브라우저에만 **단말 열쇠** 저장(서버에는 해시만). 연결되면 관리자 화면 목록에 바로 나타난다.
- 코드 맞히기 방지: 같은 IP에서 10분에 10번 틀리면 잠시 막는다. MAC 주소 등 기기 고유값은 웹에서 읽을 수 없어 쓰지 않는다.
- 단말 목록: 이름 · 등록자 · 등록일 · 마지막 사용 · [이름 바꾸기] · [해제]. 여러 대 가능(회사당 20대까지).
- **해제하면 즉시** 그 단말의 QR이 무효, 그 기기 화면은 "등록이 해제됐어요".
- 단말 열쇠가 지워진 기기(브라우저 데이터 삭제)는 다시 등록해야 한다.
- 데이터: `attendance_terminals`(id, company_id, name, key_hash, created_by_member_id, created_at, last_used_at, revoked_at).

### 2-2. 출근 화면 (`/attend/terminal` — 로그인 없이 단말 열쇠로만 동작)
- 표시: 큰 QR · 현재 시각(서버 기준) · 회사 이름 · 단말 이름 · "휴대폰 카메라나 WORKON 앱 [QR 출퇴근]으로 찍으세요".
- **QR 띄우는 시간 = 06:00~24:00**(사용자 결정 2026-11-08). 00:00~06:00에는 QR 대신 "출퇴근 가능 시간: 06:00~24:00"만 보이고 서버도 토큰을 주지 않는다. 06:00 전에 시작하는 새벽 근무는 **지원하지 않는다**(설명글에 표시).
- **QR이 뜨는 과정**: ① 단말이 30초마다(매분 00·30초) 단말 열쇠로 서버에 요청 ② 서버가 해제 여부·근태 켜짐·운영 시간 확인 ③ 회사·단말·30초 칸 번호에 서명한 토큰 발급 ④ 단말이 `…/attend/scan?t=토큰`을 QR로 그림 + 다음 QR까지 남은 시간 막대 ⑤ 연결이 끊기면 QR을 숨기고 "연결 끊김 · 다시 연결 중"(예전 QR을 계속 보여 주지 않음).
- **동적 QR**: 30초마다 바뀐다. 직전 칸까지만 유효(최대 약 60초). 내용 = 회사·단말·시간 칸에 서버 비밀키 서명(HMAC). DB에 저장하지 않는다.
- 상시 켜 둠: 화면 꺼짐 방지(Wake Lock), 끊기면 자동 재연결, 재부팅 뒤 브라우저만 열면 바로 이 화면(로그인·조작 없음).
- 찍힌 피드백: 누가 찍으면 2~3초 "김OO 출근 08:57 ✔" / "김OO 퇴근 18:12 ✔". 화면 중앙 QR은 가리지 않는다.
- QR 발급 API는 요청 횟수 제한. 서버 비밀키는 환경변수(서버 전용).

## 3. QR 출퇴근 (직원)
### 3-1. 찍는 방법
- **앱 하단 가운데 [QR 출퇴근]**: 근태가 켜진 회사에서는 [+ 결의서 쓰기] 자리를 대신한다(결의서 쓰기는 홈 [지출결의] 칸·목록 화면에서). 누르면 앱 안 카메라 스캐너.
- **휴대폰 기본 카메라**: QR 링크(`/attend/scan?t=…`)가 열리며 바로 기록. 로그인이 풀려 있으면 로그인 후 이어서 기록(토큰이 만료됐으면 다시 찍기 안내).

### 3-2. 출근·퇴근 판단 (근무일 = 찍은 날짜, 한국 시간)
1. 그날 출근 기록이 없으면 → **출근**.
2. 출근이 있으면 → "퇴근할까요?" 확인 → [퇴근] 누르면 **퇴근**. [취소]면 아무것도 남기지 않는다.
3. 퇴근 뒤 다시 찍으면 → **아무것도 남기지 않고** "오늘은 이미 퇴근했어요 (17:02)" + [정정 신청] 안내. **하루 출근 1번·퇴근 1번만**(사용자 결정 2026-11-08 A). 실수로 일찍 찍었거나 퇴근 뒤 돌발 업무로 더 일한 경우는 정정 신청 → 관리자 승인으로 고친다.
- 같은 사람이 1분 안에 같은 동작을 반복하면 처음 것만 남긴다.
- **자정 넘은 퇴근 없음**: QR은 06:00~24:00에만 뜨므로 00:00~06:00에는 찍을 수 없다. 06:00부터는 그날 출근부터. 전날은 §3-4 자동 퇴근.

### 3-3. 결과 화면
- 출근: "출근 08:57 ✔" + [홈으로].
- 퇴근: "퇴근 18:12 ✔ · 오늘 9시간 15분"(찍힌 시각 사이 머문 시간만, 휴게 차감 없음) + [홈으로].
- **휴일**(근무 요일 아님·공휴일): 결과에 "휴일" 표시. 퇴근 결과 화면에 [휴일 근무 상신] 버튼(월 근태 현황에서도 상신 가능 — 다음 Spec). 관리자 승인 전에는 근무일로 세지 않는다.
- 홈 "오늘 · 내 현황" 카드 맨 위 한 줄: "출근 08:57 · 퇴근 전" / "출근 08:57 · 퇴근 18:12".

### 3-4. 퇴근 누락
- **알림**(D-238 문구): 정규 퇴근 + 설정 시간이 지나도 퇴근이 없으면 본인 채팅 **[알림]방**과 휴대폰 알림으로 보낸다. 하루 한 번. 휴일·휴가일은 보내지 않는다.
  - 제목: "퇴근을 아직 안 찍었어요"(휴대폰 알림 ⏰)
  - **자동 기록 안내(반드시, 휴대폰 알림 본문 맨 앞)**: "자정까지 안 찍으면 정규 퇴근 시각(18:00)으로 자동 기록돼요."
  - "더 일하고 있다면 자정 전에 회사 QR로 퇴근을 찍어 주세요." · "출근: 08:57" · 버튼 [내 근태 보기](→ 월 근태 현황)
  - 기존 예약 작업(pg_cron 10분마다)·[알림]방·웹푸시 구조를 재사용한다.
- **자동 퇴근**: 자정이 지나도 퇴근이 없으면 그 날 퇴근 = **정규 퇴근 시각**, 방법 = `auto`("자동" 표시). 출근이 정규 퇴근보다 늦으면 자동 퇴근 = 출근 시각(0분). 휴일 출근에도 같은 규칙.
- 고치려면 직원 정정 신청 → 관리자 승인(다음 Spec). 원본 보존.

### 3-5. 실패
| 경우 | 안내 |
|---|---|
| QR 만료(60초 넘음) | "QR이 바뀌었어요. 다시 찍어 주세요" |
| 다른 회사 QR / 해제된 단말 | "이 QR로는 출퇴근을 남길 수 없어요" |
| 근태 꺼진 회사 | "회사에서 근태를 쓰지 않아요" |
| 비활성(퇴사) 멤버 | 기록하지 않음 |
- 실패는 시간·실패 코드·단말·기기 정보로 자동 기록(90일 보관). 화면 캡처는 자동으로 하지 않는다.

### 3-6. 데이터
- `attendance_logs`(id, company_id, member_id, work_date, kind in/out, at(서버 시각), terminal_id, method qr/auto/correction, replaced_by, created_at) — 직원 권한 쓰기 불가. 본인·관리자 읽기.
- `attendance_attempts`(실패, company_id, member_id?, terminal_id?, code, ua, at) — 90일 뒤 삭제.

## 5. 월 근태 현황 (직원 [근태]) — 승인(2026-11-08, D-237)
> 결정 출처 attendance-draft §7-1("[근태] 메뉴 = 월별 근태 내역, 날짜를 누르면 그날 상세 + [정정 신청]"). 사용자 "월 근태 현황 먼저 해" → 시안 확인 "일단 이렇게 진행해"(2026-11-08). migration 125.
- **들어가기**: 근태 켠 회사의 직원 홈 메뉴 칸 [근태](아이콘+이름, 배지 없음) → `/employee/attendance?month=YYYY-MM`(기본 이번 달). 관리자도 [직원 모드]에서 본인 것. 근태 꺼진 회사는 칸 없음·주소 404.
- **맨 위**: ← 홈 · 제목 "근태" · 월 이동(‹ 2026년 11월 ›, 다음 달은 이번 달까지만).
- **요약 카드**(그 달, 오늘까지): 출근한 날 n일(그중 휴일 m일) · 머문 시간 합계 · 자동 퇴근 n번 · 기록 없는 근무일 n일. 휴가 일수는 휴가 기능(⑦) 때 추가.
- **날짜 목록**(최근 날짜가 위, 미래 날짜 없음):
  - 보이는 날 = 기록이 있는 날 + 기록 없는 **근무일**(근무 요일이고 공휴일 아님). 기록 없는 휴일은 목록에 넣지 않는다(짧게).
  - "기록 없음"은 **근태를 켠 날과 본인 가입 승인일 중 늦은 날부터**만 센다(켜기 전 날짜를 빈칸으로 채우지 않음). 오늘은 기록이 없으면 "출근 전".
  - 한 줄: `11/19 (수)` · `08:57 – 18:12` · `9시간 15분` + 표시: **자동 퇴근**(자정까지 안 찍음, 주황) · **휴일**(빨강) · **기록 없음**(회색) · **퇴근 전**(오늘).
  - 토·일·공휴일 날짜 글자는 달력처럼 파랑·빨강.
- **날짜 누르기 → 그날 상세(아래에서 올라오는 창)**: 날짜·요일, 출근 시각·단말 이름, 퇴근 시각·단말 이름(자동이면 "자정까지 안 찍어 정규 퇴근 18:00으로 자동 기록"), 머문 시간, 휴일 여부. 맨 아래 [정정 신청]은 ⑤(8-89)에서 연다 — 그때까지 "정정 신청은 곧 열려요" 안내.
- **PC**: 같은 목록을 가운데 넓게(요약 카드 위). 달력 칸 보기는 하지 않는다(목록 하나로).
- **데이터**: 새 표 없음. 조회 함수 `my_attendance_month(p_month)` — 본인 기록만(회사 격리), 근무 요일·공휴일·근태 켠 날·가입 승인일을 함께 돌려줌.
- 하지 않는 것: 지각·조퇴 판정, 월 근무시간 기준 대비 부족/초과 계산, 엑셀 내보내기, 다른 직원 기록 보기(관리자 현황은 ⑧).

## 6. 정정 신청 · 휴일 근무 상신 (⑤, 8-89) — 승인(2026-11-08, D-239, 시안 캔버스 ⑤ 줄)
> 결정 출처: attendance-draft §7-2(정정 = 직원 신청 → 관리자 승인, 원본 보존 / 휴일 출근은 기록 → 상신 → 관리자 최종 승인 / 승인자는 관리자 역할 누구나 / 상신 위치는 퇴근 결과 화면 + 월 근태 현황). "결정 필요"였던 4가지는 사용자 결정(2026-11-08)으로 확정.

### 6-1. 직원 — 정정 신청
- **들어가기**: [근태] → 날짜 → 그날 상세 [정정 신청] / "오늘은 이미 퇴근했어요" 화면 [정정 신청] / 퇴근 누락 알림 [내 근태 보기] → 그날.
- **쓰기**: 날짜 고정. 출근·퇴근 시각(분 단위, 지금 값이 미리 채워짐, 바꾼 칸 표시). 머문 시간 변화 미리 보기. **사유 필수**(빠른 선택: 퇴근을 못 찍었어요 · 퇴근 뒤 더 일했어요 · 일찍 잘못 찍었어요 · 출근을 못 찍었어요 · 외근·출장 + 글 200자).
- **기록 없는 근무일**도 정정으로 출근·퇴근을 넣을 수 있다(외근·QR 못 찍은 날).
- **검사**: 출근 < 퇴근, 같은 날 안(23:59까지 — 자정 넘은 시각 불가), 미래 시각 불가(오늘이면 지금까지), 바뀐 것이 하나도 없으면 보낼 수 없음.
- **하루 승인 대기는 1건**. 대기 중에는 [신청 취소]만(고치려면 취소 후 다시). 승인·반려된 뒤에는 다시 신청할 수 있다.
- 신청할 수 있는 날짜 범위: **이번 달 기록만**(오늘까지, 근태 켠 날·가입 승인일 이후). 지난 달 기록은 정정할 수 없다. 이미 낸 신청은 달이 바뀌어도 관리자가 처리할 수 있다.
- **말일 주의 안내**: 정정 신청 화면에는 항상 "정정 신청은 이번 달 기록만 할 수 있어요". 달의 마지막 3일에는 [근태] 화면 위에 "이번 달 기록은 말일(11/30)까지만 정정 신청할 수 있어요. 빠진 기록이 없는지 확인해 주세요" 띠를 보여 준다.

### 6-2. 직원 — 휴일 근무 상신
- 대상: 휴일(근무 요일 아님·공휴일)에 QR로 찍힌 기록. 들어가기: 휴일 퇴근 결과 [휴일 근무 상신] / [근태] 그날 상세 [휴일 근무 상신].
- **한 일 필수**(200자). 시각이 다르면 같은 신청에서 시각도 함께 고칠 수 있다(정정 + 상신 한 건).
- 퇴근 전(오늘 아직 안 찍음)에는 상신할 수 없다.
- **QR 기록이 없는 휴일 근무는 상신할 수 없다**(사용자 결정: 기록에 근거해야 신뢰도가 생김 — 휴일에는 반드시 QR을 찍는다). 기록 없는 휴일은 정정 신청도 할 수 없다.

### 6-3. 관리자 — 근태 승인
- 관리자 메뉴 [근태]에 승인 대기 수 표시 → **근태 승인** 화면(탭: 승인 대기 · 처리 끝 최근 3개월), 오른쪽 위 [근태 설정].
- 한 줄: 이름·신청 시각 · 날짜·종류(정정/휴일 근무) · 지금 → 바꿀 값(지금 값은 취소선) · 머문 시간 · 사유 · [반려] [승인].
- **승인자**: 직원 신청 → 관리자 역할(관리자·대표) 누구나. 관리자(대표 아님) 본인 신청 → **대표(최고 관리자)만**. 대표 본인 신청 → **보내는 즉시 본인 승인**(D-026 결의서 본인 승인과 같은 방식, "본인 승인" 기록). 신청한 본인은 자기 신청을 승인할 수 없다(대표 제외). 결재라인은 쓰지 않는다. **반려 사유 필수**(직원에게 그대로 보임).
- 승인 대기 목록에는 내가 처리할 수 있는 건만 버튼이 있고, 다른 관리자의 신청은 "대표가 승인해요"로 보인다. 메뉴 숫자는 내가 처리할 수 있는 건 수.
- 승인할 때 그 사이 기록이 바뀌었으면(예: 같은 날 다른 신청이 먼저 승인) 승인하지 않고 "기록이 바뀌었어요. 다시 확인해 주세요".
- 위쪽에 접힌 안내 [승인하면 이렇게 돼요](시안 그림 포함).

### 6-4. 승인하면
- 정정: 그날 출근·퇴근 시각이 바뀌고 방법 = "정정". 기록 없던 날이면 그날 기록이 새로 생김(단말 없음).
- 휴일 근무: 그날이 **근무한 날로 인정**. 월 요약 "출근한 날"은 근무일 출근 + 인정된 휴일 근무만 센다(인정 전 휴일 출근은 세지 않음 — §5 요약의 "휴일 n일 포함"을 "휴일 근무 n일 인정"으로 바꿈). 수당 계산은 하지 않는다.
- **원래 기록은 지우지 않는다**: 신청마다 바꾸기 전 값·바꾼 값·사유·신청 시각·처리자·처리 시각·반려 사유를 남기고 수정·삭제 불가(회사가 지워질 때만 함께 삭제).
- 그날 상세에 "바뀐 기록"(원래 값 취소선 → 새 값, 신청·승인 정보) 표시. 월 목록 표시: **정정 대기** · **정정됨** · **반려** · **휴일 · 상신 전** · **휴일 · 승인 대기** · **휴일 근무 인정**. 목록 위 "내 신청 승인 대기 n건 · 반려 n건".

### 6-5. 알림
- 결과(승인·반려)는 신청한 직원의 [알림]방 + 휴대폰 알림(메신저 켠 회사). 반려면 사유 포함. 버튼 [내 근태 보기].
- **새 신청은 건마다** 그 신청을 승인할 수 있는 관리자 각자의 [알림]방 + 휴대폰 알림으로 보낸다(묶지 않음). 직원 신청 → 관리자·대표 모두, 관리자 신청 → 대표. 버튼 [근태 승인 열기].

### 6-6. 데이터(안)
- `attendance_requests`(id, company_id, member_id, work_date, kind correction/holiday, new_in, new_out, reason, status pending/approved/rejected/canceled, before 값(jsonb), decided_by, decided_at, reject_reason, created_at). 하루 pending 1건(부분 유일 인덱스). 직원은 본인 것 읽기·만들기·대기 중 취소만, 처리는 관리자 함수로만. 처리된 행은 수정·삭제 불가(트리거).
- `attendance_days`에 `in_method`(qr/correction), `holiday_status`(null/approved) 추가. out_method에 `correction` 추가.
- 회사 격리·강제 RLS 동일.

### 6-7. 관리자 안내 그림
- 근태 설정 [근태는 이렇게 동작해요]: 4번 "잘못 찍었으면 정정 신청" 칸에 '정정 신청 쓰기' 그림, 5번 "관리자가 승인"('근태 승인' PC 그림), 6번 "원래 기록은 남아요"('승인 뒤 그날 상세' 그림) 추가. 로고·서비스 이름 없음, 회사명 "예시 회사".

### 6-8. 하지 않는 것
- 관리자가 신청 없이 직접 기록 고치기, 일괄 승인, 지각·수당 계산, 엑셀 내보내기, QR 없는 휴일 근무 상신, 지난 달 기록 정정.

## 7. 직원별 연차 일수 (⑥, 8-90) — 승인(2026-11-08, D-240, 시안 캔버스 ⑥ 줄)
> 결정 출처: attendance-draft §7-2(입사일로 근로기준법 제60조 **법 기준 추천값** + **관리자가 확정(수정 가능)**, 5인 미만은 직접 입력, 출근율·수당·퇴사 정산은 하지 않음, 시간차 허용은 이 화면에서). 사용자 원칙(2026-11-08): 관리자는 앱을 모른다 — **법 기준을 숨기지 말고 관리자가 인지하게** 근거·계산 과정을 보여 준다.

### 7-1. 관리자 안내 "연차는 법에서 이렇게 정해요"(접힘, 처음 한 번 펼침, 예시 그림 포함)
| 법 조항(근로기준법 제60조) | 쉬운 말 | 예시 |
|---|---|---|
| ① 1년간 80% 이상 출근 | 1년을 다 채우면 **15일** | 2025-03-02 입사 → 2026-03-02에 15일 |
| ② 1년 미만(또는 80% 미만) | **1개월 개근할 때마다 1일**, 최대 11일 | 4/1 입사 → 5/1에 1일, 6/1에 1일 … |
| ④ 3년 이상 | 첫 1년 뒤 **2년마다 1일 더**, 최대 **25일** | 근속 3년 16일 · 5년 17일 · 21년 25일 |
| ⑥ 출근한 것으로 보는 기간 | 일하다 다쳐 쉰 기간·출산전후휴가·육아휴직 등은 **출근한 날로 침** | 육아휴직 기간을 출근율 계산에서 빼지 않음 |
| ⑦ 사용 기간 | 생긴 날부터 **1년 안에** 써야 함(안 쓰면 소멸, 회사가 사용 촉진을 안 했으면 수당) | |
| 발생 시점(2021 대법원·고용노동부 해석) | 1년(또는 1개월) 근무를 **마친 다음 날** 생김 | 1년 계약 후 바로 퇴사하면 15일은 생기지 않음 |
| 적용 범위 | **상시 5명 미만 회사는 제60조가 적용되지 않음** → 회사가 자율로 정함 | |
| 대표(사업주) | 근로자가 아니어서 법 연차 대상 아님 → 직접 정함 | |
- **연도 기준**(근태 설정): (가) 1월 1일~12월 31일(회계연도) — 입사한 다음 해 1월 1일에 근무한 날만큼 비례(15일 × 재직일수 ÷ 365), 그 뒤 매년 1월 1일 / (나) 직원별 입사일. (가)는 회사가 고를 수 있는 방식이지만 **입사일 기준보다 적게 주면 안 돼요**(퇴사 때 차이 정산 — 앱은 정산하지 않음, 노무사·1350 상담 안내).
- **앱이 하지 않는 것**: 출근율 80%·개근 판단, 연차수당·퇴사 정산, 연차 사용 촉진 통지. "앱 추천값은 법 기준을 계산한 참고값이에요. 최종 일수는 회사가 확정해요."

### 7-2. 화면 (설정 > 근태 안 "직원별 연차")
- 위: 연도(2026년 ‹ ›) · 연도 기준 표시(근태 설정에서 바꿈) · **시간차 허용** 스위치(켜면 1시간 단위로 쓸 수 있음, 1일 = 1일 소정근로시간 8시간) · 5인 미만이면 "추천값 없이 직접 입력" 띠.
- 직원 목록 한 줄: 이름 · **입사일**(없으면 "입사일을 넣어 주세요") · 근속 · **법 기준 추천 n일** · **확정 n일**(입력) · 상태(확정 전 / 확정 / 추천보다 많음 / **법 기준보다 적음** 빨강).
- 줄을 누르면 **계산 근거**: "입사 2019-03-04 · 2026년 1월 1일 기준 근속 7년 → ① 1년 이상 기본 15일(제60조 ①) + ② 3년 이상 가산 (7-1)÷2 = 3일(제60조 ④) = 18일(최대 25일)". 1년 미만은 "입사 후 1개월마다 1일, 지금까지 n일 생김(최대 11일), 다음 1일은 12/1".
- **[추천값으로 모두 확정]**(입사일 있는 직원 중 확정 전만) + 줄마다 확정·수정. 법 기준보다 적게 정하면 경고 + 사유 필수(출근율 80% 미만 등 회사 판단). 대표는 추천값 없이 직접.
- 확정·수정·시간차 스위치는 모두 [변경 이력]에 남음(누가·언제·이전→이후·사유).

### 7-4. 결정(사용자 2026-11-08, D-240)
1. **입사일은 직원이 온보딩에서 입력**(카카오·구글 로그인 → 회사 가입 화면에 입사일 칸). 이미 가입한 직원은 근태를 켠 회사에서 홈에 "입사일을 넣어 주세요" 한 번 안내. 저장 위치: 멤버 정보 `hire_date`.
   - **관리자 수정 허용 + 사유 필수 · 변경 이력(누가·언제·이전→이후·사유) · 직원에게 [알림]방 안내**(확정). 직원 본인은 가입 뒤 스스로 못 바꾸고 관리자에게 요청. 관리자는 직원별 연차 화면에서 고친다(멤버 관리 화면 표시는 이번 범위 밖).
2. **1년 미만 월차**: 매달 추천 +1. 개근 판단은 관리자 몫이지만 **우리 앱 출퇴근 기록을 참고 자료로 보여 줌** — 달마다 "근무일 n일 · 출근 기록 n일 · 기록 없는 근무일 n일(날짜)". 기록 없는 날이 0이면 "기록상 개근", 있으면 "확인 필요"(외근·휴가·정정 대기일 수 있음). 근태를 켜기 전 달은 "기록 없음(앱 사용 전)".
3. **비례 연차 소수점**(확정): 회사 설정 — **1일 단위 올림(기본)** / 0.5일 단위 올림 / 시간 단위(시간차 켰을 때만, 1일 = 1일 소정근로시간). **버림은 없음**(근로자에게 불리해 위법 소지). 설정 위치는 직원별 연차 화면 위, 바꾸면 이력.
4. **법 기준보다 적게 확정: 막지 않고 경고 + 사유 필수**(확정).
5. **화면 위치: 설정 > 근태 안 "직원별 연차"**(확정).

## 8. 휴가 신청 · 취소 (⑦, 8-91) — 검토 중(미승인, 2026-11-08 시안 캔버스 ⑦ 줄)
> 결정 출처: attendance-draft §7-2(휴가 종류는 관리자가 관리·기본 템플릿, 종류마다 유급/무급·연차 차감 / 일 단위 + 시간차 / 대기 중 취소는 바로, 승인 뒤 취소는 취소 신청 → 결재 후 연차 복원 / [휴가] 메뉴 = 연도별 내역 + [휴가 신청] / 승인 휴가 캘린더 자동 표시). 사용자 질문(2026-11-08) "근태코드 같은 게 존재해야 해?" → 아래 8-1.

### 8-1. 휴가 종류(근태코드 대신)
- **코드 번호는 두지 않는다**(법정 코드 없음, 급여 연동 안 함). 대신 **휴가 종류 목록**: 이름 · 법 근거 · 연차 차감 여부 · 유급/무급(기록용) · 단위(일 / 일·시간) · 직원에게 보임.
- **기본 목록**: 연차(근로기준법 제60조, 차감·유급·일·시간) · 경조사(회사 규정) · 병가(회사 규정, 무급 기본) · 공가(예비군법 제10조·민방위기본법 제27조 — 불이익 금지) · 생리휴가(근로기준법 제73조, 무급) · 출산전후휴가(근로기준법 제74조) · 배우자 출산휴가(남녀고용평등법 제18조의2) · 난임치료휴가(같은 법 제18조의3) · 가족돌봄휴가(같은 법 제22조의2, 무급).
- **법정 휴가 일수·유급 범위는 앱에 고정하지 않는다** — 2025~2026년 개정이 잦음(배우자 출산휴가·난임치료휴가·배우자 유산사산휴가 신설 등). 안내: "최근 법 개정이 잦아요 — 고용노동부 1350에서 확인". 출산전후휴가 등은 연차 출근율에서 출근으로 침(제60조 ⑥) 안내.
- 관리자: 이름 바꾸기 · 추가 · 숨기기(쓴 적 있으면 지우기 대신 숨기기) · 차감·유급·단위 바꾸기 — 모두 변경 이력.
- 반차 종류는 따로 두지 않음(시간차 4시간 = 반차). 육아휴직 등 휴직은 이번 범위 밖.

### 8-2. 직원 [휴가] (홈 메뉴 칸, 근태 켠 회사)
- 위: 연도 · **남은 연차**(확정 일수 − 승인 − 승인 대기, 일·시간) · 받은 · 쓴 · 승인 대기 · 쓸 수 있는 기간. 연차가 확정 전이면 "회사가 아직 연차를 확정하지 않았어요" + 연차 신청 막음.
- [휴가 신청] + 내역(최근 위): 날짜 · 종류 · 일수/시간 · 상태(승인 대기 · 승인 · 반려(사유) · 취소 신청 중 · 취소됨).
- 내역 누르기: 대기면 [취소](바로) / 승인이면 [취소 신청](사유 → 관리자 승인 → 연차 돌려줌).

### 8-3. 휴가 신청
- 종류(빠른 선택 + 더 보기) → 단위(하루 이상 / 시간 — 시간은 시간차 켠 회사·그 종류가 시간 허용일 때) → 날짜(기간) 또는 날짜·시작·시간(1~7시간) → 사유(선택, 회사가 종류마다 필수로 바꿀 수 있음은 결정 필요) → **미리 보기**: "근무일 n일(주말·공휴일 제외) · 남은 연차 a → b".
- 기간은 **근무일만 셈**(근무 요일·공휴일 기준). 근무일이 0이면 신청 불가.
- 지난 날짜: **이번 달까지만**(정정과 같은 규칙). 미래: 제한 없음(그 해 연차 기간 안).
- 연차 부족: **결정 필요(추천: 막기)**.
- 같은 날 겹치는 휴가 신청·승인 휴가가 있으면 막음.

### 8-4. 승인 · 알림 · 다른 기능과의 연결
- 근태 승인 화면에 **휴가 · 휴가 취소** 줄 추가(정정·휴일 근무와 함께). 승인자·알림 규칙은 §6과 같음(직원 → 관리자·대표 / 관리자 → 대표 / 대표 → 바로 본인 승인, 새 신청은 건마다 알림, 반려 사유 필수).
- 승인된 **종일 휴가일**: 월 근태 "기록 없음"·퇴근 누락 알림에서 빠지고 목록에 "휴가 · 연차" 표시. 시간 휴가 날은 QR 그대로.
- 월 근태 요약에 휴가 일수 추가(§5 "휴가 일수는 ⑦에서").
- **캘린더 자동 표시**(캘린더 켠 회사): 결정 필요 — 추천: 다른 직원에게는 "휴가"만, 관리자는 종류까지(병가 등 사생활).

### 8-5. 데이터(안)

### 8-6. 결정(사용자 2026-11-08) · 남은 결정
1. **연차가 모자랄 때: 회사가 고름**(근태 설정 > 휴가) — "막기"(기본) / "당겨쓰기 허용"(남은 연차가 마이너스로 보임, 다음 연차에서 빠짐). 당겨쓰기 안내: "퇴사 때 당겨쓴 만큼 급여에서 빼려면 직원 동의가 필요해요 — 노무사 확인".
2. **사유는 선택(기본)**. 회사 설정으로 필수를 두지 않음(필요하면 회사가 직원에게 안내). 연차는 사용 목적을 묻지 않는 것이 원칙이라 연차 사유 칸에 "적지 않아도 돼요" 안내.
3. **캘린더: 다른 직원에게는 "휴가"만, 관리자는 종류까지**.
4. **기본 휴가 종류는 법에서 주는 9가지**(8-1 목록). 그 밖의 회사 휴가는 회사가 직접 추가.
