# [Spec] 결재라인 설정 · 상신 · 순차 결재

관련: D-011~D-015, D-026 / 규칙 원본: `spec/data/expense-lifecycle.md` §1~§4 / 데이터: `approval_lines`, `approval_line_steps`, `expense_approvals`

## 1. 개요
관리자가 회사 결재라인을 미리 설정하고, 직원은 결재자를 고르지 않고 [상신] 한 번으로 결재를 올린다. 결재는 단계 순서대로 진행되며 각 차례마다 결재자에게 카카오 알림톡이 간다.

## 2. 결재라인 설정 (관리자, `/admin/approval-lines`)
- **회사 기본 결재라인**(필수 1개): 부서별 결재라인이 없는 모든 직원에게 적용.
- **부서별 결재라인**(선택): 부서당 최대 1개. 해당 부서 직원에게 우선 적용.
- 단계 편집: 결재자 추가(회사 `approved` 멤버 검색), 순서 변경(드래그), 삭제. 단계 1~5개. 같은 결재자 중복 불가.
- 화면에 "적용 대상" 요약 표시: 각 결재라인이 적용되는 부서와 인원 수.
- 회사 생성 직후 기본 결재라인이 없으면 대시보드 체크리스트에 "결재라인을 설정하세요"를 표시한다.
- 결재라인 수정은 이후 상신분부터 적용되고 진행 중인 결재에는 영향이 없다(D-012).

예시 (8인 회사)
```
기본 결재라인:  1단계 김팀장 → 2단계 이대표
영업팀 결재라인: 1단계 박영업팀장 → 2단계 이대표
```

## 3. 상신 (직원)
1. 경비 작성 화면 하단 [상신하기] 전에 "결재선: 김팀장 → 이대표" 미리보기를 보여 준다.
   - 청구자가 결재라인에 포함되면 본인까지의 단계는 제외하고 보여 준다(`expense-lifecycle.md` §3-3).
   - 청구자가 최종 결재자(예: 대표)면 "본인이 최종 결재자라 결재 없이 바로 승인됩니다"를 보여 주고 버튼은 [제출하기(결재 생략)].
2. 확인 다이얼로그 → 서버 액션이 상신 검증(`expense-lifecycle.md` §2), 결재라인 선택·스냅샷(§3)을 한 트랜잭션으로 수행.
3. 커밋 후 1단계 결재자에게 `APPROVAL_REQUEST` 알림톡(`spec/features/kakao-alimtalk.md`).
4. 직원 화면은 경비 상세로 이동하고 "김팀장님께 결재를 요청했어요" 토스트. 결재 생략 건은 "승인 처리되었어요" 토스트.

## 4. 결재 (결재자)
- 알림톡 링크 또는 내 결재함에서 결재 화면(`spec/screens/approver.md`)으로 들어온다.
- [승인]: 확인 다이얼로그(선택 코멘트) → 다음 단계 결재자에게 `APPROVAL_REQUEST`, 마지막 단계면 청구자에게 `APPROVAL_COMPLETED`.
- [반려]: 사유 입력(필수, 최소 5자) → 청구자에게 `APPROVAL_REJECTED`.
- 처리 후 내 결재함의 다음 대기 건으로 이동하는 [다음 결재] 버튼을 보여 준다.

## 5. 반려 후 재상신
- 직원은 반려 알림톡 링크 → 경비 상세(반려 사유 강조) → [수정하기] → 수정 → [재상신]. 결재는 1단계부터 새 회차로 진행한다(D-014).

## 6. 정산완료 (관리자)
- `/admin/expenses`에서 `approved` 건을 선택해 [정산완료 처리](일괄 가능). 결제수단별 정산 금액 합계를 확인 다이얼로그에 표시: "지급 5건 132,000원 / 납부 2건 8,000원".
