# [Spec] 결재 흐름 · 사전 검토 결재라인 · 관리자 최종 승인

관련: D-012~D-015, D-026, D-034, D-039 / 규칙 원본: `spec/data/expense-lifecycle.md` §1~§4 / 데이터: `approval_lines`, `approval_line_steps`, `claim_approvals` / 관리자 화면: `spec/screens/admin-expense-approvals.md`

## 1. 개요 (D-039)
- 직원은 결재자를 고르지 않고 [결재 요청] 한 번으로 **지출소명서 1건**(영수증 항목 N건)을 올린다.
- **최종 승인은 관리자 이상(최고 관리자·관리자)** 이 [지출 승인 관리] 화면 또는 알림톡 링크로 들어간 결재 화면에서 소명서 전체를 **일괄 승인** 또는 **반려**한다.
- 회사가 원하면 관리자 승인 전에 **사전 검토 단계**(예: 팀장 확인)를 결재라인으로 둘 수 있다. 기본값은 사전 검토 없이 관리자에게 바로 가는 **직통 결재**다.

```
직원 결재 요청 ──▶ [사전 검토 1..n단계 (선택, 결재라인)] ──▶ [관리자 최종 승인] ──▶ 승인 완료 → 세무 마감 큐
                         └ 반려 가능                          └ 반려 가능
```

## 2. 사전 검토 결재라인 설정 (관리자, `/admin/approval-lines`) — 선택 기능
- **회사 기본 결재라인**: 부서별 결재라인이 없는 직원에게 적용. 회사 생성 시 **사전 검토 단계 없이(0단계)** 만들어진다(= 관리자 직통).
- **부서별 결재라인**(선택): 부서당 최대 1개. 해당 부서 직원에게 우선 적용.
- 단계 편집: 검토자 추가(회사 `approved` 멤버 검색, 역할 무관), 순서 변경(드래그), 삭제. 사전 검토 단계 0~4개. 같은 검토자 중복 불가.
- 모든 결재라인의 마지막에는 항상 **"관리자 최종 승인"** 단계가 고정으로 표시된다(편집 불가).
- 화면에 "적용 대상" 요약 표시: 각 결재라인이 적용되는 부서와 인원 수.
- 결재라인 수정은 이후 상신분부터 적용되고 진행 중인 결재에는 영향이 없다(D-012).

예시 (8인 회사)
```
기본 결재라인:   관리자 최종 승인                         (직통)
영업팀 결재라인: 1단계 박영업팀장 검토 → 관리자 최종 승인
```

## 3. 상신 (직원)
1. 소명서 편집 화면 하단 [결재 요청] 전에 결재선 미리보기: "박영업팀장 검토 → 관리자 승인" 또는 "관리자 승인".
   - 청구자가 사전 검토 단계에 포함되면 본인까지의 단계는 제외하고 보여 준다(`expense-lifecycle.md` §3-3).
   - 청구자가 **최고 관리자**면 "본인 소명서는 결재 없이 바로 승인됩니다"를 보여 주고 버튼은 [제출하기(결재 생략)](D-026).
2. 확인 다이얼로그("3건 · 72,000원을 결재 요청합니다") → 서버 액션이 상신 검증(소명서+전 항목, `expense-lifecycle.md` §2), 금액 재계산·합계 갱신, 계정과목 스냅샷, 결재 단계 스냅샷(§3)을 한 트랜잭션으로 수행.
3. 커밋 후 첫 단계 대상자에게 `APPROVAL_REQUEST` 알림톡: 사전 검토 단계면 그 검토자, 관리자 단계면 **청구자를 제외한 관리자 이상 전원**(`spec/features/kakao-alimtalk.md`).
4. 직원 화면은 소명서 상세로 이동하고 "결재를 요청했어요" 토스트. 결재 생략 건은 "승인 처리되었어요" 토스트.

## 4. 결재
- **사전 검토자**: 알림톡 링크 또는 내 결재함에서 결재 화면(`spec/screens/approver.md`)으로 들어와 [검토 승인]/[반려]. 검토 승인 시 다음 단계 대상자에게 `APPROVAL_REQUEST`.
- **관리자 최종 승인**: [지출 승인 관리](PC, `admin-expense-approvals.md`) 또는 알림톡 링크의 결재 화면(모바일)에서 [일괄 승인]/[소명서 반려]. 관리자 이상 누구든 처리할 수 있고 먼저 처리한 사람의 결정이 반영된다. 본인 소명서는 처리할 수 없다.
- [일괄 승인]: 소명서 안 모든 항목을 한 번에 승인 → 청구자에게 `APPROVAL_COMPLETED`.
- [반려]: 소명서 전체 반려. 사유 입력(필수, 최소 5자) + 문제 항목 지목(선택) → 청구자에게 `APPROVAL_REJECTED`. 항목별 부분 승인은 없다.
- 처리 후 다음 대기 건으로 이동하는 [다음 결재] 버튼을 보여 준다.

## 5. 반려 후 재상신
- 직원은 반려 알림톡 링크 → 소명서 상세(반려 사유·지목 항목 강조) → [수정하기] → 항목 수정·삭제·추가 → [재상신]. 결재는 첫 단계부터 새 회차로 진행한다(D-014).

## 6. 정산 (관리자, D-047)
- 승인 시 정산할 금액(사비 지급·법인카드 한도 초과 납부)이 없으면 소명서는 바로 `paid`(정산 없음).
- 정산할 금액이 있으면 `approved`(정산 대기)로 A-02 [정산 지급 관리](`admin-payouts.md`) 대기열에 들어가고, 관리자가 이체 후 [정산 지급 완료 처리] → `paid` + 직원 알림톡(`notification-rule.md` 트리거 D).
