# [Spec] 역할 · 권한 체계

관련: CLAUDE.md 제4장 제3조, D-004, D-005, D-011, D-030 / 데이터: `members.role`, `approval_line_steps`

## 1. 설계 원칙
- 모든 사람은 **각자의 카카오/Google 계정**으로 가입한다. 대표 계정을 경리 담당자에게 공유하지 않도록, 권한은 계정 공유가 아니라 역할 부여로 위임한다.
- 역할(`role`)은 2단계(`admin`, `employee`)다. 결재 권한은 역할이 아니라 결재라인 지정으로 정해진다.

## 2. 역할
| 구분 | 정해지는 방식 | 할 수 있는 일 |
|---|---|---|
| `admin` (대표·경리 담당) | 회사 생성자는 자동으로 admin. 이후 admin이 멤버 관리에서 다른 직원을 admin으로 지정 | 회사 설정·정책, 부서, 결재라인, 사내 양식, 멤버 가입 승인·역할 변경·비활성화, 전체 소명서 열람, 정산완료 처리, 월말 출력, 알림 이력 |
| `employee` (직원) | 초대 링크/QR로 가입 | 본인 지출소명서 작성·상신·조회, 내 정보 관리 |
| 결재자 (역할 아님) | 결재라인 단계에 지정된 멤버 | 자기 차례 소명서 승인·반려, 결재함 |

- admin도 본인 소명서를 청구할 수 있다.
- admin이라도 결재라인의 현재 결재자가 아니면 승인·반려할 수 없다(`expense-lifecycle.md` §3-8). 경리 담당 admin에게 결재를 맡기려면 결재라인에 넣는다.
- 회사에는 admin이 최소 1명 있어야 한다. 마지막 admin은 강등·비활성화할 수 없다.

## 3. 권한 위임 흐름 (경리 담당자에게 관리 맡기기)
1. 경리 담당자가 초대 링크/QR로 들어와 본인 계정으로 로그인하고 가입 신청(`employee`, `pending`).
2. admin이 [멤버 관리]에서 가입 승인 후, 역할을 [관리자로 지정].
3. 경리 담당자가 다시 들어오면 관리자 메뉴가 보인다.

## 4. 권한 매트릭스
| 기능 | employee | admin | 결재자 |
|---|---|---|---|
| 본인 소명서 작성·상신 | O | O | O |
| 자기 차례 소명서 승인·반려 | — | — | O |
| 전체 소명서 열람 | — | O | 자기 결재 건만 |
| 정산완료 처리 | — | O | — |
| 회사 설정·부서·결재라인·양식 | — | O | — |
| 멤버 승인·역할·비활성화 | — | O | — |
| 월말 출력·알림 이력 | — | O | — |
