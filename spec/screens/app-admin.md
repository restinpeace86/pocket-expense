# [Spec] 앱관리자(운영자) 화면

라우트: `/app-admin`, `/app-admin/companies/[companyId]`, `/app-admin/receipts/[recordId]`, `/app-admin/companies/[companyId]/export?month=` / 관련: D-080, D-079, D-046 / PC 기준

## 0. 접근
- 운영자 계정(`public.app_admins`, SQL로만 등록)으로 로그인했을 때만 열린다. 로그인 안 함·고객 계정은 **404**(화면이 있다는 것도 알리지 않음). 요청 입구(proxy)와 화면 서버 코드에서 두 번 확인한다.
- 고객 화면 어디에도 링크하지 않는다. 검색 노출 금지(noindex).
- **읽기 전용**. 고객 데이터·회사 설정을 바꾸는 기능은 없다.
- 데이터는 운영자 확인 뒤 서버에서 service role로만 읽는다. 사진은 10분짜리 서명 링크.

## 1. 회사 목록 (`/app-admin?month=YYYY-MM`)
- 요약: 가입 회사 수, 이 달 영수증(크레딧 사용) 장수, 전체 크레딧 사용, 직원이 지운 영수증 수.
- 표: 회사명, 사업자번호, 가입일, 멤버(승인 대기), 크레딧 지급/사용/남음, 이 달 영수증, 전체/지움, 마지막 업로드. 회사명을 누르면 회사 상세.

## 2. 회사 상세 (`/app-admin/companies/[companyId]?month=`)
- 회사 정보(사업자번호, 가입일, 크레딧).
- **영수증(크레딧 사용) 표**: 크레딧 사용 시각, 직원, 가맹점, 사용일, 금액, 품목 수, AI 인식 상태, 결의서 제목·상태, 상태(결의서에 있음 / 직원이 지움 + 시각), 사진(보관 중 / 운영 보관함 ~자동 삭제일 / 기간 지나 삭제). 시각을 누르면 영수증 상세. 월 이동, [CSV 내려받기].
- 멤버 목록(이름·역할·상태·가입일), 크레딧 지급 내역(무료 지급·이벤트 추가 지급).

## 3. 영수증 상세 (`/app-admin/receipts/[recordId]`)
- 사진(2000px 보관본, 새 창 크게 보기). 지운 영수증은 운영 보관함 사진, 보관 기간이 지났으면 안내.
- 기록: 회사, 직원, 크레딧 사용 시각, AI 인식 상태·시각, 결의서, 항목 상태, 기록 ID.
- **AI가 읽은 내용 전체**: 가맹점명, 사업자번호, 가맹점 주소, 결제일·시각, 승인번호, 카드번호(가린 모양, 앞 6자리·뒤 4자리만), 증빙 구분, 소득공제용 여부, 합계·공급가액·부가세, 추천 분류, **품목별 내역 표**(수량·단가·금액, 품목 합이 영수증 합계와 다르면 표시).
- 직원이 확정한 값(지금 값, 지운 경우 지울 때의 값): 가맹점, 사용일, 금액, 카테고리, 결제수단, 증빙, 인원, 목적·거래처·참석자, 회사 지원/개인 부담.
- AI 응답 원본(JSON, 접힘).

## 3a. 추천 현황 (`/app-admin/referrals?filter=all|paid|unpaid`, D-147)
- 회사 등록 때 적은 추천(회사당 1건) 목록. 조회만(보상은 운영자가 직접 챙김).
- 칸: 첫 결제(결제 완료 + 시각 / 미결제 — `companies.first_purchase_at`), 가입 회사(+가입일, 회사 상세 링크), 등록한 사람(이름·휴대폰), 추천 유형(추천 회사/추천인), 추천 대상(회사명 링크 또는 이름·휴대폰), 적은 날.
- 첫 결제를 마친 줄은 초록 배경 + 배지. 위에 추천 입력·첫 결제 완료·미결제 수, [전체]·[첫 결제 완료]·[미결제] 보기.
- 결제 연동 전(B-4)에는 모두 미결제로 보인다.

## 3b. 알림 이력 (`/app-admin/notifications?company=&status=failed`, D-159)
- 회사별 알림톡 발송 기록: 시각·회사·종류·받는 사람(가린 번호)·결의서·상태·실패 사유·발송 경로. 최근 200건, 회사·실패만 거르기. 읽기 전용(재발송 없음).

## 3c. 공휴일 (`/app-admin/holidays`, D-161)
- 마감일·알림일을 앞 영업일로 당길 때 쓰는 공휴일 표. 추가·지우기(운영자 화면 쓰기 예외). 해마다 다음 해 공휴일·대체공휴일·선거일을 확인해 넣는다.

## 3d. 양식 접수 (`/app-admin/format-requests`, D-180)
- 회사가 세무 마감 화면에서 등록한 이카운트·세무사랑 엑셀 업로드 서식 목록(최근 200건): 상태(접수됨/준비 완료) · 회사 · 프로그램 · 파일 이름 · 메모 · 등록자 · 일시.
- [원본 받기](운영 키로 보관함에서) · [준비 완료로 표시]/[접수됨으로 되돌리기] — 회사 화면 상태가 바뀐다. 접수 때 운영자 디스코드 알림(DISCORD_WEBHOOK_URL).

## 4. CSV
- 한 회사·한 달의 기록 전체. 엑셀 한글 깨짐 방지(BOM), 수식 주입 방지.
- 칸: 크레딧 사용 시각, 직원, 결의서 제목·상태, 항목 상태, 지운 시각, AI 인식, 가맹점명, 사업자번호, 사용일, 결제 시각, 승인번호, 합계, 공급가액, 부가세, 카드번호(가림), 증빙 구분, 가맹점 주소, 품목, 기록 ID, 항목 ID.

## 5. 기록·보관 규칙 (D-080)
- 크레딧 1장 차감 = 기록 1행(`receipt_usage_records`, DB 트리거가 만든다). AI 인식 결과도 기록에 복사.
- 직원이 항목 또는 결의서를 지우면: 지운 시각·지울 때의 항목 값·결의서 제목/상태를 기록에 남기고, 사진을 `receipt-archive` 버킷으로 옮긴다(옮기지 못하면 지우지 않는다).
- 보관 사진은 **삭제 후 3개월**이 지나면 매일 도는 정리 작업(`/api/cron/purge-receipt-archive`, Vercel Cron, `CRON_SECRET` 필요)이 지운다. 기록(텍스트)은 회사가 있는 동안 보관.
- 고객(회사 관리자 포함)은 기록·운영자 목록·보관함에 접근할 수 없다(`supabase/tests/016_receipt_records.sql`).
