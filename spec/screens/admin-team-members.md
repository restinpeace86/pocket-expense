# [Spec] 관리자 대시보드: 멤버 관리 (Team Members)

관련: D-002, D-025, D-038, D-042, D-043, D-044 / 라우트: `/workspace/[id]/admin/members` / 권한: `spec/features/roles-and-permissions.md` / 가입 규칙: `spec/features/auth-onboarding.md`

## 1. 개요 및 목적
- **목적**: 5~30인 소기업의 사장님(관리자)이 팀원들을 등록하고, 관리자 권한을 부여하며, 퇴사자 및 신규 입사자를 손쉽게 관리하는 공간.
- **접근 경로**: 관리자 대시보드 좌측 사이드바 ➔ **[ 👥 멤버 관리 ]**

## 2. 화면 레이아웃 구조
- **상단 영역**: `[ + 신규 멤버 초대하기 ]` 버튼, 현재 총 멤버 수(활성 / 전체), 공용 초대 링크·QR(보완), `[ 🔔 미제출자 독촉 ]` 버튼.
- **탭(보완)**: [전체] / [가입 승인 대기 (n)] / [비활성].
- **메인 영역**: 등록된 팀원 목록 데이터 테이블 (이름/부서 검색 및 부서별 필터링).

## 4. 컴포넌트별 상세 동작 규칙

### A. 신규 멤버 초대 및 온보딩 (`[ + 신규 멤버 초대하기 ]`) — D-042
- **개별 초대**: 관리자가 이름, 휴대폰 번호, 부서, 직급(선택)을 입력하고 초대 방식을 고른다.
  - **[카카오톡 알림톡으로 초대]**: 입력한 휴대폰으로 개인 초대 링크 발송(`INVITE`, `spec/features/kakao-alimtalk.md`).
  - **[초대 링크 복사]**: 개인 초대 링크를 복사해 사내 톡방·개인 톡으로 전달.
- 직원은 링크로 들어와 카카오/Google 로그인 후 이름·부서·직급(초대 시 입력값이 미리 채워짐)과 휴대폰, 개인정보 동의를 확인하고 **가입 완료**한다. 관리자가 직접 초대한 사람이므로 **가입 즉시 활성**(승인 절차 없음).
- **초대 대기**: 가입 전 상태는 목록에 '초대 대기'로 표시되며, [초대 링크 복사] 또는 알림톡 재발송으로 다시 보낼 수 있고 [초대 취소]로 링크를 무효화할 수 있다.
- **공용 초대 링크/QR(보완)**: 사람별 입력 없이 단톡방에 공유하는 회사 공용 링크·QR. 이 경로로 가입하면 **[가입 승인 대기]** 탭에 들어가고 관리자가 [승인]/[거절]한다(`auth-onboarding.md` §3). 공용 링크는 [재발급]으로 이전 링크를 무효화할 수 있다.

### B. 멤버 역할 및 권한 체계 (Role-Based Access)
소기업 규모에 맞춰 화면상 권한은 **관리자 / 일반 멤버** 2가지로 단순하게 보여 준다.
- **관리자 (Admin)**: 사장님, 공동 대표, 총괄 경리 담당자. 모든 직원의 지출소명서 승인/반려(D-039), 사내 정책 룰(`admin-settings.md`) 수정, 세무 마감 데이터 다운로드 권한.
  - 관리자 중 회사를 등록한 1명은 **최고 관리자**로 표시된다(D-038). 최고 관리자만 [권한변경](관리자 지정·해제)과 [최고 관리자 넘기기]를 할 수 있다. 관리자에게는 [권한변경] 버튼이 보이지 않는다.
- **일반 멤버 (Member, `employee`)**: 일반 임직원. 모바일 웹앱으로 본인의 영수증 업로드 및 지출소명서 작성/상신만 가능.
- 상세: `spec/features/roles-and-permissions.md`.

### C. 멤버 편집 (`[편집]`)
- 이름, 부서, 직급, 사번, 휴대폰 수정.
- **자가운전보조금 받음** 체크(D-070): 체크한 직원은 자차 유류비를 청구할 수 없다(통행료·주차비는 가능). 급여에서 자가운전보조금을 받는 직원만 체크한다. 한 줄 설명 + [왜 필요한가요?] 도움말(비과세 중복 방지).
- **개인별 맞춤 예외 한도 (Custom Limit Override, D-044)**: 회사 공통 1식 한도(예: 1만 원) 대신 이 멤버에게 적용할 개별 한도(예: 1만 5천 원)를 입력. 비우면 회사 공통 한도. 외근이 잦은 직책자·영업직의 오인 초과 경고를 방지한다. 일반 식대와 출장 식비 모두에 적용되며, 이후 상신분부터 적용(D-018).

### D. 계정 상태 및 퇴사자 안전 장치 (비활성화)
- **활성 (Active)**: 정상 이용 중인 재직자.
- **비활성화 (퇴사 처리)**: 계정을 완전히 삭제하면 세무 증빙용 영수증 이력이 사라지므로, 비활성화하여 과거 지출 내역은 보존하되 로그인 후 회사 데이터 접근과 신규 청구를 차단한다.
- **퇴사 처리 시 미정산 건 방어 장치** — 비활성화 직전 팝업:
  - 경고(진행 가능): 정산받지 못한 승인 건(지급 n원 / 납부 m원), 작성중·반려 소명서 n건.
  - 차단(먼저 처리 필요): 결재라인 사전 검토 단계에 포함되어 있거나, 현재 그 사람의 검토 차례인 소명서가 있음(`approval-workflow.md` §2).
- 비활성화 권한: 관리자는 일반 멤버만, 최고 관리자는 관리자까지. 최고 관리자 본인은 비활성화할 수 없다(D-038).
- **다시 활성화(D-062)**: 비활성 멤버 상세에서 [다시 활성화]. 실수로 비활성화했거나 재입사한 경우. 역할·부서는 그대로 돌아온다. 권한은 비활성화와 같다.

### E. 핵심 운영 킥 (Kick) 기능 — 미제출자 독촉 알림 (D-043)
- **[ 🔔 독촉 알림 ]**: 월말 마감 시 영수증 미제출자에게 관리자 대시보드에서 원클릭으로 카카오 알림톡(`REMINDER`)을 발송하여 빠른 제출을 유도.
  - 행 단위 [🔔]: 그 멤버에게 바로 발송.
  - 상단 [미제출자 독촉]: 이번 달 **작성중(`draft`) 또는 반려(`rejected`) 소명서가 있는 활성 멤버** 목록을 보여 주고 선택 발송.
  - 같은 멤버에게는 하루 1회까지. 발송 이력은 알림 이력(`admin-dashboard.md` ⑩)에 남는다.
