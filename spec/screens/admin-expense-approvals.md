# [Spec] 관리자 대시보드: 지출 승인 관리 (Expense Approvals)

관련: D-034, D-036, D-037, D-039, D-040, D-041, D-047, D-048 / 라우트: `/workspace/[id]/admin/claims`, `/workspace/[id]/admin/claims/[claimId]` / 규칙 원본: `spec/data/expense-lifecycle.md`, `spec/features/approval-workflow.md`

## 1. 개요 및 목적
- **목적**: 직원들이 다건의 영수증을 모아 하나의 청구 묶음(지출결의서)으로 상신한 내역을 관리자(사장님)가 데이터 테이블 형태로 한눈에 검토하고, **일괄 승인 또는 반려**하는 핵심 실무 운영 공간.
- **승인 권한**: 관리자 이상(최고 관리자·관리자)이 최종 승인한다(D-039). 본인이 올린 결의서는 본인이 승인할 수 없다.
- **접근 경로**: 관리자 대시보드 좌측 사이드바 ➔ **[ 💳 지출 승인 관리 ]**

## 2. 화면 레이아웃 구조 (Split-View Layout)
전체 화면은 좌우로 분할되어 불필요한 화면 이동을 최소화한다.
- **좌측 영역 (약 25%)**: 상태 탭에 해당하는 [지출결의서 묶음 목록] (우편함/결재함 개념).
- **우측 영역 (약 75%)**: 좌측에서 선택한 묶음의 상세 경비 데이터 및 회계 분류 내역 메인 뷰.
- `< 768px`에서는 목록 → 상세 2단계 화면으로 전환한다(`spec/common/ui-rules.md` §1).
- (D-122 구현) 좌우 분할은 1024px 이상. 왼쪽 목록 칸은 화면에 붙어 따로 스크롤(하단 승인 바 위에서 끝남)하고, 결의서를 바꿔도 목록 위치를 유지하며 고른 결의서가 목록 안에 보이게 한다. 누르면 그 줄에 '여는 중' 표시. 1024px 미만은 목록 → 상세 2단계이고, 상세의 [목록]으로 돌아오면 보던 결의서 위치로 스크롤하고 잠깐 강조한다.

## 4. 컴포넌트별 상세 동작 규칙

### A. 상단 상태 탭
- **[ 승인 대기 (N) ]**: 아직 처리되지 않은 상신 건(`submitted`). 기본 진입 탭.
  - 사전 검토 단계(`approval-workflow.md` §2)가 남아 있는 건은 "김팀장 검토 중" 배지와 함께 읽기 전용으로 표시하고, 검토가 끝나 관리자 승인 차례가 된 건만 [일괄 승인]/[반려] 버튼이 활성화된다.
  - 본인이 올린 결의서는 버튼 대신 "본인 결의서는 다른 관리자가 승인합니다" 안내.
- **[ 승인 완료 ]**: 관리자가 일괄 승인해 세무 마감 큐로 이관된 건(`approved` 정산 대기, `paid`).
  - 사비 지급·납부가 남은 건은 "정산 대기" 배지와 [정산 지급 관리로 이동] 링크. 지급 처리는 A-02 [정산 지급 관리](`admin-payouts.md`)에서 한다(D-047).
  - 법인카드만 있어 정산할 금액이 없는 건은 승인과 동시에 완료되어 "승인 완료 (정산 없음)" 배지.
  - 결재 생략(최고 관리자 본인) 건은 "결재 생략" 배지.
- **[ 반려됨 ]**: 반려 사유와 함께 직원에게 재작성 요청된 건(`rejected`). 직원이 재상신하면 다시 [승인 대기]로 이동.
- 공통 필터(보완): 월(항목 사용일자 기준), 부서, 직원, 카테고리, 검색(제목·가맹점명).

### B. 좌측 묶음 리스트
- 행: 결의서 제목(출장 결의서는 "출장" 배지), 신청자, 합계, 건수, 상신일, 확인 포인트 배지 수.
- 승인 대기 탭은 오래된 상신일 순.

### C. 우측 메인 데이터 테이블 (Line Items)
- **청구 정보**: 제목, 신청자(부서), 출장 결의서면 출장지·기간·목적, 메모/적요(지출 사유), 예외 사용 표시·예외 소명 사유(D-084, 있을 때 노란 칸), 결재 이력(사전 검토 단계 승인 기록, 이전 회차 반려 사유).
- **회계 계정과목 노출**: 세무사무소 회계 프로그램(더존 등)에 연동될 수 있도록 친화적 용어가 아닌 세법상 표준 계정과목(여비교통비, 복리후생비 등)으로 표기한다(`spec/features/account-titles.md`). 관리자는 이 칸에서 항목별 계정과목을 조정할 수 있다("계정 조정됨" 표시).
- **사내 정책 검토 (한도 초과 뱃지)**: 관리자 설정(`admin-settings.md`)의 1식 한도(직원 개별 한도가 있으면 그 값, D-044)를 초과한 식대·출장 식비 항목에 ⚠️ **[한도 초과]** 주황색 뱃지와 초과 금액을 표기한다.
  - **절사 모드**(기본): 초과분은 개인 부담으로 잘라 "10,000원 지급 (⚠️ 한도초과 7천원 절사)"로 표시.
  - **알림 모드**(알림 및 자율 승인 모드): 영수증 원본 금액은 그대로 회사 지원으로 두되, 사장님이 인지할 수 있도록 뱃지만 표시(D-041).
- **결제 수단 구분 뱃지**: 가맹점 옆에 **[💳 법인]** 또는 **[👤 개인(사비)]**(D-048). 법인카드를 등록한 회사는 카드 별칭·끝 4자리까지 표시(`[💳 법인 · 대표 7890]`), AI 인식과 직원 선택이 다르면 "직원 수정"(D-055). 증빙구분(카드매출전표·현금영수증·세금계산서·간이영수증)과 사업자등록번호는 영수증 [🔍] 패널에 표시하고, 사업자번호가 없으면 "사업자번호 없음" 회색 배지(D-050, D-051). 사장님이 "회사가 이미 법카로 긁은 건지, 직원이 사비로 쓰고 회사 통장에서 정산해 줘야 하는 돈인지"를 즉시 구분하기 위함.
- **처리 상태 / 정산 안내** 열:
  - 법인카드 + 개인 부담 0원: "법인카드 (자동승인)" — 별도 정산이 필요 없다는 뜻. 승인 자체는 결의서 단위로 이루어진다.
  - 법인카드 + 개인 부담 있음: "개인 부담 n원 납부".
  - 개인카드: "n원 지급"(절사 시 사유 병기).
- **기타 확인 포인트 배지**(보완): 직접 입력 거리, 합계≠공급가액+부가세, 청구 기한 초과, 출장 기간 밖 결제.
- **영수증 [🔍]**: 클릭 시 영수증 원본과 읽어낸 값을 나란히 보는 패널(좌 원본 / 우 값), AI 값과 다른 칸에 "직원 수정" 표시(D-037). [이전]/[다음] 항목 이동.
- **마감 요약**: 세무 증빙 총지출액(Σ 영수증 금액), 회사 통장 실지출 총액(개인카드 지급액 합계, 법인카드 건 제외), 직원 납부액(법인카드 개인 부담 합계).

- (D-079) 항목마다 영수증 사진 옆에 접힌 "AI가 읽은 참고 정보"(결제 시각·승인번호·가맹점 주소·품목 표)를 보여 준다. 승인 판단 참고용이며 지출결의서 양식·세무 엑셀에는 들어가지 않는다. 중복 영수증 의심 항목은 "중복 의심" 배지(같은 회사 안이라 관리자는 해당 결의서를 열어 볼 수 있다).

### D. 하단 액션 버튼
- **[ ❌ 결의서 반려 ]**: 반려 사유 입력 팝업(필수, 5자 이상) + 문제 항목 체크(선택). 묶음 단위로 반려 처리되며 직원 워크스페이스 및 카카오톡(`APPROVAL_REJECTED`)으로 반려 알림.
- **[ ✅ 일괄 승인 ]**: 클릭 한 번으로 해당 결의서에 묶인 모든 영수증 행이 일괄 승인되며 월말 세무 마감 데이터로 흡수된다. 사비 지급·납부가 있으면 `approved`(정산 대기 → 정산 지급 관리 대기열), 없으면 바로 `paid`(정산 없음). 직원에게 `APPROVAL_COMPLETED` 알림(`notification-rule.md` 트리거 B).
- 두 관리자가 동시에 처리하면 먼저 처리한 쪽만 반영되고, 나중 쪽은 "이미 처리된 결재입니다" 안내(`expense-lifecycle.md` §3).
- 해당 월이 세무 마감된 항목이 포함된 결의서도 승인할 수 있으며, 그 항목은 다음 마감 패키지의 "전월 추가분"으로 들어간다(`tax-closing.md` §4.C).
