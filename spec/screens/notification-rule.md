# [Spec] 카카오톡 알림톡 트리거 정책 및 템플릿 (KakaoTalk AlimTalk Triggers)

관련: D-007, D-013, D-039, D-042, D-043, D-047, O-01 / 발송 구조·링크 보안·실패 처리: `spec/features/kakao-alimtalk.md` / 데이터: `notification_logs`
**알림톡 템플릿 목록과 문구는 이 문서가 단일 기준이다.**

## 1. 개요 및 원칙
- **목적**: PC나 사내 그룹웨어를 켜지 않고도 카카오톡으로 지출결의서 상신, 승인/반려, 사비 정산 지급 완료 등 핵심 이벤트를 실시간 전달해 업무 리드타임을 0에 가깝게 줄인다.
- **원칙**: 임시저장 건은 알림을 보내지 않는다. 확정된 액션(상신, 승인/반려, 지급 완료)과 관리자가 직접 누른 초대·독촉에만 발송한다.
- 알림 단위는 **지출결의서 1건**이다(D-034).

## 2. 트리거 4대 시나리오 + 운영 알림 2종

### ① 트리거 A — 지출결의서 상신 완료 ➔ 결재 대상자 (`APPROVAL_REQUEST`)
- **발송 시점**: 직원이 [ 🚀 결재 상신 ]을 완료한 직후, 또는 사전 검토 단계가 승인되어 다음 단계로 넘어간 직후.
- **수신자**: 현재 단계 대상자 — 관리자 승인 단계면 **청구자를 제외한 관리자 이상 전원**, 사전 검토 단계면 지정된 검토자(D-039).
- **템플릿**:
  ```
  [PocketExpense] 새로운 지출결의서가 상신되었습니다.
  상신자: #{이름} (#{부서})
  제목: #{제목}
  금액: #{합계} 원 (영수증 #{건수}장)
  사용처: #{사용처 — 영수증 순서대로 서로 다른 가맹점, 예: 김밥천국 / 코레일 외 2곳}
  결제수단: #{결제수단 요약 — 예: 법인카드 / 법인 2 · 사비 1}
  [결재하러 가기]
  ```
- **버튼**: `/workspace/{companyId}/approvals/{claimId}` (모바일 카드형 승인 뷰).

### ② 트리거 B — 최종 승인 완료 ➔ 상신자 (`APPROVAL_COMPLETED`)
- **발송 시점**: 관리자가 [ ✅ 일괄 승인 ]을 완료한 직후.
- **템플릿**:
  ```
  [PocketExpense] 결재가 정상 완료되었습니다. ✅
  신청자: #{이름}
  제목: #{제목}
  금액: #{합계} 원
  사용처: #{사용처}
  상태: #{정산 안내 — 법인카드만: "법인카드 사용 건으로 정상 마감 처리되었습니다." / 사비 포함: "사비 #{지급액}원 지급 대기 중입니다."}
  [내 내역 확인하기]
  ```
- **버튼**: `/workspace/{companyId}/employee/claims/{claimId}`.

### ③ 트리거 C — 반려 ➔ 상신자 (`APPROVAL_REJECTED`)
- **발송 시점**: 관리자(또는 사전 검토자)가 [ ❌ 반려 ]와 사유 입력을 마친 직후.
- **템플릿**:
  ```
  [PocketExpense] 지출결의서가 반려되었습니다. 🔴
  신청자: #{이름}
  제목: #{제목}
  금액: #{합계} 원
  사용처: #{사용처}
  반려 사유: #{사유 — 필수. 비어 있으면 "결의서에서 확인해 주세요"}
  [수정 후 재상신하기]
  ```
- **버튼**: `/workspace/{companyId}/employee/claims/{claimId}/edit` (편집 화면으로 바로 진입).

### ④ 트리거 D — 사비 정산 지급 완료 ➔ 직원 (`PAYOUT_COMPLETED`, D-047)
- **발송 시점**: 관리자가 [정산 지급 관리](`admin-payouts.md`)에서 [ 💰 정산 지급 완료 처리 ]를 누른 직후. 지급액이 0원인 결의서(납부만 있는 경우)는 보내지 않는다.
- **템플릿**:
  ```
  [PocketExpense] 사비 정산금이 지급되었습니다. 💰
  항목: #{결의서 제목}
  지급 금액: #{지급액} 원
  지급 일시: #{YYYY.MM.DD HH:mm}
  [나의 정산 타임라인 확인]
  ```
- **버튼**: `/workspace/{companyId}/employee/settlements`.

### ⑤ 운영 — 개별 초대 (`INVITE`, D-042)
- 관리자가 [알림톡으로 초대] 시. 수신자: 초대 대상(비회원). 문구: "#{회사명}에서 #{이름}님을 경비 정산 서비스에 초대했습니다." 버튼 [가입하기] `/join/i/{token}`.
- 수신자가 아직 회원이 아니므로 템플릿 심사에서 정보성으로 인정받도록 구성한다. 반려되면 [초대 링크 복사]만 제공한다.

### ⑥ 운영 — 미제출자 독촉 (`REMINDER`, D-043)
- 관리자가 [독촉 알림] 시. 같은 멤버에게 하루 1회(한국 날짜, 실패 건은 세지 않음). 문구: "#{회사명} 아직 제출하지 않은 지출결의서가 있어요 (작성중·반려 #{n}건). 확인 후 상신해 주세요." (D-094) 버튼 [제출하러 가기] `/workspace/{companyId}/employee`.

- 위 6종 외의 알림(가입 승인 등)은 현재 범위가 아니다.

### 2-x. 월말 마감 알림 (CLOSING, D-161) — 관리자
- 1일(마감 주간 시작, 전체 관리자): "[회사] 지출 마감 주간이 시작됐어요. 직원 청구 마감은 M/D, N월분 세무 마감은 M/D까지예요. 홈택스에서 N월 세금계산서·카드 매입 자료를 내려받아 올려 주세요."
- 3일(그 달 홈택스 자료 0개인 회사): "[회사] N월 홈택스 자료가 아직 올라오지 않았어요. M/D까지 올리고 마감을 완료해 주세요."
- 5일(그 달 세무 마감 안 한 회사): "[회사] 오늘(M/D)이 N월 지출 세무 마감일이에요. 누락 내역을 확인하고 마감을 완료해 주세요."
- 승인 대기 독촉(D-166): 3일·5일에는 지난달까지 쓴 영수증이 든 승인 대기 결의서가 있으면(마감했어도) 대상. "N월까지 쓴 결의서 N건이 아직 승인 대기 중이에요. (오늘|M/D)까지 승인 또는 반려해 주세요. 처리하지 않으면 N월 세무 자료에서 빠져요." 버튼 [승인 대기 보기]. 1일에도 대기 건수 한 줄.
- 버튼 [세무 마감 열기]. 날짜는 앞 영업일로 당긴 날. 아침 7시 cron, 같은 날 한 번, 웹푸시와 함께. 실제 발송은 대행사 연결 뒤(O-01).

## 3. 기술 연동 및 운영 고려사항
- **API 연동**: 국내 알림톡 발송대행사(솔라피, 알리고, 비즈엠 등) 중 선정(**O-01 미결**). 선정 전에는 `log` 드라이버(Mock)로 동작한다(`kakao-alimtalk.md` §2): 서버 콘솔에 템플릿 이름·가린 받는 번호·본문·버튼·변수(#{…})를 상자 모양으로 찍고 성공으로 기록한다. 교체는 `src/lib/notify/sender.ts`의 드라이버 하나 추가 + 환경변수(`ALIMTALK_DRIVER`, `ALIMTALK_API_KEY`·`ALIMTALK_API_SECRET`·`ALIMTALK_SENDER_KEY`, `ALIMTALK_TEMPLATE_<코드>`)만으로 한다(7차 개선사항 4). 현장명·프로젝트명 칸은 우리 데이터에 없어 넣지 않는다(제목에 가맹점·카테고리가 들어감).
- **버튼 링크 (Deep Link)**: 버튼은 모바일 웹 URL로 바로 연결한다. **로그인 토큰은 URL에 넣지 않는다**(D-013, 알림톡이 전달·공유되면 다른 사람이 승인할 수 있음). 대신 로그인 세션을 오래 유지해 대부분 재로그인 없이 바로 열리고, 세션이 없으면 카카오 로그인 한 번 후 원래 화면으로 돌아온다.
- 서비스 도메인은 배포 시 확정해 `NEXT_PUBLIC_SITE_URL`로 설정하고, 템플릿 심사 때 버튼 도메인으로 등록한다.
