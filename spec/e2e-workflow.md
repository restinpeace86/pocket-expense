# [Spec] 사용자 워크플로우 E2E 시나리오

관련: 7차 개선사항 1(2026-10-27) / 기준 문서: `spec/data/expense-lifecycle.md`(상태·결재), `spec/features/roles-and-permissions.md`(권한), `spec/common/pricing-policy.md`(요금·크레딧), `spec/features/tax-export.md`(세무 마감)

이 문서는 5~30인 소기업에서 실제로 일어나는 순서대로 **영수증 등록 → 알림 → 승인 → 반려·재상신 → 권한별 화면 → 세무 마감 엑셀 → 크레딧 소진 → 설문 크레딧 → 월말 마감**을 끊김 없이 따라가며 검증하는 E2E 시나리오다. 각 단계는 "사용자 행동 → 시스템 반응 → 확인할 것"으로 적는다. 화면·규칙이 이 문서와 다르면 위 기준 문서를 따른다.

## 0. 공통 준비

### 0.1 등장인물 (테스트 회사 1개)
| 사람 | 역할(D-038) | 하는 일 |
|---|---|---|
| 김대표 | 최고 관리자(`super_admin`) — 회사를 등록한 사람 | 최종 승인·반려, 마감 해제 |
| 박경리 | 관리자(`admin`) — 경리·총무 | 최종 승인·반려, 정산 지급, 세무 마감 엑셀 |
| 이팀장 | 직원(`employee`) + 사전 검토자 | 팀원 결의서 사전 검토(선택 기능) |
| 최직원 | 직원(`employee`) | 영수증 등록·상신 |
| (타사) 정직원 | 다른 회사 직원 | 격리 확인용 |

### 0.2 요청 원문과 실제 결정의 차이 (이 문서가 따르는 쪽)
| 요청 원문 | 실제 규칙 | 근거 |
|---|---|---|
| 사장이 카톡 링크에서 바로 승인 | 알림톡 링크를 누르면 **로그인한 해당 결재자만** 승인 화면을 연다(토큰만으로 승인되는 무로그인 링크 없음). 카카오 로그인이 유지돼 있으면 바로 열린다 | D-013 |
| 카카오톡 알림 | 알림톡은 발송대행사 미정이라 **로그 드라이버(Mock)** 로 동작하고 발송 이력에 남는다. 무료 웹푸시는 실제로 간다 | D-007, O-01, D-116 |
| 경리·총무는 전체 목록, 사장은 결재 대기 목록만 | 역할은 최고 관리자 ⊃ 관리자 ⊃ 직원 3단계. **관리자 이상은 회사 전체**를 보고 처리한다. 사장도 경리도 같은 [지출 승인 관리]를 쓰며 기본 탭이 "결재 대기"다. 사전 검토자는 [내 결재함]에서 자기 차례만 본다 | D-038, D-039 |
| 승인된 내역만 엑셀 | 세무 마감 대상은 **승인(`approved`)과 정산 완료(`paid`)**. `paid`는 승인 뒤 정산까지 끝난 상태라 함께 넣는다. 기준월은 결제일자 | D-016 |
| 29,000원 기본 플랜(150장) 소진 시 업그레이드 팝업 | 결제 연동 전이라 결제 버튼은 비활성. 소진 시 이벤트 추가 지급(켜져 있으면) 또는 추가 크레딧·상위 플랜 안내만 | D-046, D-054, 7차 개선사항 8 |
| 구글 폼 후기 → 시크릿 쿠폰 번호 입력 | 외부 구글 폼·쿠폰 번호 대신 **앱 안 설문**을 제출하면 바로 +100장(회사당 1회) | 7차 개선사항 7 |
| 월초 사용량 리셋·이월 | 결제 연동 전에는 리셋 없음(누적 무료 크레딧). 정식 구독 후 매월 기본 장수는 이월되지 않음 | pricing-policy §1 |

### 0.3 공통 확인 (모든 시나리오 끝에)
- 휴대폰(360·390px)·태블릿(768)·PC(1280)에서 가로 넘침·가림 없음(`ui-rules.md`).
- 타사 직원(정직원)은 이 회사의 결의서·영수증·멤버·크레딧을 **어떤 경로로도 볼 수 없다**(주소 직접 입력 → 본인 회사로 이동, DB는 RLS로 0행).
- 저장·상신·승인 버튼은 누른 동안 비활성(두 번 눌러도 한 번만 처리).

## 시나리오 1. 영수증 등록 → 지출결의 상신 (직원, 모바일)

**사전 조건**: 최직원이 카카오 로그인, 회사 크레딧 ≥ 3장.

| # | 사용자 행동 | 시스템 반응 | 확인할 것 |
|---|---|---|---|
| 1 | 직원 홈 [+ 새 지출결의서] | 작성중(`draft`) 결의서를 만들고 편집 화면으로 이동 | 하단 고정 버튼이 화면 아래 safe-area 위에 있음 |
| 2 | [영수증 추가] → 사진 3장 촬영/선택 | 사진을 줄여(긴 변 기준 압축) 올리고, 장마다 크레딧 1장 차감, AI가 가맹점·날짜·금액·결제수단·카테고리 초안을 채움 | 업로드 단계 표시(준비 → 올리는 중 → AI 읽는 중), 남은 크레딧 3장 감소, 실패한 장은 "확인 필요"로 남고 직접 입력 가능 |
| 3 | 항목을 열어 금액·카테고리 확인, 필요하면 수정 | 식대는 1인 한도 분할(회사 지원/개인 부담), 수정한 값은 "직원 수정" 표시 | 합계 = 항목 합계 |
| 4 | 지출 사유 확인(AI 초안) | 제목 `[카테고리] 가맹점 외 N건` 자동 | 필수 칸 비면 상신 버튼 아래에 무엇이 비었는지 안내 |
| 5 | [결재 올리기] | 서버가 전 항목 검증 → 금액 재계산·계정과목 스냅샷 → 결재라인 스냅샷 → `submitted` | 상신 체감 1초 이내, 결의서 상세에 결재 타임라인 표시 |

**예외**: 크레딧 0장(이벤트 꺼짐) → 영수증 추가 버튼이 막히고 "관리자에게 문의" 안내, 이미 올린 영수증으로 상신은 가능. 네트워크 끊김 → 작성 내용은 서버 임시저장(`draft`)에 남아 다른 기기에서도 이어서 작성.

## 시나리오 2. 알림 → 승인 (관리자, Mock 알림톡)

**사전 조건**: 시나리오 1 상신 완료. 결재라인 = 이팀장 사전 검토 1단계 + 관리자 최종 승인.

| # | 사용자 행동 | 시스템 반응 | 확인할 것 |
|---|---|---|---|
| 1 | (자동) | 이팀장에게 `APPROVAL_REQUEST` 알림톡(로그 드라이버: 서버 콘솔에 받는 사람·결의서·금액·링크를 찍고 성공 처리) + 웹푸시 | [관리자 › 알림 이력]에 "개발 모드"로 기록, 버튼 링크 = 운영 주소 `/workspace/{id}/approvals/{claimId}` |
| 2 | 이팀장이 링크를 누름 | 로그인돼 있으면 결재 화면, 아니면 로그인 후 같은 화면으로 복귀 | 다른 사람이 링크를 열면 읽기 전용 또는 접근 불가 |
| 3 | 이팀장 [승인] | 사전 검토 완료 → 관리자 단계 대기, 관리자들에게 결재 요청 알림 | 이팀장은 같은 결의서를 다시 처리할 수 없음 |
| 4 | 김대표(휴대폰) 또는 박경리(PC)가 [지출 승인 관리]에서 확인 후 [승인] | 먼저 처리한 사람만 반영. 지급액·납부액이 0이면 바로 `paid`, 있으면 `approved`(정산 대기) | 최직원에게 `APPROVED` 알림, 동시에 두 관리자가 눌러도 한 번만 처리 |
| 5 | (정산 대기면) 박경리가 [정산 지급 관리]에서 지급 완료 처리 | `paid` + `PAYOUT_COMPLETED` 알림 | 직원 [정산 내역]에 입금 타임라인 |

**예외**: 관리자 본인 결의서는 본인이 최종 승인할 수 없다(다른 관리자, 최고 관리자 본인 건은 결재 생략 규칙 D-026). 알림톡 실패 → 1회 자동 재시도, 그래도 실패면 이력에 사유·[재발송].

## 시나리오 3. 반려 → 수정 → 재상신 (예외)

| # | 사용자 행동 | 시스템 반응 | 확인할 것 |
|---|---|---|---|
| 1 | 관리자가 [반려] → 사유 입력(필수), 문제 항목 지목(선택) | `rejected`, 직원에게 `REJECTED` 알림(사유 포함) | 사유 없이 반려 불가 |
| 2 | 최직원이 알림/홈 배지에서 결의서를 엶 | 반려 사유와 지목 항목이 맨 위에 보임 | 지목 항목에 표시 |
| 3 | 항목 수정·영수증 교체(추가 차감 없음) 후 [다시 올리기] | 새 결재 차수(`current_round + 1`)로 결재라인 처음부터 | 이전 차수 이력은 타임라인에 남음 |
| 4 | 관리자 승인 | 시나리오 2의 4~5와 같음 | |

## 시나리오 4. 권한별 화면 흐름

| 사람 | 들어가는 곳 | 보이는 것 | 못 하는 것(확인) |
|---|---|---|---|
| 최직원(직원) | `/workspace/{id}/employee` | 자기 결의서·정산 내역·내 정보 | `/admin/**` 주소 입력 → 직원 홈으로, 다른 직원 결의서 주소 → 접근 불가 |
| 이팀장(사전 검토자) | 직원 홈 + [결재함] | 자기에게 온 검토 대기·처리 완료 | 회사 전체 목록·정산·세무 마감 |
| 박경리(관리자) | `/workspace/{id}/admin` | 홈 할 일, [지출 승인 관리] 전체(기본 "결재 대기" 탭)·정산 지급·멤버·세무 마감·설정 | 관리자 지정·해제, 최고 관리자 넘기기, 마감 해제 |
| 김대표(최고 관리자) | 관리자와 같음(휴대폰은 메뉴가 햄버거) | 관리자 전부 + 관리자 지정·해제·넘기기·마감 해제 | 본인 결의서 직접 승인(결재 생략 규칙으로 처리) |

**확인**: PC는 [지출 승인 관리] 좌우 나눠 보기(목록 + 상세), 휴대폰은 목록 → 상세 → 뒤로 가면 보던 줄로 복귀(D-122).

## 시나리오 5. 세무 마감 엑셀 (경리)

| # | 사용자 행동 | 시스템 반응 | 확인할 것 |
|---|---|---|---|
| 1 | 박경리 [세무 마감] → 월 선택 | 결제일자 기준 그 달 `approved`·`paid` 항목 집계, 미포함(작성중·상신 중·반려) 경고 | 반려·작성중 건은 엑셀에 없음 |
| 2 | [마감 패키지 내려받기] | 브라우저에서 ZIP(엑셀 1개 + 영수증 원본 + 지출결의서 PDF) 묶기, 진행률·실패분 재시도 | 엑셀 시트1 지출내역(결제일 순, 영수증 1행), 시트2 요약(계정과목·부서·직원별 합계), 시트3 세무 업로드 초안 |
| 3 | (자동) | 그 달을 마감 잠금, 항목에 마감월 기록 | 마감 항목은 계정과목 조정·삭제 불가, 마감 뒤 승인된 그 달 건은 다음 패키지 "전월 추가분" |

**확인**: 엑셀의 영수증 파일명과 ZIP 안 파일명이 1:1, 합계 = 화면 요약 합계.

## 시나리오 6. 크레딧 소진 → 추가 크레딧·상위 플랜 안내

| # | 상황 | 시스템 반응 | 확인할 것 |
|---|---|---|---|
| 1 | 남은 크레딧 20장 이하 | 관리자 홈·요금제 화면에 "n장 남았습니다" 안내 + [추가 크레딧 받기](설문, 시나리오 7) | 직원 화면에는 표시 안 함 |
| 2 | 0장 + 이벤트 켜짐 | 같은 트랜잭션에서 100장 자동 지급, 직원 토스트·관리자 배너 | 업로드가 끊기지 않음 |
| 3 | 0장 + 이벤트 꺼짐 | 직원 업로드 중지. 관리자 요금제 화면에 **소진 시에만** [추가 크레딧 충전 50장 8,000원]과 상위 플랜 안내가 나타남 | 결제 연동 전이라 버튼은 비활성("결제 준비 중"), 요금 카드에 "기본 장수 이월 없음" 안내 |

## 시나리오 7. 설문 작성 → +100장 (회사당 1회)

| # | 사용자 행동 | 시스템 반응 | 확인할 것 |
|---|---|---|---|
| 1 | 관리자가 [추가 크레딧 받기] | 설문 창: 만족도 별점, 가장 유용한 기능, 업종·규모, 한 줄 후기, 홈페이지 소개 동의 | 휴대폰에서 전체 화면 |
| 2 | [제출] | 서버가 회사 참여 여부 확인 → 처음이면 `credit_ledger` +100(`survey_bonus`) + 잔여 크레딧 즉시 증가 | 두 번 눌러도·다시 열어도 1회만 지급, 다른 관리자가 또 제출해도 거절 |
| 3 | (공개) | 소개에 동의한 후기는 랜딩 하단 "실제 사용자 후기"에 업종·직무로 익명 표시 | 회사명·이름 노출 없음, 운영자가 숨기면 바로 사라짐 |

## 시나리오 8. 월말 마감·데이터 보관 주기

| 시점 | 자동/수동 | 처리 | 확인할 것 |
|---|---|---|---|
| 매일 03:00 | 자동(cron) | 유가 받기, 지운 영수증 사진 3개월 지난 것 삭제 | |
| 매일 07:00 | 자동(cron) | 정기 결제 결의서 생성, 청구 기한 D-3·당일 웹푸시, 결재 대기 24시간 독촉 | |
| 월말 ~ 다음 달 초 | 직원 | 청구 기한(기본: 다음 달 N일) 안에 상신, 지나면 "기한 초과" 배지(상신은 가능) | |
| 다음 달 초 | 관리자 | 시나리오 5로 지난달 마감 패키지 → 세무사무소 전달, 그 달 잠금 | 마감 후 들어온 지난달 건 = 다음 패키지 전월 추가분 |
| 매월 1일 | (정식 구독 후) | 기본 장수 새로 지급, 남은 기본 장수 이월 없음 | 결제 연동 전에는 리셋 없음(누적 무료 크레딧) |

**보관**: 결의서·항목·영수증 원본은 회사가 있는 동안 보관(마감 잠금으로 수정 차단). 지운 영수증은 운영 보관함에 3개월(D-080).
